# grok — round 1

The kitchen-sinks survey is a careful file-size map wearing a volatility coat. Its method — three full-tree sweeps, fat files read whole, "what imports what" as the lift test — is honest about what it measured. It is the wrong measurement.

Lowy's bar, which binds this debate: a boundary must encapsulate a **named axis of change** (likelihood × effect), not group related functionality, and not package whatever already happens to import nothing. "Variable is not volatile." "Speculative volatility is not volatility." The survey's ranking key is `(severity × how free the cut is)`, and severity is proxied by line count. That is functional decomposition with a tape measure.

I will steelman the document, then re-derive the seams from what this repository has actually changed and what it has already put on the roadmap.

## Steelman

The document's best claims are true, and they are not small.

**The package graph is not the kitchen sink.** Architecture.md's layering is machine-checked by `bun install`; every edge is argued in a `//dependencies` comment; nothing points sideways or up. The one recent extraction — `@olai/git`, out of `ops/src/git.ts` under `commit-whole-repo` (#122) — is the right precedent: a leaf on `effect` alone, knowing nothing about outlines, writers, or a wire (`packages/git/package.json`). Very few candidates pass *that* test. The document is right to treat package lifts as the rare case.

**`scale.ts` is misfiled.** `web/src/client/markdown/scale.ts` is a type-and-spacing table plus its CSS emitter. Its own header says so (lines 1–17): the scales are declared here, the sheet is generated from them "exactly as the palettes are." It is not markdown. Wherever the theme lives, this belongs with it.

**The stale manifest claims are honesty bugs today.** `@olai/web`'s `//exports` says the one cross-package import is `testids.ts`. `@olai/tests` already imports six modules by path: `testids.ts`, `theme/css.ts`, `theme/palettes.ts`, `markdown/scale.ts`, `clock.ts`, `edit/draft.ts`. The tests `//dependencies` comment documents three of them. A rename that compiles on both sides and fails as a thirty-second timeout is the failure mode those comments exist to prevent. Declare the contracts or shrink the list. That is not a refactor.

**`pending.ts` does mix two kinds of thing.** `COMMIT_MODES`, `GitState`/`gitOf`, `whyOf`/`commitDoor` sit in the same 987-line file as the survey/commit/push/automatic closure. The document is right that the closure is bound by shared state and must not be split (its own header, `pending.ts:247–251`, already says the mode is one module's business). The seam it saw is real.

**One cut in `agent.ts` names an axis.** The permission-bypass rule — do not take the first allow-flavoured option, because the Claude Code adapter maps plan-mode's "Ready to code?" onto a permission whose first allow switches the session to `auto` (`agent.ts:341–371`, `569–576`) — is the most safety-critical prose in the package. Isolating it as a pure decision is worth doing. The document almost says this.

**Several "do not touch" calls are correct.** `plan.ts`'s thirteen `planX` functions are one shape; length is not mixture. `server/src/edit.ts` is two readings of one `Reading` on purpose. `format/src/validate.ts` is the "rules checked in exactly one place" invariant. `asks.ts` is one subject. `serve.ts` is a composition root. Path-safety twins should not be a package. `@olai/committing` as a new package is not urged. `inverseOf` waits for a second consumer. `@olai/store` to its own repo is already on the record.

I concede all of that. The rest of the proposal follows from a lens that points at the wrong seams.

## The lens error

The survey's lift test is: *does this directory/file import nothing outside itself?* That finds **already-isolated** code. Lowy's receptacle test is the opposite: *what changes independently, and is the change leaking across a missing socket?*

Applied to this tree, the isolation test nominates:

- a 334-line token table with zero imports (`scale.ts`)
- a 399-line palette table with no imports (`palettes.ts`)
- a precompress utility that imports only `node:fs` / `node:zlib`
- a JSON-RPC skeleton that imports only node builtins
- payload readers that close over no state

Those are the *least* volatile things in the repo. They are tables, pins, and plumbing. Meanwhile the things that have demonstrably moved — adapter interpretation, git *policy*, the wire's Edit union, the format's mark model, Workflowy parity — sit in files the survey either wants to split by function (`reading.ts` / `rpc.ts`) or ranks by length (`world.ts` at #3 because it is 1060 lines).

`@olai/git` did not graduate because `ops/src/git.ts` was long or import-light. It graduated because **git policy had to change independently of git plumbing**, and the olai-isms (audit convention, writer trailer, which dirty files matter, whole-repo vs outlines) were leaking into the subprocess layer. Architecture.md records the axis. The survey kept testing candidates against the *shape of the result* (a leaf on `effect`) rather than against the *reason for the cut*.

## What has actually changed

Last two weeks of this tree, plus the open roadmap, name the axes. Likelihood × effect, not line count.

### 1. How the pinned ACP adapter lies — high × high

`OLAI_ACP_AGENT` exists so another adapter can be plugged in (`chat/src/adapter.ts`). The e2e suite already points it at a scripted one. The Claude Code adapter is the default on every launch path, and it is a source of *activity* volatility that has already bitten:

- tool names live in `_meta.claudeCode.toolName`, not on the permission request (`agent.ts:1070–1091`)
- MCP tools are recognised by the `mcp__<server>__` prefix, "a bet on that adapter" (`agent.ts:346–353`)
- plan-mode exit is a permission whose first allow switches the session to `auto` (`agent.ts:569–576`)
- the running model is one field of a forwarded CLI `init` message on `_claude/sdkMessage` (`agent.ts:1048–1068`, `556–567`)
- `elicitation.form` must be advertised or `AskUserQuestion` is disallowed

The package has already extracted the *other* chat axes correctly: `asks.ts` (payload shapes), `questions.ts` (promise-per-question), `attachments.ts`, `kolu.ts` (padi probe), `events.ts`, `pipes.ts`, `adapter.ts` (which executable). What `adapter.ts` does **not** own is interpretation. It only answers "what to spawn." The remaining 657-line closure is the session Manager (sequence: boot, adopt, load, cancel, permission routing) with adapter quirks still interleaved.

Roadmap still on this axis: `orchestrator-in-chat`, `mcp-fail-visible`, `chat-node-context`, `chat-drop-files`.

The survey's `reading.ts` + `rpc.ts` are file splits with no axis. Those readers change when the ACP protocol changes, which is the same reason the rest of `agent.ts` changes. `model.ts` as "three variables nothing else reads" is functional grouping of Claude-Code-specific dual-source display. The real cut is: **interpretation of the pinned adapter, versus the session lifecycle.**

### 2. Git *policy*, now that plumbing has a home — high × high

`@olai/git` just shipped. What remains in `pending.ts` is not "vocabulary beside orchestration." It is three different things the survey lumps:

| Thing | Travels the wire? | Changes when | Right home |
|---|---|---|---|
| `GitState` (`off` / `repo` / `none` / `error`) | yes — it *is* the `git` cell | #108, #119, every time a new face is named | the floor, next to `RepoState` |
| `COMMIT_MODES` | no — "CLI flag, never travel the wire" (`pending.ts:84–86`) | a new `--commit` value | ops, where it already is |
| `whyOf` / `commitDoor` / `commitDoors` | no — prose for a write reply and `--help` | a new writer, a new door, a new setting | ops, next to the mode |

`format/src/committing.ts` already exists for this reason: "this package is the floor both the ops layer and the wire spec stand on" (lines 1–11). It already re-exports `RepoState` from `@olai/git/state` and owns `Writer`, `Pending`, `CommitRequest`. `GitState` is the missing piece of that same vocabulary. Surface currently *redeclares* it as a Schema (`surface/src/index.ts:212–218`) and says the two are "kept in step by the compiler" (`207–210`). That is a hand-kept mirror of a published shape. `RepoState` already showed the pattern: declare once on the floor, re-export, both ends import.

The survey's `@olai/committing` package is the wrong altitude. Format already owns the commit *vocabulary* because it travels. A third package would be a third home. The survey's reason for not urging it ("blocked on `changes.ts`") is also the wrong reason: `changes.ts` is "what two readings of a set differ by," which is format's business and already imported by `committing.ts`. The cut that is *not* clean is mixing CLI modes and door-prose into that floor. The file already refuses to.

`pending.ts` has been touched by every git feature PR in the window (#83, restore, #116, #119, #122). The closure is the committing Manager. Leave it.

### 3. The wire's Edit union — high × high, *active now*

`@olai/surface` is already the receptacle for "what travels." It grew a collection, a documents collection, a git cell, a pending cell, chat, attach, and `edit.apply`. The package already splits by *subject*: `chat.ts`, `edit.ts`, `attach.ts`, `media.ts`, barrel in `index.ts`. Splitting the barrel into `git.ts` / `outlines.ts` because `index.ts` is 500 lines is file organization.

The live axis is the **keyboard's closed union** (`surface/src/edit.ts`). Its own header says the list is spelled once, and it currently admits it is "deliberately narrower" than the ops table: no `create`, no `archive`, no `see`, no `date` (lines 32–36). That admission is now a filed HACKING.md bug: `editor-op-parity` (roadmap, 2026-08-12) — "Web editor expresses less than MCP." Children: archive, date, todo/doing, see, after, remove-mirror, create-outline, unarchive. `menu-verbs` is dispatched today onto the same union.

Every one of those lands as an arm on `Edit` and an arm in `server/src/edit.ts`. That is the work. A `surface/git.ts` sibling file does not encapsulate it.

### 4. The format's mark model — high × high, already housed

`derive.ts` moved twice in two days: drop `open` as the residual (#86), add `todo` as a stored mark (#88), then "status is stored, never derived" (#90). Mirrors, edges, title-markdown all touched it. The axis is **what a mark is, and whether a bullet is a task.** Format is the one validator and the one derivation. Architecture.md puts it there so the view and the validator cannot disagree. Splitting `titles.ts` out of `derive.ts` is free navigation (`titleParts` is already a separately exported function at `derive.ts:715`). It is not a wave, and it does not encapsulate the mark model.

`validate.ts` stays whole. Agreed.

### 5. Workflowy parity in the client — high × high, already splitting itself

Keyboard editing shipped (#109). Undo shipped (#120) as `edit/undo.ts` + `undoing.ts`. The write queue is already `edit/queue.ts` — and its header says the editor and undo each have their *own* queue on purpose (`queue.ts:4–8`). The survey's "caret / dispatch / queue+undo seams" are partly *done*, and the remaining loop (one draft, caret-follow across a non-optimistic redraw, when the draft commits) is the subject `editing.tsx`'s header claims (lines 1–43).

`keys.ts` is two layers that must not overlap, in one file, so a collision is a unit test (`keys.ts:1–20`). Splitting "when it next grows" destroys the invariant that is the file. Growth is why they stay together. The next growth is `editor-op-parity` and `input-widgets`, which add *verbs*, not a third keyboard.

`said.ts` is the pill's copy tables. `one-git-indicator` just folded a second chip into this one control. It is one derivation of `pending` + `git`. Splitting "state machine / copy tables / error extraction" is finding vocabularies with a trench-coat metaphor. The documented duplication of the ops message table is deliberate (`said.ts:11–15`: a log line vs a phrase in a popover). Leave it.

### 6. Theming — variable, not volatile

Fifteen palettes shipped as #69. Since then the theme directory has grown `chrome.ts` for the app header. The table's own header: "adding one is adding a row" (`palettes.ts:4–9`). Architecture.md: "adding a theme is adding a row." That is the encapsulation. The OS preference was *removed* so there would not be two ways to be dark. Likelihood of an independent theme-system change is low; effect of adding a row is already local.

Tests importing `DEFAULT_THEME` / `THEME_STORAGE_KEY` / `customProperty` is the contract-honesty issue above, not a reason to mint `@olai/theme`. Nothing outside this repo wants these tokens. The `olai.theme` key and `--olai-md-` prefixes are real olai-ness. A directory (`web/src/client/theme/`, plus `scale.ts` moved in) is the whole of the cut.

### 7. Markdown — the volatile half is the half the lift would leave behind

The generic remark/rehype pipeline is a pin. It changed for documents, title-markdown, doc-toc, and the load-perf code-split (#118) — and that last one already extracted the first-paint axis (`chunk.ts` / `pipeline.ts`). What still changes independently is **olai-specific rewrite**: `/media` bijection, picture allowlist, title unwrapping, relative-link routing.

Upcoming items land there: `daily-notes` (date-named `.md` composed into the day view), `md-editing` (documents become writable), the relative-link residue after wikilinks were retired. Those are `rewrite.ts` and `tags.ts` — which the survey would **leave in `web`** as "the olai half." So the proposed `@olai/markdown` package is the *stable* half, extracted so "the server could someday share it (rendering a note for an email digest)." That sentence is speculative. Speculative is not volatility.

One pipeline for notes, documents, titles, and agent replies is an architecture.md invariant, not a package boundary.

### 8. `precompress.ts` — scheduled for deletion

`precompress-upstream` (roadmap, still `todo`): when `@kolu/surface-app`'s `buildSurfaceClient` emits siblings, "olai deletes `precompress.ts`." The file's own header says the same (`precompress.ts:19–23`). Lifting it to a leaf — "eventually its own repo" — is the opposite of the actual plan. `precompress-dev-tax` is a local bug (sibling-skip, dist pruning, dev opt-out). Fix it in place. Do not enshrine a file the pin bump is meant to erase.

"Zero olai knowledge" is true and insufficient. Extractable ≠ should extract.

### 9. Two-face consistency — the kitchen sink the survey names and does not cut

HACKING.md: "MCP and Web ops must be consistent; never deviate." `editor-op-parity` is that rule filed as a bug. `tools.ts` already restates policy that lives in `pending.ts` and `plan.ts` — the `commit` description restates whole-repo + selection + waiting (`tools.ts:342–344`); each mark tool restates the stamping / dating / "a bullet is not a task" rules (`195–211`). The survey records this as "a drift risk to keep in mind." That is Lowy's **duplicated volatility encapsulation** — a first-class finding — marked "not a split."

It *is* the split that will bite as `menu-verbs` and `editor-op-parity` grow the verb list. The receptacle is the ops table. Descriptions should be bound to (or generated from) the decisions they restate, so a change to "what `commit` sweeps" cannot leave the agent-facing prose behind. That is more important than whether `world.ts` is 1060 lines.

### 10. The test World — navigation, not volatility

`world.ts` and `hooks.ts` are long. The survey itself says they are "co-location, not coupling," then ranks them #3 and #4 by line count. HACKING.md already prefers "multiple files & folder hierarchy for ease of navigation." If someone is in `world.ts` and the selector constants are in the way, move them. That is not a Lowy finding and it is not Wave 0 of a decomposition program.

The fake ACP agent is two products in one executable. True. The generic half is interesting *if* a second scripted agent appears. One consumer, and the interface would mirror the implementation (JSON-RPC framing + session verbs). The value the survey names — unit-testing the permission-bypass rule — is achieved by extracting the **decision function**, not the stdin loop. The file's own header still points at `packages/server/src/chat/agent.ts`, a path that no longer exists. That is the kind of drift a testlib package would freeze.

## The path twins, more carefully

`outlinePath` (`plan.ts:1135–1150`) and `mediaTarget` (`surface/src/media.ts:47–72`) share a *discipline*: judge segments after they are read, refuse `.` / `..` / empty / separators / NUL rather than resolving them. They do not share a function. One takes a relative `.jsonl` path and rejects a leading `/`. The other takes a URL under `/media/`, decodes URI components, and requires `isPicture`. Unifying them in `format/paths.ts` is functional grouping of "path judgment." The comment pointing at the twin is documentation of a rhyme. Leave both. The survey's "no package" conclusion is right; the "put them in format" alternative is still the wrong cut.

Same rule as `inverseOf` and as the two `WeakMap`s on `OutlineSet` (`query.ts:INDEXED`, `pending.ts:BY_FILE`): two copies with the same invalidation story. A third would be a "per-revision derivations" module. Two is not.

## The decomposition this analysis yields

Against the survey, point by point.

**Package lifts**

| Survey | This analysis |
|---|---|
| `@olai/markdown` (generic pipeline; rewrite/tags stay) | No. Speculative consumer. Volatile half stays in `web` either way. |
| `@olai/theme` (or `web/src/design/`) | Directory only. Move `scale.ts` into `theme/`. No package. Variable ≠ volatile. |
| `precompress` → leaf → own repo | No. Fix `precompress-dev-tax` in place. Delete on the upstream pin. |
| `@olai/committing` (recorded, not urged) | Correct not to urge. Wrong reason. Vocabulary already lives in `format/committing.ts`. Do not add a package. |

| `@olai/store` own repo later | Already on the record. No urgency. |

**Module cuts that name an axis**

1. **`GitState` onto the floor.** Add it to `format/src/committing.ts` as a Schema, next to `RepoState`. Surface imports it; delete the hand-kept mirror. `COMMIT_MODES`, `whyOf`, `commitDoor`, `commitDoors` stay in `ops/src/pending.ts`. This is the leftover of #122, not a vocabulary dump.

2. **Adapter interpretation.** Grow `chat/src/adapter.ts` (or add `interpret.ts` beside it) to own `toolNameIn`, the `mcp__` prefix, `liveModelIn`, and a pure `shouldBypass(tool, givenServers, options)` — the plan-mode trap as a function with unit tests. Session lifecycle stays in `agent.ts`. This is the one agent.ts cut that will still make sense when `OLAI_ACP_AGENT` points at something that is not Claude Code.

3. **Grow the Edit union.** `editor-op-parity` and `menu-verbs` land on `surface/src/edit.ts` + `server/src/edit.ts`. That *is* the decomposition: one more arm, one more resolver, compile errors everywhere else. Do not split `surface/index.ts` for length; `GitState` leaving it is a consequence of (1), not a sibling-file project.

4. **Bind `tools.ts` descriptions to the decisions they restate.** Not a new file for its own sake — a single source, so "what `commit` sweeps" and "what `set_done` stamps" cannot drift from the planner. This is the HACKING consistency rule applied to prose.

5. **Re-home `scale.ts` under `theme/`.** Fix the two stale manifest claims. Same PR is fine; they are honesty, not architecture.

**Module cuts the survey wants that I would not schedule**

- `reading.ts` / `rpc.ts` — no axis. Move them if you are already in the file and the scroll is painful. Not Wave 0 of a program.
- `permit.ts` + `model.ts` as the survey draws them — `permit` is real but it belongs with the *other* adapter reads, not as a sibling of `rpc.ts`. `model.ts` is one of those reads.
- `tests/selectors.ts` + `budgets.ts` + `servers.ts` — navigation.
- `said.ts` → `faces.ts` / `words.ts` / `trouble.ts` — one control, one derivation.
- `editing.tsx` caret/dispatch/queue — queue and undo already left; the loop is the subject.
- `keys.ts` — the one-file invariant is the content.
- `format/titles.ts` — free, not a wave.
- `runtime.ts` `applyEdit` / `gitCells` — composition-root sequencing. The file's header argues the one-fiber / one-survey invariants. Do not split the thing whose order is the content.
- `surface/index.ts` → `git.ts` + `outlines.ts` — subjects already have files. Barrel stays a barrel.

## Sequencing, from the work that is already happening

The survey's Wave 0 is "free, no interfaces invented." That is a cost ranking. The work ranking is: **what is already on fire.**

- **Now (already dispatched or filed as bugs):** `menu-verbs` and `editor-op-parity` grow the Edit union. That is the surface/edit.ts receptacle doing its job. Do not start a sibling-file project in the same package while that union is moving.
- **Leftover of a shipped axis:** `GitState` onto `format/committing.ts`. One Schema, two importers, the mirror dies. Small, named, #122's missing floor piece.
- **The adapter axis, before the next adapter:** `shouldBypass` + `toolNameIn` + `liveModelIn` as interpret. Unit tests. This is what makes the plan-mode trap reachable without Cucumber, which is the only part of the testlib proposal that names a real risk.
- **Honesty, any day:** the two stale manifest claims; `scale.ts` next to the palettes.
- **When the verb list next grows:** bind tool descriptions. `menu-verbs` is that growth.
- **When kolu lands it:** delete `precompress.ts`. Until then, `precompress-dev-tax` in place.
- **Not a program:** the rest of Wave 0/1 file splits. If a later PR is in `world.ts` or `derive.ts` and a constant block is in the way, move the block. Do not pre-split the tree so the next survey finds shorter files.

## What neither "defend the doc" nor "prosecute the doc" will say if they stay inside its list

The document asks "which of these long files should we cut." Both a defence and a prosecution of that list will argue about `pending.ts` vocabulary, `agent.ts` closures, and whether `@olai/markdown` is a leaf. The seams that will actually move this month are **the Edit union** (HACKING consistency, in flight), **adapter interpretation** (the override already exists; the quirks are still in the Manager), and **tool-prose drift** (the survey's own unused finding). File length is how the survey found the rooms. It is not how the walls should be placed.
