# Round 1 — fable (defends the proposal)

I wrote the document under debate, so my defense starts with what it deliberately is: a survey that found the *package* layering healthy and located the sinks in *files*. That finding is itself the proposal's strongest Lowy credential — the easy, wrong answer to "identify kitchen sinks and lift packages" was ten new packages. The doc proposes four, defers two of those on their own weaknesses, and argues one case (path-safety) explicitly *against* a package. If the prosecution's charge is functional decomposition in volatility clothing, the first exhibit is that the doc already threw out most of the functional candidates.

## The four package lifts, each with its axis named

Lowy's bar: name the volatility, its likelihood × effect, and the stable socket. Taking them in order:

**The markdown pipeline.** The axis is *what may render, and what may safely reach `innerHTML`* — and it is demonstrably volatile, not merely variable: this year alone the pipeline grew GFM footnotes with per-block id re-minting, heading anchors plus the one sanitizer allowlist value they required (`anchors.ts` records the negotiation), a replaced-not-extended highlight grammar set (the lowlight `common`-plus-Nix decision in the web manifest), and the media rewrite. Every one of those changes landed *inside* the pipeline while its four consumers — notes, documents, titles, chat replies — kept calling the same socket: markdown in, sanitized HTML out. That is the receptacle shape: supply-side churn behind a stable plug. The two olai-aware files (`rewrite.ts`, `tags.ts`) staying behind as injected plugins is the interface-stability rule applied, not an afterthought.

**The theme system.** The axis is the doc's own quoted sentence from architecture.md: *"adding a theme is adding a row."* Fifteen rows exist, ported from the racket implementation, with a WCAG test holding each; the token vocabulary above the rows has stayed fixed while rows accumulated. Row-supply volatile, token socket stable — this is close to Lowy's literal electricity example. I concede the honest hedge in the doc: nothing outside this repo wants it, so a *directory* with a declared boundary buys most of the value; the package is defensible, not mandatory.

**Precompress.** The axis is *encoding policy* — which encodings, at what quality, skipping what — and it is on the roadmap, not speculative: `precompress-dev-tax` is filed against exactly this file's policy (no sibling-skip, never-pruned dist). The socket "compress this dist directory" doesn't move when brotli quality or the skip rule does. Weakest of the four in effect-size; the doc accordingly pairs it with the pending fix rather than urging it alone.

**The fake-agent skeleton into `chat/testlib`.** The axis is *adapter quirk churn*, and the codebase is a catalogue of it: the `_claude/sdkMessage` meta, the `toolName` read off `_meta.claudeCode`, the plan-mode permission request whose first allow-flavoured option silently flips the session to `auto` (the single most dangerous behavior the chat package guards against), the stored-session trailing-slash cwd bet. Those quirks change with every adapter release — high likelihood, high effect, and today the *only* harness that can exercise the guards is Cucumber spawning a real subprocess. A scripted ACP agent importable by unit tests is the receptacle for that axis. Note this lift's Lowy shape: the generic skeleton (protocol, stable) separates from the verb script (scenario supply, volatile) — the cut runs *along* the axis, not across it.

## Where the prosecution is right before it starts

Three concessions, so the steelman is on the record:

1. **File length is not an axis.** The module-split half of the doc (its ranked table) is argued on co-location and legibility — a Hickey argument, not a Lowy one. I hold that this is fine: Lowy governs *published boundaries*; a file split inside a package invents no interface and encapsulates nothing, so demanding a volatility axis of it is applying the bar at the wrong altitude. But the doc does not say this out loud, and it should.
2. **The deferred entries fail the bar today, and the doc says so.** `@olai/committing` is blocked by `changes.ts`'s ownership; the store's own-repo move has no driving change scenario. "Recorded, not urged" is the doc pricing its own weak volatility correctly.
3. **One entry I will not die defending:** the `pending.ts` vocabulary extraction is argued partly on "these lines are pure and the server reads them" — which is a coupling observation, not an axis. The axis that *does* exist there is UX-copy churn (the faces and sentences changed under `one-git-indicator`, `git-invisible`, and `commit-whole-repo` while the survey/commit/push core changed for none of them), plus the `GitState` shape that `@olai/surface` currently hand-mirrors. If the debate finds that axis too weak for even a module boundary, I'll concede the entry down to "fix the duplication, leave the file."

## What I ask the other stances to engage

- **opencode:** the "checked, and explicitly not sinks" section is the doc applying the almost-expendable test — `plan.ts`, server `edit.ts`, `validate.ts` left alone *because* their length protects an invariant. If the prosecution wants to show over-eagerness, it must find an entry where the doc split something whose co-location was load-bearing — not re-argue entries the doc already declined.
- **grok:** a re-derivation from actual change history is welcome, but it must explain the observed asymmetry: why did `@olai/git` (extracted along the "what git does" axis) survive contact with three subsequent PRs unchanged at its socket while `pending.ts` above it churned every time? If your axes are real, they should retrodict which past extractions aged well.
