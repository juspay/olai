# grok — round 1

The article's design directive is decompose on volatility. This altitude asks the corollary the last debate could not: **whose vault is it?** Some electricity is olai's. Some is already behind `@kolu/surface`. The rest is the half-built socket every surface-app still has to oscilloscope — and that leftover is what this stance extracts.

I argue FOR extraction. I do not argue for new olai packages. The paid-upstream pattern in this house *is* the electricity: `defineSurface` hid the wire, `serveSurfaceApp` hid the listener sequence (`packages/server/src/listener.ts:3–10`, `docs/architecture.md:79`), kolu#2133 hid the stale-tab handshake (`wire.ts:23–28`). The next receptacle is the one whose consumers are every kolu-surface app, not just this one.

## Kitchen-sinks, by name

Two arguments from that ledger bind this opening. I signed both. I still sign both. This charter does not reopen the factual corrections, and it does not ask whether the survey survived the bar. It asks what the bar, argued affirmatively, demands.

**"Isolation selects for stability"** (`debates/kitchen-sinks/conclusion.md:31`). The survey's lift test found already-isolated code — a token table, a palette table, a zlib walk, a fake agent on node builtins — and treated isolation as the reason to extract. That is the inverse of the article. The article encapsulates the *volatile* interior; the socket is what must stay still. `@olai/git` aged well because plumbing-vs-policy was the axis (`packages/git/package.json:17`, `docs/architecture.md:24`), not because `ops/src/git.ts` imported nothing. At this altitude the corollary is sharp: **do not graduate a stable copy. Complete the upstream socket whose leftover volatility is still leaking into every consumer.**

**"A receptacle you plan to delete is not a receptacle"** (opencode, kitchen-sinks 02, ratified at conclusion item 7). I signed this about an *olai leaf* of `precompress.ts`. I still sign it. The plan is to delete the file on the kolu pin (`docs/roadmap.jsonl` `precompress-upstream`; `packages/web/src/precompress.ts:19–22`). Extracting a copy you intend to erase is duplicated encapsulation of kolu's axis. The receptacle is `@kolu/surface-app.buildSurfaceClient`. Deleting the copy is how you *install* the socket, not how you refuse one.

**"Prove-then-extract" / "dated second consumer"** (conclusion.md:19, 39). I signed this for markdown, theme, committing, and store-own-repo. The article is explicit that reuse is a *consequence* of encapsulation ("using power in one house indistinguishable from another"), never a precondition. I concede the Löwy reading: you do not wait for a second house to put a receptacle in the wall. I distinguish two acts the last debate folded together:

- **Installing the vault** (encapsulation) does not wait. `@olai/store` already has the vault. `@olai/git` already has the vault.
- **Incorporating the power company** (own-repo, published manifest, fleet-wide pin) is not the vault. Doing it while the plug is still being invented is how you change the socket after houses are wired.

That is not "wait for reuse." That is "do not ship a moving plug." `packages/store/src/index.ts` was edited in #112 (`Codec.unreadable`), #63 (`commit`), and #59 (the live loop). The git socket is one commit old (`packages/git/src/index.ts`, #122). Neither plug is ready to leave the house.

## Candidate 1 — complete `buildSurfaceClient`

This is the extraction. Two `#upstream` tickets (`precompress-upstream`, `splitting-upstream`) are one axis wearing two names: **what a surface-app dist is.**

The far side of the receptacle already exists. `freshStaticLayer` negotiates build-time siblings in server preference order — `br` / `zstd` / `gzip` — under the hashed-asset prefix only; identity when missing; the `no-store` shell never compressed; already-compressed media types refused (`node_modules/@kolu/surface-app/src/server.ts:83–101, 145`). `buildSurfaceClient` already owns hashed `/assets/*` names, the `no-store` shell, and the commit stamp on that shell (`bun.ts:118–125`). It does not emit the siblings the static layer is built to serve. It hardcodes `splitting: false` and takes no option to change it (`bun.ts:149`).

So every consumer re-derives the leftover. Olai's copies are `packages/web/src/precompress.ts` and `packages/web/src/markdown.ts`, composed after the helper returns (`packages/web/src/build.ts:215–232`). Drishti, kolu, the next surface-app — same post-steps, or identity-only on the wire, or a 391 KB markdown pipeline inlined into `main-*.js` because a dynamic `import()` is "deferred in evaluation, identical on the wire" (`markdown.ts:12–14`).

### The four tests

**Supply-side volatility (the AC/DC / voltage / phase / frequency / source litany).** Which encodings exist (olai writes `.br` and `.gz`, never `.zst`, while the server prefers `zstd` between them — `precompress.ts:41–42` vs `server.ts:87–91`). Brotli quality 11 vs gzip 9 vs "did this encoding even beat identity" (`precompress.ts:70–84`). Sibling-skip vs re-encode-every-build vs never-pruned `dist/assets` (`precompress-dev-tax`). Which extensions are compressible; whether a `.map` or a `.png` gets a sibling (`precompress.ts:33–38`). Q-value parsing or bare tokens (`precompress.ts:8–10`). Shell compressed or not (kolu#1319). Splitting on or off; extra entry chunks; who rewrites the `no-store` shell to name them (`markdown.ts:21–26`). Bun vs Vite (already two paths in surface-app). That is the power coming into the house.

**The opaque socket.** `buildSurfaceClient({ precompress, splitting, extraAssets, … })` produces a dist `freshStaticLayer` already knows how to serve. The consumer supplies what is genuinely its own — Solid JSX, Tailwind, public icons, the markdown *module* — and never opens the bundler to learn that splitting is false, never walks `node:zlib`, never knows `br` then `zst` then `gz`. Using the helper in one surface-app is indistinguishable from using it in another. That is the article's reuse, as a consequence.

**Functional but not domain-functional.** A hashed-asset dist with negotiated encodings is real functionality. It is not outlines, notes, days, marks, or a journal. The markdown *pipeline* is closer to the domain (notes and documents *are* markdown); the fact that it is a *chunk* rather than a first-paint tax is not. The socket hides the chunking, not the language.

**The oscilloscope test.** Today, consuming a non-trivial first paint requires: open `bun.ts` and read `splitting: false`; stand up a second `Bun.build` (`markdown.ts:64–76`); rewrite the shell the helper just wrote; know `ASSET_DIR`; know the static layer's token-set negotiation; write `.br`/`.gz` by hand; know not to compress the shell or a `woff2`. That is expose the wires, measure the frequency, certify the voltage.

**The vault test.** `precompress-dev-tax` is the grenade, live: Q11 over a never-pruned dist, ~20s on every `just serve`, growing without bound. The shrapnel landed in `precompress.ts` + `build.ts` — olai's copy of an axis the pin bump is meant to erase. A quality, skip, or prune change should open one door in `@kolu/surface-app` and close it. Splitting a 391 KB pipeline off the critical path required a whole second file *because the helper would not open* (`markdown.ts:10–19`). Two tickets that can land on different pins are two chances for the builder and the static layer to disagree about what a dist is — the same class of bug as the 8 MiB vs 16 MiB frame cap, which was paid upstream by *removing the knob* (`listener.ts:35–40`).

### What this is not

It is not an `@olai/precompress` package. It is not "eventually its own repo." Kitchen-sinks item 7 stands: fix `precompress-dev-tax` *in place*; delete `precompress.ts` (and most of `markdown.ts`) on the pin. The extraction is the kolu-side socket. Olai's local action is the deletion.

The two `#upstream` nodes should be ratified as **one receptacle**, not two chores. A `precompress` option that lands while `splitting` stays hardcoded is a socket that still forces the oscilloscope for the next first-paint cut.

What stays in olai, the way port-retry and `report.ts` stayed after `serveSurfaceApp` (`listener.ts:17–32`): the Solid transform, the Tailwind CLI, the fonts, the public icons. Those are this house's appliances.

## Candidate 2 — stop letting `status` lie

`connectSurface` already learned the article's lesson once. Apps forgot to render `status`, forgot the pid echo, forgot the watchdog. The framework closed those holes: the echo feeds itself, `retired` is a required option, the watchdog is default-on (`node_modules/@kolu/surface-app/src/solid/connectSurface.ts:29–35, 64–71`; `packages/web/src/client/wire.ts:12–28`). `client.health()` is still discardable. Olai discarded it. A dead `documents.keys` rendered as a directory with no documents, under a green light (`packages/web/src/client/connection/status.ts:74–81`; `Indicator.tsx:33–41`). The surface-utilization audit named the unused primitive on 2026-08-09 (`docs/brainstorming/surface-utilization.md:14–15`). The pill landed later, as a local conjunction.

### The four tests

**Supply-side volatility.** Four transport states (`connecting` / `live` / `reconnecting` / `retired`). Subscription enrolment (per-member vs per-key — documents enrol one sub per open body). `health()` walking every enrolled sub and allocating a record per sub, re-folding on every membership change (`Indicator.tsx:64–75`). Error vs pending vs no-first-frame. Retries, `lastFrameAt`, `gracedDown`. Heartbeat vs subscription-health vs process-id retirement. That is the blood-pressure litany behind "is this page still reading?"

**The opaque socket.** `connectSurface(…).status` should be unable to say `live` while a subscription over the socket has errored. Five states, one accessor: the four the transport can see, and `degraded` for the one it cannot. Pending does not degrade — that default is universal, not olai-specific: a first frame is what every page load looks like, and a pill that is amber most of the time is a pill nobody reads (`status.ts:91–99`). The app still owns LOOK — what "partly live" is *called*, whether the detail names "files on disk." The framework owns whether green can lie.

**Functional but not domain-functional.** "Is this page still talking to a server, and is what it subscribed to still arriving?" is real functionality. It is not outlines, notes, or days. Olai's *copy* ("the files on disk reach this page") is this house's. The conjunction is not.

**The oscilloscope test.** Today a consumer of `status` must also know to call `client.health()`, know to read it inside a tracking scope, know that the walk is expensive and must be memoized with an `equals` on the name list (`Indicator.tsx:81–84`), and know that `sub.error` degrades while `pending` must not. Kolu's own `HostStatusPip` / `SurfaceGate` already memoize; olai re-derived the walk. That is two houses exposing the same wires.

**The vault test.** Changing how documents subscribe (per-key `rawStream`, so the stream is *in* the health fact) threw shrapnel into the pill: enrolment exploded, `health()` became a per-row tax on a streaming turn, and six JSX effects would have re-walked it (`Indicator.tsx:67–75`). The grenade is enrolment policy. The vault should be the framework's readout. The app's LOOK table should not have to know that a document key is a subscription.

This is the same class of payment as kolu#2133, not a new package. I am not paying olai's chrome upstream. I am refusing a socket that can report `live` while nothing is arriving — because a receptacle that reads 110 or 220 depending on whether you also brought a voltmeter is not a receptacle.

`gateStatus` stays a gate (`status.ts:92–93`). A gate decides whether to draw the body. A pill decides whether green is a claim. Those are two policies. The framework already split them; it left the pill half optional.

## Not a receptacle, still paid up

`keysbus-upstream` is a framework defect: full key-set broadcast per new key, O(M·N) on a bulk add (`docs/roadmap.jsonl`). Olai cannot encapsulate it. Paying the fix is mandatory. It is not a vault we install; it is shrapnel the existing wire socket still throws. On the ledger as a fix, not as an extraction.

## What I will not graduate

**`@olai/store` to its own repo, this cycle.** The vault is already built. Zero olai types (`packages/store/README.md:8–12`; `packages/store/src/codec.ts:1–9`). The supply-side litany is real — watcher payloads dropped unread, inotify overflow, FSEvents coalescing, mtime+size stamps that miss a same-second same-length write (`disk.ts:39–43`), settle vs backstop, prune of `.git`/`node_modules` (`disk.ts:19–21`), last-good vs errors as two channels, `StaleWrite` vs codec refusal, `Codec.unreadable` for a directory that vanished (`errors.ts:11–15`), `changed`/`removed` spanning refused probes (`store.ts:82–87`). The socket is `Store.make({ root, codec })` → `{ snapshot, errors, commit }`. The domain test passes with room to spare: a live, transactionally-writable directory is electricity, not outlines.

All of that is why the *package* is the receptacle, and why I sign it at fable's altitude below. None of it is why the package should leave the workspace this week. The plug grew in #112. Own-repo is incorporation. The article does not demand a separate power company before the house is safe to live in.

**`@olai/git` to its own repo.** The leaf is the extraction that already happened. The socket has never been edited *because it is one commit old*, not because it has aged through a second consumer. Isolation here is the *result* of a correct cut. Graduating it now is the survey's lens again.

**`@olai/log` into `@kolu/log`.** Different sockets. Kolu's is a pino-shaped `Logger` type with zero runtime (`node_modules/@kolu/log/src/index.ts:1–12`). Olai's is Effect's verbs plus pretty-vs-logfmt faces (`packages/log/src/index.ts:3–16`). Paying one into the other is a functional merge.

**Markdown pipeline, theme palettes, committing, inverseOf.** Kitchen-sinks still holds. Markdown is how notes and documents are *read* — closer to the domain than electricity. Theme's encapsulation is already "adding a theme is adding a row." Committing and `inverseOf` wait on a socket that has actually been asked twice, not on a hoped-for email digest.

## What I sign at the other two altitudes

**Package (fable).** `@olai/store` is olai's next `@kolu/surface`-shaped receptacle — already extracted, already generic, already the vault. I will sign "the package *is* the extraction" and refuse a new manifest. I will not sign `@olai/markdown`, `@olai/theme`, `@olai/committing`, or precompress-as-olai-package. If the package altitude wants a *graduation* rather than a recognition, the store is the only candidate that passes the four tests, and the work is aging the plug (`unreadable` is one PR old), not cutting a new one.

**Module (opencode).** Two sockets I will sign, and the kitchen-sinks modules I still sign.

1. `packages/web/src/client/connection/status.ts` — the module whose interface is this house's *policy* over the connection: `LOOK`, `needsReload`, `unhealthy` (errors only), the "files on disk" sentences. If candidate 2 lands, this file *shrinks* to chrome over a five-state readout; it does not disappear. The framework must not own what olai *calls* a degraded page. The module socket delivers that vault without a manifest.
2. Kitchen-sinks items that already named an axis and are not this debate's to reopen: `GitState` (+ `gitOf`) onto `format/src/committing.ts` (item 3); grow the Edit union in place (item 5); `interpret.ts` (item 4, shipped — `packages/chat/src/interpret.ts:1–24`). Tool/panel prose reads from the planner's typed structures, never from each other (registered objection, conclusion.md:33–35).

I will not sign pre-splitting `said.ts`, `keys.ts`, `pending.ts`, `plan.ts`, or `validate.ts`. Those walls protect invariants, not leftover voltage.
