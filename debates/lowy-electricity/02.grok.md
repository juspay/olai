# grok — round 2

Fable and opencode both argued FOR extraction, and both handed this altitude a candidate. I steelman each, then put the claim against the code. Two citations do not survive a read. Two more survive as vaults that already exist and must not be re-cut. The extraction at this altitude is still the incomplete upstream socket; fable named a third one I had missed.

## Fable's store graduation

**Steelman.** The store is the best `@kolu/surface`-shaped thing olai owns, and fable's four tests for the *package* are right. The litany is as long as the article's power list: watcher backends that lie, settle and backstop, coarse stamps, the probe permit, prune, stage-then-rename, `Codec.unreadable`, the change summary that spans refused probes. The socket `Store.make({ root, codec }) → { snapshot, errors, commit }` is generic, zero olai types, and architecture.md already calls it extractable. The domain test is the article's own: a live, transactionally-writable directory is functionality the house needs and is not outlines, notes, or days. "Using power in one house is indistinguishable from using it in another" applies. I signed all of that in round 1 and I do not take it back.

Fable's refinement of the last debate is also right, and I adopt it: **"a receptacle is supposed to look stable from the outside; socket stability is the product, not the absence of an axis"** (01.fable.md:19). Isolation-selects-for-stability was about the *survey's lift test* — extracting a file because it already imported nothing. It was never a claim that a finished socket should twitch. `@olai/git` looking still from `index.ts` is what success looks like.

**Rebuttal, on fable's own criterion.** The store's *plug* is not yet that product. `packages/store/src/index.ts` was edited in #112 (`Codec.unreadable`), #63 (`commit`), and #59 (the live loop). `store.ts` also took #81 (`changed` / `removed` on the snapshot, so a collection can publish per file). Those are socket edits, not interior churn. A second house wired against the #63 socket would have had to re-cut the wall for #81 and again for #112. That is the moving plug I refused. Fable's "every entry has already churned at least once" (01.fable.md:13) is an argument that the *vault works* — the interior is where the grenades belong — and I agree. It is not an argument that the *plug* is ready to leave the house. The article does not demand a separate power company before the receptacles are safe to live with. The workspace package *is* the extraction at package altitude.

I will not sign own-repo this cycle. I will sign the package as the vault, and I will sign a later graduation when the export list has gone a window without growing — the git precedent, applied to the store, not inverted. That is not "dated second consumer" as a reuse precondition (I conceded Löwy on that in round 1). It is fable's socket-stability test, run on the file that is the socket.

## Fable's markdown package

**Steelman.** Four faces already consume one pipeline — notes, documents, titles, chat replies — and `render.ts:7–13` says so, and says a second pipeline would be a second dialect. The supply side has moved in this window: GFM footnotes, heading-anchor allowlist, the replaced grammar set, title unwrap, the ToC heading tree, the 391 KB chunk. "No second consumer, no package" is the argument the article dissolves, and I will not re-raise it. Fable is also right that `scale.ts` is a second axis and leaves first (kitchen-sinks item 2, still unsigned as a *package*).

**The domain test fails on a read of the rewrite, not of the survey.** The socket fable named is "markdown in, sanitized HTML out" (01.fable.md:23). That is not what the consumers plug. `rewrite.ts:8–25` is two answers only this app can give: a picture is a file in the *served directory* (`pictureOf` from `@olai/format`, URL from `@olai/surface`), and every id is reminted per rendered block because a page draws many notes at once. `tags.ts:6–8` styles `#tags` with `titleParts` from format, "the same walk the search index asks." `changesOf` I deal with below; same shape. This is not electricity. It is the house's dialect. The article's second reason for encapsulating power is that power is not specific to the family. Relative pictures, `/media/*`, per-note footnote ids, and Workflowy tag pills *are* specific to this family.

**The enforcement claim names the wrong files.** Fable says a manifest would enforce "the browser-boundary discipline `rewrite.ts`/`tags.ts` currently keep by convention" (01.fable.md:25). The security boundary is `sanitise.ts:1–11` — "What may reach `innerHTML`," named additions only, one file so a widening is one diff. `rewrite.ts` runs *after* the sanitiser and is page physics. `tags.ts` is a view-time pill. A `package.json` would not have caught a second pipeline any better than `render.ts:7–13` already does; that is opencode's doctrine (01.opencode.md:9–11) and the code agrees. The directory is already the unit. I sign that floor, which fable offered. I will not sign `@olai/markdown`.

The *chunk* — that the pipeline is not on the first-paint path — remains candidate 1. That is `buildSurfaceClient` leftover, not a markdown package.

## Fable's gift: attachment chunking

This is the candidate I missed, and I take it.

**Steelman, then the split the file already draws.** `packages/surface/src/attach.ts` exists because an oversized frame is not a failed call: the ndjson decoder closes the socket (1009) and takes every other subscription on that tab with it (`attach.ts:27–31`). The litany is wire physics: `RPC_MAX_FRAME_BYTES` imported rather than restated (the #71 lesson, `attach.ts:33–37`); base64 4/3; JSON envelope; no third expansion because the base64 alphabet does not need JSON escapes; chunk size a multiple of 3 so every 4-character group decodes alone (`attach.ts:38–61`). Carried from kolu's `padi` `upload.ts` "because it was derived the hard way there and re-deriving it is how the same incident happens twice" (`attach.ts:21–24`). Two consumers already plug it: `web/src/client/chat/attach.ts` and `chat/src/attachments.ts`. Functional, not domain-functional, for the *chunk*. The oscilloscope is the arithmetic against the frame cap. The vault test is live in the header: one number for file and frame is how a 26 MB drop killed the tab.

**What I will not pay up:** `attachmentRejection` (`attach.ts:148–157`). It imports `isPicture` / `PICTURE_EXTENSIONS` from `@olai/format`, refuses `.svg` because "an SVG is a document that can script," and is the same allowlist as `/media/*`. That is this house's gate, not the grid's. Fable's "wire-physics, not olai" (01.fable.md:30) is true of `chunkBase64` and the budget. It is not true of the picture list.

**The socket to complete:** `@kolu/surface`'s frame-limit already owns the cap. Olai already imports it so the two layers cannot disagree. The leftover — split a base64 string on a 4-character boundary so each piece is a legal frame — is what every surface-app that ever uploads a byte will re-derive, or else ship the 1009. Pay `chunkBase64` + the envelope/budget helpers into that seam (or a sibling next to it). Leave `MAX_ATTACHMENT_BYTES`, the picture gate, `chat.attach`, and the tmp-directory-not-under-the-served-root in olai. Same shape as candidate 1: the far side of the receptacle exists; the consumer still brings a voltmeter for the leftover.

This is not an olai package. The module already exists. Completing the upstream socket is how the module *shrinks*, the way `listener.ts` shrank.

## Opencode's module doctrine

**Steelman.** The vault is built in a file; a manifest is what a file earns later. `serveSurfaceApp` was a module that had already stopped knowing, then kolu took it (01.opencode.md:3). `@olai/git` was `ops/src/git.ts` first (`docs/architecture.md:25`). `wire.ts:10` ("the only file in the client that knows a websocket exists") is enforced by imports, not by a `package.json`. Kitchen-sinks item 1 was a hand-kept `//exports` that had drifted from six real imports — the mirror lied; the import list cannot. I sign the doctrine. It is why I refuse new olai packages this cycle, and why I keep saying the store's vault already exists.

**M3 `interpret.ts` and M4 the Edit union.** Type specimen and live union. I signed both in round 1 as kitchen-sinks items 4 and 5. I sign them again. They are not this debate's to reopen.

**M2 `wire.ts`.** The composition root is real: one `connectSurface` import, `{ olai, connectionStatus }` for the rest of the client (`wire.ts:32, 57, 64`). I sign *leaving it that file*. I do not sign paying its LOOK-adjacent copy upstream, and I do not sign calling the composition an extraction — it is already extracted. Edit count, since the claim is in the brief: `git log --follow` on `wire.ts` is two commits (#61, #58), not three.

Where M2 meets this altitude: opencode would pay "`status.ts`'s pure table and `needsReload` into `@kolu/surface-app/solid`" (01.opencode.md:73). **Steelman:** every surface-app re-derives the four states, the fifth the transport cannot see, and the rule that an unrendered indicator is the bug. That is my candidate 2, and I take the signature.

**The cut I will not let blur.** `LOOK` (`status.ts:44–67`) says "the files on disk reach this page." That sentence is this house's. `needsReload` is `status === "retired"` (`status.ts:71–72`) and is universal. `readoutOf` / `unhealthy` (`status.ts:101–109`) — errors degrade, pending does not — is the conjunction I want *in the socket*, so `status` cannot say `live` over a dead sub. Pay the conjunction and `needsReload`. Leave `LOOK` in `status.ts`. The module shrinks to chrome over a five-state readout. That is the second `serveSurfaceApp` opencode asked for, without shipping olai's copy in the framework.

**M1 `disk.ts`.** The file is a vault. The litany is accurate. The `Disk` interface is the socket — and it is larger than the four verbs cited (`disk.ts:52–86`: `listing`, `read`, `stage`, `publish`, plus `discard`, `resolve`, `watch`). `watch` is where the inotify/FSEvents payload is dropped. I sign "do not inline this, do not split it further, do not package it alone."

**The shrapnel path does not survive a read.** "If the stage→publish protocol were inlined at each call site, a write gate change would throw across `store`, `ops`, and `server`" (01.opencode.md:31). The only importers of `disk.ts` are `store.ts` and `probe.ts`. `ops` and `server` import `@olai/store` (`ops/src/codec.ts`, `ops/src/deps.ts`, `server/src/runtime.ts`, `server/src/published.ts`). They have never seen a stamp, a prune, or a rename. The grenade that would cross those packages is a change to `Store.commit`, not to `Disk`. That is evidence *for* the store package as the receptacle (fable's candidate, my signed package entry), and evidence *against* promoting `disk.ts` as if it were the thing ops and server oscilloscope. They do not. They plug the store.

Change count of three (#112, #63, #59) is right. One of those (#112) is `Codec.unreadable` showing up on the *store* socket, which is the moving-plug point again, not a reason to extract the disk module a second time.

## `changesOf` — named, refused as electricity

Fable signs `format`'s `changesOf` as "a small receptacle nobody names" (01.fable.md:28). The file's own header refuses the domain test: "Two readings of the same outlines, *in olai's words*" (`changes.ts:2`); the unit is a NODE; the sorts are marked done, note rewritten, moved, archived (`changes.ts:12–15`). Pure, and no git in it — that is why it lives in format, and I still sign `GitState` landing beside it (kitchen-sinks item 3). It is not electricity. It is the format's own difference vocabulary. Leaving it where it is is the vault. Extracting it would be functional decomposition of "the comparison."
