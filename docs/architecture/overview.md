# Architecture overview

Olai serves one directory of files, to a browser and to agents. This page names the parts, their dependencies, and why each sits where it does. For plugin dependencies, ownership and safe removal, see [Cordis in Olai](cordis.md).

A few words are used here in a particular way. A **door** is a named interface a package exposes or calls through, such as `@olai/git`'s `./state` subpath or the `Search` service. A **row** is one plugin entry in the bundle catalogue. A **face** is one presentation of a thing that exists once, such as the browser and MCP over one surface. The **wire** is the websocket protocol between server and browser. A **leaf** package is one with no `@olai/*` dependency. A **tenant** is a plugin holding olai's whole judgement about one outside system, and its **appliance** door is the only part that dials that system.

## Shape

### The set, and the one entry point

The *set* is the files under the served directory that olai treats as content. Live rows register claims with the vault-owned `vault.file-kinds` registry to decide which ([format.md](../format.md)).

| claiming row | suffix | how it travels |
|---|---|---|
| outline-olai | `.olai` | text, inside the snapshot |
| markdown | `.md` | text, inside the snapshot |
| hypertext | `.html` | path only |
| csv | `.csv` | path only |
| image | image suffixes | path only |
| pdf | `.pdf` | path only |

- Outlines and documents are content, so their text rides the snapshot. The other four are large files nothing in the set reads, so only paths travel; bytes are read when somebody opens one, or fetched by the reader's browser from `/media/`. Anything else under the directory (a `README`, a `.json`, a source file) is not in the set.
- Viewers key their media URL to the file revision. A deleted file keeps its last URL until the missing-file page replaces it; a restored file gets a new revision and reloads. CSV reloads its body through the vault’s browser service; HTML reloads its sealed preview through `/media/`.
- There is one entry point and one vocabulary; only the transport and the reach differ. `olai web <dir> [--port] [--host]` serves the browser over a websocket, on loopback by default. `/mcp` on that same listener serves HTTP MCP clients, such as an agent in a terminal.
- `olai surface <verb>` is a terminal client of `/mcp`. `@kolu/surface-cli` projects the surface as argv exactly as `@kolu/surface-mcp` projects it as tools. It opens no directory; it dials the running server.
- So one process writes the files, and one function judges every write: the write gate, described below. Editing a file or running `git pull` updates the open page without a reload.

### Host, plugins and transports

Olai is a host plus scoped plugins. The host loads modules, composes their declarations, serves transports and publishes management; it needs no outline and no workspace.

- Layout, navigation, sidebar, outlines, markdown, files, pins, capture, trash and appearance each own their server or browser behaviour. Only the renderer's `root` location is permanent; slot contracts live with their owners, and a missing owner leaves dependants waiting ([slot ownership](slot-ownership.md), [plugin system](plugin-system.md#phase-18-shell-and-content-capabilities)).
- General packages import no plugin package; `@olai/bundle` is the one exception, because it composes them. Plugins may consume other plugins through static APIs and declare availability through scoped services. The *fence* is the import check that enforces this, and it walks the runtime closure, so a clean entry file is not enough.
- Each capability declares its own wire surface beside its provider. `@olai/surface/core` holds process identity and management; `@olai/surface` holds shared schemas. Providers register through `Surfaces`; browser code acquires typed clients through `Wired` and revokes them on disposal.
- Plugins expose test identifiers in `src/testids.ts`, and `@olai/bundle/testids` combines them and checks key and value collisions. Profiles apply disabled patches over the catalogue in `packages/bundle/olai.yml`, and the first vault policy reading overrides authored rows before they activate.
- `TransportSurface.register` accepts scoped HTTP route layers and upgrade handlers, and each registration owns only its own contribution. `packages/server/src/listener.ts` owns one port and rebuilds HTTP dispatch from those contributions, with no transport flags and no transport-specific branch. It is one call to `serveSurfaceApp` (`@kolu/surface-app`) plus this program's port and log wording (`report.ts`).
- The ws plugin owns origin checks, header admission, stale-tab checks, heartbeat enrolment and cleanup. The web-app plugin owns static routes, the service worker and the manifest. The MCP plugin owns its route, protocol server, tool projection and scoped ticket registry (`plugins/mcp/src/endpoint.ts`, `plugins/mcp/src/binding.ts`).
- The `vault` plugin owns the store and offers `Vault`, `Directory` and `Ops`. Teardown withdraws the offers, drains dependants, closes the gate to new calls, waits for accepted writes, then releases the store and lock. A failed vault leaves the transports up.
- Route changes preserve existing websocket connections. Shutdown stops accepting, unloads rows, then closes the composed surface.

### How a change travels

```
files on disk ── load + validate ──▶ snapshot ── surface collection ──▶ browser (SolidJS)
      ▲                                                          │           │
      │                                                    chat panel     keyboard
   commit(baseRev)                                               │           │
      │                                       ACP session ◀──────┘           │
      │                                            │                         │
      │                                       MCP tools           edit procedures
      │                                            │                         │
      └── ops (create, add, mark, move, trash, untrash, see) ◀───────────┘
                                                 ▲
                                                 └── stdio ── an agent in a terminal
```

### The store, and one server per vault

`packages/store` turns files into a revision-tagged snapshot. It is generic: the caller supplies the codec, so it carries no olai types.

- Errors travel on a second channel, so a broken file does not blank the screen. A published snapshot names which paths moved, so consumers can publish per file without diffing two snapshots.
- It stays current by *probe*: re-list the tree, re-stat everything, diff against a table of mtime and size stamps. A watcher only triggers the probe and its payloads are dropped unread; a settle delay turns a `git pull` into one probe, and a slow backstop catches lost events.
- The walk arms a watcher on every directory created after boot, because the runtime's recursive watch does not follow new ones. It prunes dot-directories and `node_modules`, because a served directory is somebody's working tree and `.git` is its busiest part.
- **Every read carries a vintage**: how old the answer is, and on whose word. A caller states a freshness class, never a means. `cheap` returns the standing answer with its earned age; `verified` walks the tree on the asker's own fiber, so a wedged publish loop yields a visibly stale vintage instead of a fresh-looking lie (`store/src/vintage.ts`).
- A vintage is confirmed, held on the loop's word, diverged (naming the files the disk disagrees about), or unchecked (with the reason nobody could look). MCP reads carry `vintage` beside `root`, and `resync` is now `refresh("verified")`.
- **Two olai processes cannot serve one directory**, because whole-file writes are last-writer-wins, validation is per-store, and two commit paths would sweep one work tree. `packages/plugins/vault/src/lock.ts` takes `flock` through `bun:ffi` at `$XDG_RUNTIME_DIR/olai/<digest>.lock`, keyed on the directory's realpath so a symlinked spelling is one vault. A second olai refuses to boot and names the holding pid.
- An advisory lock rather than a pid file, because the kernel releases it on any death. A graceful stop unlinks the file; the next boot sweeps leftover `.lock` and retired `.sock` files, never `surface.sock` and never a lock another olai holds. On Linux the process dies with its parent (`prctl`), and a served directory that vanishes shows the unreadable-directory banner over the last-good tree rather than exiting. A share mounted on two hosts is beyond what `flock` can exclude, and the code says so.

### The write gate and validation

The *write gate* is the one function every edit goes through: `commit({baseRev, changes})` in `store/src/store.ts`.

- It takes the probe's permit, so a write and a `git pull` cannot interleave. Inside: probe, check `baseRev`, validate the set the write would produce, stage each file beside its destination, rename them all, re-probe, publish. Validating before any rename makes a refusal cost nothing on disk.
- A stale `baseRev` returns a typed `StaleWrite{currentRev}` and the caller re-derives. A set the codec refuses is an answer, so the caller renders the errors instead of retrying.
- Changed files are re-read because the gate says so, not because a stat noticed: stamps cannot see a write landing in the same second at the same length. Bytes are compared against what the write promised, and the codec is asked again only if they differ.
- **A write may not produce a file olai cannot read back.** The gate refuses a write whose own changed files will not decode, before the set-wide validation and before any bytes move. That puts every per-line rule behind every verb at once.
- **Drift repairs itself** (`stale-set-reads-clean-writes-refuse`). A rebase can replace a file at the same length with the mtime restored, so the gate compares the write's own paths by bytes on the way in and answers `StaleWrite`. A refusal reached from drifted evidence opens `refresh("verified")` once, the class `POST /olai/resync` uses. Fingerprints ride the probe cache, 16 hex characters per file.
- Nothing rides the gate. Committing to git is a separate quiet window over the whole repository, and the store never learns what git is.
- **Validation is incremental.** The store hands the codec its last published value and every path that moved (`Codec.Since`). `format/src/patch.ts` swaps changed entries into the indexes and leaves the rest standing, with reverse indexes saying which mirrors, edges, blockers and tags to re-examine. It may decline, which costs a rebuild and never an answer.
- Indexes asked by key are layered over the previous map (`format/src/overlay.ts`): `byId`, `children`, `status`, `after`, `blocked`, `mirrorsOf`, `edgesTo`. Indexes read whole stay clones, because walking a layer costs more than the copy: `namedBy`, `taggedBy`, `byDay`, `owedByDay`, `byFile`. A touched key is spliced rather than rebuilt, using the corpus order `format/src/derive.ts` promises.
- `format/src/pointing.ts` indexes what a document link names, read backwards, so "what points at this file?" is a lookup. `format/src/incremental.ts` narrows the whole-set rules and its verdict is the verdict; the six whole-set rules run only when there is nothing to narrow from — a boot, a rebuilt view, or an unvalidated reading.
- Every narrowing is held to the full version by differential tests over generated corpora and this repository's own `docs/` (`patch.bench.ts`, `splice.test.ts`, `overlay.test.ts`, `incremental.test.ts`, `validate.bench.ts`). `just bench` prints both arms.
- **Error scope is per file**, at cold boot and at runtime alike. An implicated file keeps its place in the sidebar, shows its errors where its tree would be, and refuses writes; every other outline stays live and writable. A finding naming two files takes both, because a duplicate id has no single culprit. One failure cannot be per file — the directory could not be read at all — so the codec translates it (`Codec.unreadable`) into a banner over the last-good tree.

### Ops: the only writer

`packages/ops` sits between `format` and `store`. It is the only thing that writes, and the only reader an agent gets.

- Every request names a node, a document, or (for the two creates) a relative path judged segment by segment. There is no free-form byte range, so a retry against a newer snapshot lands cleanly and a malformed file is unrepresentable.
- A refusal carries the validator's rows, each pinned to `file:line`. A write that landed may carry a `nudge`: advice from the rollup, never a reason nothing happened.
- `create` mints a file the set does not hold and may seed it with a capture; `add` refuses any path not already loaded and takes a whole nested subtree in one request. `split` and `merge` are single requests, because each changes an outline several ways at once and must not half-land.
- `outlines_update` and `outlines_apply` fold several fields, or an ordered list of verbs, into one plan. Each refusal is the single verb's own words, while the gate validates once and publishes one revision. The fold is three files: one planner per verb dispatched by a table, one value answering the directory questions planners ask, and the sequencing that splices each op's set from the one before.
- `outlines_subtree` takes an `id` or a `file`; the file arm answers `{file, roots}` with every top-level node, and placements ride a row as `placed`. `search_nodes` takes `withDesc`, because a note is unbounded prose and the palette asks this per keystroke.
- Ops owns the codec joining `format` to `store`, and the grammar a tool is built in. The tool *list* is not here: each row owns its verbs in `packages/plugins/<row>/src/tools.ts` (#546), so a disabled row withdraws them. The keyboard reaches the same procedures through `edit-intents/src/index.ts`, so there is one writer rather than two.
- **Documents** are written through the same gate and read back through the same snapshot (`md-editing`). A write carries the whole new text, staged and renamed atomically with the same audit trailer, and may carry `was` — what the caller read — refused on mismatch with the draft kept.
- `markdown_create` refuses a path that exists; `markdown_write` and `markdown_read` refuse a path the set does not hold, naming the closest one that does (`didYouMean`). `markdown_index` answers every served `.md` with its opening line, its weight and its frontmatter properties. A relative link between two `.md` files resolves beside the file it was written in and lands at `/<path>`.

### The wire

Outlines, documents and heads are three collections of kolu's surface framework (pinned via npins), keyed by root-relative path.

- `outlines` uses batched `deltas`, one entry per file, with the key declared in the protocol (`keySchema`). `documents` uses `keys` + `get` only, so bodies stay off the first paint (`snapshot-scale`); the server still validates every document, because a `doc` reference must be checkable.
- `heads` is every served file with content left off — one revision, one face, one "did it parse" — with `deltas`. A reader learns the file list and every revision on one stream and asks for content only when it will draw it.
- **A published revision costs what moved.** Each collection's map is carried from the previous revision, written into where a file moved (binary search over `assemble`'s path order) and rebuilt only where that collection's membership moved. A differential holds it against the walk it replaced (`bundle/src/published.testlib.ts`). Core's three standing reads — a page, its filter, the move picker — share one `@olai/ops` cache, answered once per question per revision.
- The `manifest` cell carries no value: it is the `null` that says a directory never loaded, which an empty collection cannot say. Error state is a cell, and git state is another.
- Chat is a collection with batched deltas for the transcript, a cell for where the conversation stands, procedures for send/cancel/new/load/list, and `attach` for bytes in bounded chunks. Chunk size is the framework's (`@kolu/surface/frame-chunking`); the extension allowlists, file cap and tmp directory are olai's.
- Editing is exactly one procedure over a tagged union of keyboard intents. Collections stay read-only on the wire, because an edit changes a file and a file reaches every tab the way a `git pull` does. Every subscription sends a full snapshot then deltas, and a reconnect is a fresh snapshot: no resume protocol, no optimistic UI.
- No raw wire code exists outside surface's API, with four exceptions, none of them a surface member: everything an MCP client speaks, `/media/*`, `GET /olai/who`, and the agent socket. `POST /olai/resync` is a fifth route that only asks the store to look at the disk.
- **Two indicators** sit in the app header, for the two facts a page can otherwise get wrong in silence. The connection pill reads `connectSurface`'s `readout` (`connecting`, `live`, `degraded`, `reconnecting`, `retired`), where `retired` means this server was replaced and only a reload recovers, offered because the readout carries `needsReload`.
- Green is the conjunction of wire status and subscription health, so a fifth state, `partly live`, names the streams that stopped; `connection/status.ts` keeps only the wording. A wire that cannot carry a question takes the app away through a modal `<dialog>` (`connection/Offline.tsx`) covering `connecting`, `reconnecting` and `retired`.
- The commit pill is the only git readout (`one-git-indicator`): `commits off` and `no git here` are dim settings, `git error` carries git's words on the tip and the `aria-label`, and healthy is quiet (`✓ committed · 3m ago · 3 unpushed`). Neither desktop pill may disappear when healthy, because an absent indicator cannot be trusted.

### The browser

`packages/web` owns the tab's boot, its build and the shared primitives, and draws no feature of its own.

```
web/src/client/main.tsx   mounts the app
web/src/client/wire.ts    dials management, fetches each row's browser half
web/src/host/             what an activation costs, what a failed one is owed
web/src/build.ts          assembles the bundle
```

- Every face belongs to a plugin: `plugins/layout` (frame and header), `plugins/sidebar`, `plugins/navigation` (routes and the ⌘K palette), `plugins/outlines`, `plugins/markdown`, `plugins/files`, `plugins/vault`, `plugins/preferences`, `plugins/theme`. No production module in `web` names a plugin.
- **A tab holds the page in front of somebody, never the vault.** It subscribes to `heads` (`plugins/vault/src/browser/directory.ts`), to each pane's address (`plugins/outlines/src/browser/reading.tsx`), and, when a pane is narrowed, to the query (`plugins/outlines/src/browser/filter/asking.ts`).
- Page readings are computed on the server by `@olai/format`'s `page.ts`: `rowsOf`, `zoom`, `datedOn`, `agendaOf`, `backlinksOf`, `referrersTo`, plus what property values name (`format/src/meaning.ts`). Whether a tab holds a directory is resolved from the manifest cell *and* the heads fold in one place (`Directory.standing`); a tab holding files outranks a `null` manifest.
- **The client reads what it is sent and never writes to it.** A keystroke is a procedure call and the answer is the file on the next frame. The only client state in an edit is the draft (`plugins/outlines/src/browser/edit/`), committed on blur, `Enter` or idle; a refused commit keeps the draft and shows the reason under the row.
- Records on the wire are borrowed objects and Solid's `reconcile` mutates what it is given, so there is no client store above the framework's. Identity across frames is a keying question, answered by `<Key>` and by the member's declared `arrayKey`. The editor follows its node across a redraw and asks for the caret back (`plugins/outlines/src/browser/edit/editing.tsx`).
- What a node *says* names the node a row shows; where a row *sits* names the row's own record. Undo replays the inverse edits through the same procedure against the current snapshot (`plugins/outlines/src/browser/edit/undo.ts`), and the server derives the inverse.
- Edit verbs: `place` and `remove` (undo only), `date`, `unmirror`, `trash`, `untrash`, `emptyTrash`, `see`, `after`, `outlineNew`, `under`, `doc`, `docNew`, `docDay`, `mark`, `split`, `merge`. `emptyTrash` is the only destructive one; it names `_olai/Trash.olai`, carries the count the confirm showed, and has no inverse.
- The `•••` row menu is the one door for a row verb, one op per click. Three values need a choice and open a panel: the date picker (`plugins/outlines/src/browser/date/`) and the edge panel for `see` and `after` (`plugins/outlines/src/browser/edges/`), which uses the server's own node search.
- Seven routes, each spelling only what it is a property of: `/<path>` for a file, `/#<id>` for a node, `/d/<ISO-date>`, `/today`, `/agenda`, `/trash`, and a zoomed node's own address. `Referenced by …` is shut by default and is a lookup over reverse indexes (`backlinksOf`); a placement is not a reference, an ordering edge is not one, and a referrer in the trash is left out.
- Client-local state: folds (`plugins/outlines/src/browser/fold/`, stored by node id under the declaring file), done-visibility (`plugins/outlines/src/browser/settings/done.ts`, default hidden, per-outline word in `olai.done.overrides`), the calendar month (`stamped.ts`), layout widths (`plugins/layout/src/layout/prefs.ts`).
- Preferences live in one panel (`plugins/preferences/src/`): theme, typeface, and what a reader does with finished work. Git policy is not here; it is the served directory's ([running.md](../running.md#the-git-policy)). A preference belongs to the browser rather than the tab: `createPreference` (`web/src/client/preference.ts`) reads, writes and follows the `storage` event, and the theme's first read is the boot script's.
- The shell is wrapped in kolu's `SurfaceFaultBoundary`, composed standalone in `main.tsx`, so a thrown render never reaches the header; `plugins/layout/src/Fault.tsx` keeps only the look.
- Keys are declared in `web/src/client/keys.ts` in two layers that never overlap: global chords on the window (⌘K, ⌘\, ⌘J, ⌘Z, ⌘⇧Z) and the row editor's bare keys (`Enter`, `Tab`, arrows) matched on the editor element. Collisions are a unit test. Touch targets are 44px except the tree gutter, which takes that in height only (`ui-primitives/src/touch.ts`); the page publishes `--visible-h` and `--visible-bottom` from `visualViewport`.
- **Installable, never offline.** The manifest is assembled by the server through kolu's manifest layer, naming SVG, 192/512 PNG, maskable 512 and `apple-touch-icon` files shipped verbatim at the dist root, outside the hashed `/_olai/assets/`; the tab icon follows the palette once the bundle is up (`plugins/theme/src/chrome.ts`).
- This origin serves one service worker, the framework's fetch-less notification worker (`serviceWorker: "notify"`). It caches nothing, so a cached shell showing stale outlines is impossible; it exists for `registration.showNotification`, the only notification path that works in `standalone` mode. On activate it purges any legacy cache and reloads that worker's windows.
- Below 48rem the sidebar becomes a drawer, chat becomes a bottom sheet, and connection and git become banners; on desktop the sidebar collapses to a ~3rem icon rail and both it and the chat dock drag-resize.

### Journal, agenda and search

Days and the agenda are queries over dated nodes; nothing on disk is a journal ([format.md](../format.md#days)).

- A month in the sidebar aggregates the whole set's dated nodes, and a day page is every node dated that day, in any outline, grouped by file. Which days have a dot is asked of the server and sent only when it moved.
- Two fields put a node on a day: the `date` it is scheduled for, and a dated `done`. A dated `doing` or `todo` is read by neither the calendar nor a day page. What is in the trash is on none of it; `is:trashed` still reaches it from every search door ([search.md](../search.md)).
- **One amendment, and only to add**: a document whose basename is exactly an ISO date (`2026-08-12.md`) is that day's note. It joins the query's answer rather than replacing it and wears a corner fold in the month against the node dot; two documents claiming one date are both listed in path order (`format/src/dates.ts`). A day page's **+ day note** mints one at the path the vault's convention names (`dailyNotePathFor`), resolved on the server.
- `/agenda` answers what is *owed*: `date` with `todo` or `doing`. A `date` with no mark is an occurrence and can never be late, so there is no `due` field (`format/src/agenda.ts`). `overdue(n) ⇔ n carries todo or doing ∧ day(n.date) < today`, derived at view time, stored nowhere, spelled once; `done` extinguishes it. `today` is an argument at every entry point (`web/src/client/today.tsx`, `web/src/client/clock.ts`).
- The agenda draws as one spine of time (`agenda-spine`): a 2px gutter line with now marked on it, days as dots, silences named and sized log-ish. Days say felt distance ("in 6 days", "Yesterday"), and a date pill survives only where it adds a fact the heading cannot. The sidebar's Agenda entry uses the same owed reading (`owedNow` over the retained `owedByDay` index).
- **Pull with one push:** journal's optional reminders component reads that owed stream against the renderer's day, without its own timer or focus reading, and announces the first non-empty reading once per browser per day through `alerts.channel`—a notification, with a best-effort chime after an earlier gesture, whose press opens `/agenda` ([rule, preferences and lifetime](../plugins/journal.md#reminders)).
- **One matcher serves five doors** and lives below all of them, in `@olai/format`'s `filter.ts`: `search_nodes` for an agent, the ⌘K palette, the header search box, the in-place page filter, and the chat composer's `@` list.
- `filter.ts` defines what a query means: case-folded substring over title, id, `#tag` and note; the operators `is:`, `has:`, `date:`, `created:`, `changed:`, `prop:` and `-` to negate; the trash rule; and which field carried a hit. Ranking (`ranked`, the done penalty, the order) is `format`'s too. It reads no clock: `date:last-week` resolves against a day handed in, and that day is the server's at every door.
- `packages/plugins/search` (`effect`, `@olai/format`, `@olai/ops`, `bun:sqlite`) is the matcher's plumbing and has no grammar. It maintains a trigram table (FTS5) so substring matching survives, kept level with the store's revisions ([plugins/search.md](../plugins/search.md)). The table answers candidates only: a needle under three characters, a query of operators alone, and a word common enough that narrowing costs more than walking are handed back to the full walk.
- Core defines the `Search` door in `@olai/ops`, and `search.nodes` refuses in words when nobody is mounted. Ops keeps the situating (`foundOf`, imported by the search row rather than copied), its own cap over the uncapped total, and the refusal for a known operator with a bad value. Recall by meaning was built and parked: it needed a model server on the reader's machine, and olai requires no dependency outside Nix.

### Agents

`packages/plugins/chat` owns node-agent conversation scopes over ACP subprocesses. Tabs and folds are readers of an engine/session pair, not separate sessions. Several node agents and writable historical sessions may be live concurrently.

- The agent's cwd is the served directory, so a terminal can reach its engine's same stored conversations. Boot opens none automatically. Node properties bind engine/session pairs; model choices use a separate capped keyed store, read when a conversation opens. The old which-conversation note is ignored and generically pruned. `heard/` bookkeeping and wake choices remain machine-local.
- Outlines owns four drawing slots: row aside and fold, page head and foot. Chat registers them under one roster provider and owns their readings. Fold removal releases its reading; page head and foot share a pane/node owner. The sidebar draws Needs you and Recent (all standings by activity, cap ten); navigation's scoped Agents palette adapter reaches all agents and offers new chat. The fixed dock, phone sheet and header toggle are retired.
- The server filer reads capture's scoped Inbox entry from the always-available vault registry, with no capture service dependency. It ensures Chats in one Ops write, then files each unclaimed conversation in its own `filer` write, checking existing and trashed claims. Full runs follow boot, session revisions and registry arrival; settled turns ask only their already-running engine. New chat mints its Inbox node before starting a session. `auto` remains commit-only.

- **The agent can ask a person a structured question.** `initialize` advertises `elicitation.form`, so `elicitation/create` and `session/request_permission` both draw as a form in the transcript rather than a modal; the projection both ways is `@olai/acp`'s. A property whose type the panel cannot draw makes the request undrawable, so it is declined out loud, and a dismissal is a decline on the wire rather than a fabricated answer. Nothing times out a blocked turn; its count appears in the conversation and Needs you.
- **Permission requests are auto-approved only for tools olai handed the session** — its mediated ops, kolu's terminals — by positive recognition. The adapter maps plan mode's "Ready to code?" onto a request whose first allow option switches the session to `auto`, so answering with the first allow found would take that decision silently.
- Subagents are read from two `_meta` stamps: `parentToolUseIn` (which agent produced a frame) and `subagent: true` with `subagent_type` on the spawning call, read through the flag as a gate (`spawnedIn`). Both fail safe, since an unstamped frame is the main agent's. Lanes are drawn by `plugins/chat/src/browser/chat/lanes.ts` and a question always names its lane; a subagent's own prose never reaches the feed, because olai does not declare `subagent-transcript`.
- Both request kinds are answered by one module under one rule, *a frame refines, never retracts* (`calls.ts`), so precedence falls out of frame order.
- The session is handed olai's own MCP server over an HTTP route on the same listener, because a stdio server would mean a second olai with a second store. Whole-file writes through olai are rejected: `fs` capabilities are false in both directions.
- It is handed `kolu mcp` too when this host runs one. Detection is a probe per conversation: start the executable, handshake, read a resource only a live daemon answers, and hand back the absolute path that answered. `PADI_SOCKET` is forwarded when olai was launched inside a kolu terminal.
- **What a call changed is drawn structurally, and the file decides the vocabulary.** A `.md` or source file draws as a collapsible diff; an outline draws as the node-level story in the Commit panel's words (*marked done*, *note rewritten*, *moved*), whichever door the write came in by. A `.olai` the agent edited with its own tools is parsed and compared as records (`plugins/chat/src/browser/chat/outline.ts`). Classification is `@olai/format`'s one `Sort`, worded by `plugins/outlines/src/contracts/changes.ts`.
- Which model is two facts: the session's config option (what was picked) and the CLI's `init` message (what is running); whichever moved last is what the header names. A switch survives a restart, written beside the conversation id and re-asserted after `session/load` through `session/set_config_option`, judged in names rather than strings (`pickerValueFor`).
- **A message can be about a node, and that is an id.** The browser sends the id alone; the server resolves it against the reading a write would be judged against (`plugins/chat/src/server/context.ts`) and hands over id, title, `file:line` and ancestor titles. An id the set no longer declares refuses the send in `notFound`'s words.
- Three things in a transcript are ids: message chips, the node an olai write was about (`Applied.id`), and an id the agent wrote in backticks. A code span becomes a reference only when the set declares it (`plugins/chat/src/browser/chat/refs.ts`, answered by `nodes.named` via `plugins/outlines/src/browser/declared.ts`); pressing one shows the node (`plugins/outlines/src/browser/focus.ts`).
- A pasted picture is chunked over `chat.attach` into the conversation's own tmp directory, outside the served root, and the prompt names the path. A path arriving over the wire is re-resolved against that directory through symlinks on both sides.
- **A send is one plain `session/prompt`, busy or idle** (`compact-lost-to-steer`). The queue is the agent's: the pinned adapter keeps a `turnQueue` and advertises it at `initialize`, so olai holds nothing and nothing is lost on restart. Cancel means stop the agent and nothing else, and a message the agent has not started says `queued` on its row.
- Steering survives as a deliberate gesture (Alt+Enter, or an `interrupt` control), offered only where the agent advertised it, and withdrawn once a message has queued — the pinned adapter then leaves the steered turn's prompt unanswered forever (`packages/plugins/claude/acp/patches/README.md`).
- A delivery that did not land marks its row with which of two things happened (`unsent-discriminate`). `refused` is a certainty, so the prompt is kept for `chat.resend`; `unanswered` is not, so it keeps no prompt and offers no button. `AgentGone` carries `Gone` with three values (`refused`, `unreachable`, `unanswered`), decided at the wire off the SDK's shapes.
- `session/new` and `session/load` can be refused by a running agent; the conversation draws that refusal (`plugins/chat/src/browser/chat/Unopened.tsx`) with a `reopen` that retries the same attempt. Entering a conversation is recorded after the agent agrees, under the boot's own permit.
- A cancel is a notification and a pipe cannot report a gone reader, so the panel watches two facts instead — is the same turn still running, and has the agent said anything since. Quiet with a cancel outstanding reports `trouble`.
- **A blocked turn is announced only to a person who cannot see it**: backgrounded, conversation folded away, or another tab reading it (`plugins/chat/src/browser/chat/attention/watching.ts` over `elsewhere.ts`). Chat chimes once, raises a notification through the service worker, and marks the icon; turn-complete is deliberately silent.
- The mark is a state recomputed from the reading, so it clears when somebody looks: `navigator.setAppBadge` with the count of questions on an installed icon, a dot on title and favicon in a plain tab (`plugins/alerts/src/badge.ts`). The tab-only alerts row owns the seam (`plugins/alerts/src/notify.ts`) and offers `alerts.channel`; chat names it on its attention component, so the conversation survives its absence. Journal's reminders component uses the same channel but never badges. Alerts owns one framework click listener and dispatches `ask` and `due` through per-kind claims, holding the newest unclaimed press for that activation. The trigger is the live websocket, so a fully closed PWA hears nothing, and Web Push is out of scope.
- **With no engine, the page composer says so** and names the agents olai can talk to, where to get one, and the variable that points at something else.

### MCP, the terminal, and engines

`POST /mcp` (`packages/plugins/mcp/src/`) is the same face the panel's agent talks to, differing only in who holds the connection.

- `@kolu/surface-mcp` projects olai's surface: each row's tools ride as tools, and outlines, documents and errors are readable and subscribable resources. The adapter is handed a rooted bundle rather than one surface, so an address and a verb name both carry the row that answers them (`surface://collections/markdown/documents`, `markdown_write`), and a row switching off withdraws both with a `list_changed`.
- Git's verbs are the git row's: `git_commit` and `git_push`, landing through the ledger door, so a serve without the row refuses in `ops.commit`'s words. Requests from loopback skip the bearer; off-loopback the session's token is required.
- Commit policy is the serving process's setting, `manual` by default, so an agent's writes land and wait and `git_commit` is what asks. `git.resume` is the browser's alone.
- **The terminal is a client of that route** (`packages/server/src/dial.ts` over `mcpClient.ts`). `capture_add` is an entry in the tool table, so the CLI verb and the MCP tool fall out of one line, and the old bespoke `POST /capture` door is gone.
- Where a capture lands is not a parameter: the top level of the directory's inbox, resolved by `@olai/format`'s `captureInto` (`inbox.ts`), the same function the palette's `+` uses. A capture arrives dated, so it is on the day page too.
- `--url` is required on every call, with nothing underneath it. Attribution is the identity the door has — the login the proxy injected — written onto the node as `captured-by` and omitted when the door knows nobody; a caller cannot send it.
- **Adapters are pinned and are the default on every launch path.** `nix/acp-agent.nix` builds the patched Claude Code and pi adapters from `acp/`'s lockfile; Codex builds from the lock and derivation in `packages/plugins/codex/acp/`. The packaged wrapper bakes both in with `--set-default`; `just serve` and `just run` resolve the same outputs through `scripts/acp-*.sh` and `scripts/nix-out.sh`, and the `nix` CI lane asserts the assignment.
- Three patches ride the pin, documented in `packages/plugins/claude/acp/patches/README.md`. The first keeps a background task's call `in_progress` until the harness reports a terminal state (agentclientprotocol/claude-agent-acp#865), with task id, kind, description and ending stamped on its frames; the panel reads that in `plugins/chat/src/browser/chat/background.ts`.
- The roster is detected, and a conversation is bound to one agent chosen at creation. `opencode` is found on the search path; `pi` is a pair — the adapter is pinned (`OLAI_ACP_PI`) and the agent is found and handed to it at spawn. **Each engine is a plugin**, because they share no release clock, and what each means by what it sends is a `Leg` behind `@olai/acp`'s `./engine`. Nothing is ever approved by failing to recognise it.
- `OLAI_ACP_AGENT` selects a command for the Claude row, including the scripted e2e agent; empty or unset falls through to packaged then search-path discovery. `on: no` on an engine node disables it; on `chat` it removes the conversation and leaves dependants waiting. `OLAI_AGENT_PATH` is where those probes look, defaulting to `PATH` and replacing it when set, because olai's `PATH` is not your shell's under a systemd user unit; the empty string means look nowhere.

### Identity, naming, pins and logging

- **Who is looking is a request, not a cell.** A reverse proxy injects a login and optionally an email claim, display name and picture. Olai trusts one configurable family of header names (`login-header`, `email-header`, `name-header`, `picture-header` on the `identity` node in `_olai/Settings.olai`), defaulting to `tailscale serve`'s four.
- Which picture a person wears is a four-rung ladder resolved server-side (`pictureOf`): picture header, `avatar-template` such as `https://github.com/{login}.png`, the gravatar of a claim that really is an address, none.
- The `identity` plugin offers the `Identity` door, and core reads it at the upgrade, at `GET /olai/who`, and in the `/mcp` route that attributes a capture. A connected tab reads it off the upgrade (`who.get`). Absent is a state: the header draws anonymous. Trust holds only when the proxy is the only way in and strips client copies ([running.md](../running.md)).
- **The deployment names itself** `olai [machine]` in the tab title, the wordmark and the manifest. The name is the server's `os.hostname()` (`OLAI_HOSTNAME` wins; `@olai/server`'s `hostname.ts`), crossing as `app.get` with the process start instant, which the header's `up 2h` chip ticks locally. The client half is one spelling, `@olai/surface`'s `appName`; `/manifest.webmanifest` is composed where it is served.
- **What a reader keeps is in the directory**: `Pins.olai`, one ordinary node per pin whose title is an address this app would spell ([format.md](../format.md#pins)). Agents reach it through `outlines_add`, `outlines_move` and `outlines_trash`. The server resolves the shelf per revision (`shelfIn`, the `pins` member), and which file is the shelf is re-walked only when the path set moves (`conventions.ts`).
- **Logging is Effect's and scoped to the serve.** Packages emit Effect log events; the composition root supplies sinks and a live level layer, updated from the `olai` namespace in the vault. `log-level` defaults to info, `log-format` to auto (pretty on a TTY, logfmt elsewhere).
- `OLAI_ALLOWED_ORIGINS` is the CSWSH escape hatch, comma-separated and empty by default (`packages/server/src/allowedOrigins.ts`), for a front end whose browser origin is not the `Host` it forwards. The gate runs on the raw socket before the upgrade, because the surface is unauthenticated and the origin is the only thing between a hostile page and the directory.

### Git

Git is the only history: no sync protocol, no CRDT. Its one job is an audit trail of what the tool wrote.

- **A commit is something somebody asks for**: `commit: off`, `manual` or `auto` on the `git` node, defaulting to `manual` and shared by every consumer of the directory. Writes land on disk and wait; the header's Commit button and the `git_commit` tool are two callers of one `Ops.commit`. `auto` commits after the server's quiet window, including headless.
- **What is waiting is derived and stored nowhere.** `git status --porcelain` names the dirty files, the current commit holds the committed side of a served outline, the store's last-good parse is the working side, and comparing two parsed sets is `format/src/changes.ts` with no git in it.
- The committed side is remembered per commit rather than per revision (`plugins/git/src/ledger/committed.ts`): a commit's copy of a file is immutable, so it is keyed by commit, path and the Claims snapshot that selected its parser. HEAD or the format claim changing requires a new reading. Both arms stay in the tree (`pending.equivalence.test.ts`, `pending.bench.ts`).
- **Never a text diff.** A `.olai` diff is one enormous line per node, so the unit is a node and what changed about it, classified once into one `Sort`.
- Who wrote it cannot come from git. A per-writer counter in the ops layer is cleared on commit and may be empty after a restart; the permanent record is an `X-Olai-Writer: chat-agent | mcp | web | filer | auto` trailer. A terminal has no word of its own, because `olai surface` is an `/mcp` client.
- Messages are prefixed `olai`, so `git log --grep '^olai'` is the audit view and `--invert-grep` gives back real history. Per-op words: `capture:`, `done:`, `doing:`, `move:`, `trash:`, `create:`, `see:`, `date:`.
- Committing checks the repository is free first (merge, rebase, cherry-pick, detached HEAD), and that hole is what decided manual over automatic. A git failure never fails a write: the bytes are on disk, so a refusal is an answer (`Failed`, with git's words).
- **The scope is the whole repository** (`commit-whole-repo`). A served dirty outline gets node-level changes; every other dirty file gets a path and the porcelain's status letter. A commit names a selection and never git's index: exactly the paths asked for, on both `add` and `commit`.
- **It pushes**: one verb, the current branch to the upstream it tracks, with git's refusal surfaced verbatim. How far ahead comes off the `--branch` header the status call already prints. Resolving a divergence stays in the CLI.
- **A reader is told why** (`git-invisible`). Every write's reply carries `why`, with no boolean beside it, because nothing commits a write on its own any more. The `git` cell and the `pending` cell are one derivation published twice, recomputed on three clocks: every revision, every landed commit, and a slow sweep because nothing watches `.git`.
- Three failures a probe cannot see are remembered rather than derived: a commit that refused, a push that refused (`push-failure-invisible`), and whether the quiet window has stopped and why. None may make a write fail, wait or retry.

## Split panes

A pane is a route: the same page (an outline, a zoom, a day, the agenda, the trash, a document), the same filter, the same chrome.

- The workspace is a **layout tree**: a leaf (one route) or a split (an axis and children with fractions, where `0` is collapsed). Today's product writes only a lone leaf or a one-level row.
- That row serializes as the flat `/s/<encoded-route>/…` list (`?w=` fractions, `?f=` focus), so every existing link stays. Axis and nesting have room in the codec (`?a=`, `?t=`) and are not written yet. Reload restores the layout, Back walks it, and sharing the URL shares the workspace.
- Exactly one pane is focused, with a visible ring when there are two or more. Keyboard shortcuts, the palette and filter typing act on that pane.
- A plain click navigates the pane the link was in. Alt+click opens the target in the pane to the right, reusing one already there; Alt+Shift+click forces a new one. No rule targets "leftmost".
- Closing the second-to-last pane returns to a plain page. Below a minimum width a pane collapses to a labelled rail, and collapse and close are different verbs. On a narrow screen the list is a tab strip over one column.
- Panes are sibling views over the one store. Dragging a node between panes would be the outline's own `place` and is not wired yet, because the drag measures one page's rows. Saved layouts are a follow-up.

## Stack

The tools olai is built from, with the one-line reason for each.

- **Runtime**: TypeScript on Bun. Bun is the package manager, test runner and script runner; types are checked separately with `tsc --noEmit`.
- **Effect**: kolu's whole stack is Effect 4 — Effect Schema at process boundaries, `RpcGroup` on the wire, `HttpRouter` layers for HTTP, `Schedule` for reconnect. oRPC, partysocket and hono are gone, and the `effect` version matches the pinned kolu's exactly, enforced via `package.json` overrides. On Bun it runs as `@effect/platform-node` under Node compatibility, the proven odu/drishti pattern; the one known seam, Bun's unix-socket async-connect-error contract, matters only if olai ever serves a unix socket, which it does not.
- **zod is in the tree and it is not ours.** `@agentclientprotocol/sdk` declares it a peer dependency and imports it at runtime, so it is a declared dependency of `packages/plugins/chat`, the one package that runs the protocol's subprocess. `packages/acp` imports SDK types only. No olai module imports zod, and the format has exactly one validator (Effect Schema, in `format`).
- **Markdown**: remark + rehype-sanitize, rendered at view time, one pipeline for a note, a document, an agent's words and a title. Titles take one extra step: every block is unwrapped to its phrasing content, so block-level source cannot break a row's layout.
- GFM brings footnotes, whose ids are re-minted per rendered block. `rehype-highlight` is bundled rather than fetched, coloured with this theme's tokens, and told its grammars (lowlight's common set plus Nix). It runs after the sanitiser, because the `hljs-` spans are ours and the `language-…` class is already on the default allowlist.
- The allowlist is the sanitiser's default plus two named additions in its own module (`markdown-ui/src/sanitise.ts`): an anchor's `class`, and `message:` on an `href` so a captured mail keeps Mail.app's address. The pipeline is its own chunk, `modulepreload`ed by the shell; until it lands, markdown surfaces show the file's text illegibly under one rule keyed on `data-markdown="waiting"`, so no reader is shown raw `**`.
- **Styling**: Tailwind v4, utilities inline in components, with a CSS entry holding only `@theme` tokens and rules for markup this codebase does not author. No `@apply`, which would invent a second name for a set of utilities, and no class-validity scanner.
- **Theming**: eleven tokens (paper, desk, panel, pill, ink/muted/rule, four accents) make a palette, tabled in `appearance/src/palettes.ts`: reef, leaf, manuscript, bloom, sky, chalk, aurora, pitch, ember, dusk. The build generates one `:root[data-theme="…"]` block per row, so adding a theme is adding a row.
- A theme pick is client state, written on `<html>` before the first paint, carried between tabs by the `storage` event, never sent anywhere. The OS preference is not consulted, because two ways to be dark can disagree. Every palette meets a reading floor and `chalk` also promises WCAG AA, both held by a unit test.
- **Type**: three tokens (`--font-sans`, `--font-serif`, `--font-mono`) make a typeface, catalogued in `packages/fonts`; `@olai/fonts/build` generates `@font-face` plus one `:root[data-font="…"]` block per row. The default is Olai (Literata / iA Writer Quattro / iA Writer Mono), with Atkinson Hyperlegible a pick. Hosted files convert to woff2 once in the Nix store and the client build copies out of `OLAI_FONTS_DIR`; the pick is stored under `olai.font` in `web`.
- **Plugin marks**: a tenant's logo arrives through that tenant's npins pin, never a committed copy and never a page fetch. `packages/plugin-kit/default.nix` runs the kit's pure transform (`src/mark/inline.ts`, which tokenises SVG ids and refuses `<script>`, `<style>`, inline handlers and off-document `href`) in the Nix store, reaching the tree through `OLAI_KOLU_MARK_DIR`, `OLAI_ODU_MARK_DIR` and `just install`.
- **Recurrence**: `repeat` holds the rule in the format's own words — `every day`, `every week on <weekday>`, `every month`, `every year` ([format.md](../format.md#repeating)). The grammar is closed and the picker reads its list off the grammar. `outlines_done` stamps the node and captures the next occurrence as a fresh node, decided in `ops/src/plan.ts`'s `recurring` so both faces send one request; the next date counts from the node's own date, so nothing reads a clock.
- **Dates**: validated as text rather than through a date library, so a writer reproduces what it read verbatim. A day is a ten-character prefix and a month a seven-character one, so grouping and comparison are string operations.
- Minting has one home beside the rule that accepts it (`format`'s `stampOf`): a local ISO datetime carrying its offset, because a mark is stamped where the person is standing. Only `done` and `cancelled` are stamped; `doing` and `todo` are written `true`. `outlines_doing` stamps `started`, and each round banks whole seconds into `worked`.
- Counting has one home too, `format/src/calendar.ts`, integers only and never a `Date`, because `new Date("2026-08-01")` is midnight UTC. Its readers are the calendar grid, the query grammar's relative words and the repeat rule; a week starts Monday, and Temporal is the intended tool if real arithmetic is ever needed.
- The client's clock (`web/src/client/clock.ts`) moves at the next computed local midnight and whenever the page becomes visible again. That it agrees with the writer's stamp is a test (`web/src/client/clock.test.ts`).
- **Nix**: flake + npins (kolu, nixpkgs, oss-olai) + justfile; `@kolu/*` packages hydrate as source from the Nix store. The third pin is a corpus rather than code: four differential legs read a real vault at `OSS_OLAI_VAULT` and throw naming that variable if it is unset. `just update-pins` moves the revision.
- **Remote unit tests and typechecking**: `just test-fast-remote` selects the existing `test` job (a leaf of Odu's task graph) through pinned Odu, with the same timeout, prerequisite ownership, working-tree snapshot and cleanup as `e2e-fast-remote`. Fast checks post no GitHub statuses; `just ci` keeps committed-HEAD attribution. Both `test` and `typecheck` permit up to six slots.
- Unit tests assign the longest estimated files first to the least-loaded shard, using slow-file estimates in `scripts/test-shard.sh`. Git discovers the files independently, an unlisted file gets a 0.1-second fallback, and a stale entry adds no tests. Typechecking partitions the sorted directories from `scripts/workspace-members.sh` and runs each package's complete script; empty slices do no work, and a malformed shard setting or a failed expansion fails the check. Without Odu shard variables both recipes run their normal local commands.
- **E2E**: Cucumber + Playwright. `just e2e` is one machine with up to four Cucumber workers; the same leaf carries `odu:shard=6`, so full CI may borrow up to six free slots and divide the suite by Cucumber's native scenario sharder, keeping four workers per slice.
- Six is a ceiling, not a demand: Odu derives the total from the slots it obtained, and the recipe translates its zero-based index to Cucumber's one-based `<index>/<total>`. A failed slot is skipped rather than retried. Each leased lane dispatches its own `install` and `nix` closure in parallel, projected as its own nodes (`e2e[2-of-N]::install`).
- The logical duration is the slowest slice, and Odu folds every shard node into the stable `e2e@<platform>` GitHub context. The split belongs to Cucumber, so adding a scenario cannot quietly leave one slot with the expensive half. A watch timeout or Ctrl-C leaves the run active; `nix run .#odu -- cancel --run <id>` cancels it.

## Packages

A Bun workspace over two globs, `packages/*` and `packages/plugins/*`, sharing `tsconfig.base.json`.

- `packages/plugins/` is the plugin container and holds no package of its own: chat, journal, search, the tenants `kolu`, `odu` and `xyne-spaces`, and the engines `claude`, `codex`, `opencode` and `pi`.
- Plugins are written against `@olai/plugin-api`. The registry that names them is `@olai/bundle`, and they are separate packages because a package that both named every plugin and was named by every plugin would be a cycle. `@olai/bundle` is the one package a plugin may not import.
- The workspace field is spelled once per consumer and nowhere restated: the root `typecheck` glob (`./packages/**`), `scripts/workspace-members.sh` (used by `scripts/check-hydrated-deps.sh` and `scripts/prove-fence.sh`), and `packages/bundle/src/tree.testlib.ts` for the TypeScript reading. All three refuse a shape they cannot expand and a glob that matched nothing.
- Layering between olai packages is declared in workspace dependencies and machine-checked by `bun install`. The isolated linker (`bunfig.toml`) gives each member only the `@olai/*` siblings its manifest names, so an undeclared one does not resolve.
- `bun install` cannot reach the `@kolu/*` tier, which hydrates as raw TypeScript from the Nix store. That is the fence's job, and it is a `bun test` (`packages/bundle/src/fence.test.ts`) rather than a shell script, because the two scripts it absorbed both ended `rg … 2>/dev/null || true` over `packages/*/src` — turning a missing ripgrep into a green result and missing `packages/tests` entirely. Version agreement with each pin stays in `scripts/check-hydrated-deps.sh`.
- The fence holds nine claims and derives both of its lists. Only `@olai/bundle` names a plugin, as an equality per package (`[]` for a general one, never a filtered list asserted empty). No plugin imports another or imports the registry back, and every plugin imports the interface.
- Doors are checked as separate graphs. The root door names every plugin in a literal specifier a bundler splits on and crosses into none, so each plugin is a chunk fetched only when the roster names it. The server door pulls no browser face and no `.tsx` at all, so a face in any folder is caught.
- A tenant is computed rather than declared: the workspace packages one plugin's doors reach and no other plugin's. `plugins/kolu` is kolu's by derivation, and `@olai/format` is general by construction because both tenants read it.
- The direction is downward. `server` and `web` sit on top; `format`, `store`, `log`, `child`, `acp`, `fonts` and `sigterm` sit at the bottom. Nothing points sideways or up.

Notes on particular rows:

- **`format`** takes the plugin-contributed kind vocabulary as a parameter, so it owns seven kinds and imports no plugin. It also holds the address grammar (`address.ts`: `[document]#[element]` and the bijection that prints and parses one), the commit vocabulary (`changesOf`, pure, no git), and the filename conventions including `inbox.ts`'s `captureInto`. The validator lives here and is never re-checked in the reader, the store, the ops layer or the web layer.
- **`child`** explicitly excludes readiness, transport, restart policy and the orphan sweep. Its riders are git's runner, the ACP agent, the Tailwind CLI and the server's process-boundary tests.
- **`plugins/git`** has three arms for opening a repository, because "not a repository" and "git could not answer" are different news. Its `./state` subpath is the half with no subprocess in it, which `format` re-exports for the wire.
- **`acp`** declares its boundary as a manifest a test enforces (`src/manifest.test.ts`): the closed export list, who may import the SDK, and who may import this package. Its refusals use one word, `Refused`, which `chat` translates into `UsageFailure`.
- **`state`** gives each plugin a keyed `LocalState` door, so a plugin parses its opaque document and never learns a path. The fence holds that no plugin imports or declares `@olai/state`.
- **`ops`** defines two doors it does not stand behind: `Ledger` (git) and `Search` (the matcher). Each is called through and refuses in words when nobody is mounted.
- **`plugins/chat`** keeps model choices keyed by engine/session (`models.ts`), observations in `heard/`, and conversation doorbell choices (`scopes.ts`), each with its existing bounded retention. The old which-conversation note is ignored; boot selects no conversation. `deliveries.ts` holds a body first and flushes later, so one body cannot overtake another under the same plugin. Optional MCP servers arrive as probes (`probes.ts`), asked four at a time once per conversation.
- **`plugins/kolu`** has three code doors, disjoint by graph: `./wire` (composes or reads the surface; no `solid-js`, no `@kolu/padi-client`), `./server` (runtime half and probe; no `.tsx` on that graph), and the root manifest (SolidJS and an emulator). `src/appliance/` is everything browser about kolu; `src/browser/` is what olai draws about kolu. Two further doors are names only: `./testids` and `./all.css`.
- **`plugins/odu`** matches that three-door shape, and its `./wire` may import `effect` and its own wire slice and nothing else. `src/server.ts` holds `worktrees.ts`, `doorbell.ts`, `wake.ts` and `probe.ts` — judgements neither the appliance (parametric in the node type) nor core (holds the vault, judges nothing about odu) may hold.
- **`effect-cordis`** exists because olai is written in Effect and the reactive half of a plugin system is a large proved thing not worth rewriting over `Scope`. `serviceTag` is one value that is both an Effect tag and the engine's key; `definePlugin` opens a `Scope` on activate and closes it from the disposer, so nobody outside sees `ctx.effect`. Two doors: the root runtime, imported only by `plugin-api`, and `./loader`, the declarative bundle carrying `node:url`, `node:fs` and a YAML parser, opened only by `bundle` ([README](../../packages/effect-cordis/README.md)).
- **`plugin-build`** does three things: it refuses what it cannot resolve (a half may name `@olai/plugin-api`, `effect` and `solid-js`); it compiles (`Bun.Transpiler` server-side, babel with `babel-preset-solid` browser-side) and bundles nothing; and it binds, so `import { createSignal } from "solid-js"` becomes a read of a table the host filled from its own static imports. Bundling a second Solid would give components that cannot read the app's contexts. It asserts afterwards that no module syntax is left. Two doors: the root compiler, and `./shared`, four string constants a tab opens ([README](../../packages/plugin-build/README.md)).
- **`fonts`**'s two entry points are one package, because a build taking the sheet without the files would ship a page whose every face 404s. `src/hosted.json` is the one list both the Nix file and the TypeScript read.
- **Pairs that deliberately do not depend on each other.** `server` does not depend on `web`: it serves a built bundle it is handed (`OLAI_DIST_DIR`, the one place either names it). `web` does not depend on `server`: they share the `surface` wire contract, not an import. Agent tool writes from `chat` reach `ops` through the session-owned internal MCP route. Host-owned binding, filing and new-chat writes use the declared Ops write gate, with their explicit writer identity. `plugins/kolu`'s `./appliance` is the only door that opens padi's socket, so it sits above `surface` and below `server`.

## Errors

Error kinds are `Schema.TaggedErrorClass`es: schemas that travel the wire and decode as themselves, surfaced as MCP tool errors and HTTP codes.

- The four kinds are `usage`, `validation`, `not-found` and `busy`. A fifth, `derived`, went with status derivation.
- Every validation error names `file:line`. A refused write carries the validator's verdict as structured data (`ValidationFailure.verdict`), whose rows are the rows a broken file on disk is explained by. A write that landed may carry a nudge (format.md's Status).
- Validation is staged, and the stage is part of the taxonomy (`stageOf`): a file decodes whole or not at all, then the set-wide rules run over the outlines that parsed. A finding costs the files it is about and nothing else.

**A validation answers with a verdict, not a log** (`@olai/format`'s `verdict.ts`). It used to be a flat `ReadonlyArray<OutlineError>` that every consumer re-partitioned for its own question. The questions are now asked at the socket:

- `blamed(report)` is what a load does with a finding: the report filed under the files it breaks. **About and broken are two planes**, two functions in `errors.ts`: `implicatedBy` names every file a finding touched, and `blamedOn` names the file it was found in plus every related site that did not say otherwise. The exceptions are said on the site by the rule that made them, never as a table beside the rows. `isCrossFile` is `blamedOn` counted.
- `stopping(set, files, standing)` is the write gate's question, per file. `admits` answers with the rows of the first asked file the published set holds no content for, so one broken outline cannot freeze writes to healthy ones and a refusal names its blocker. The gate asks over the write's own files plus whatever this write `darkened`, because moving a `ref` variant can strand values in a third file the write never opened. Darkened is a difference rather than a state, so an already-dark file stops nothing.
- The store asks `stopping` generically (`Codec.stopping`, inside `commit`) whichever arm the write took. Two conditions stay the store's own and are asked only over a refusal: the directory was already not loading (#439), and the published revision still accounts for these files.
- `summaryOf(broken, n)` is a bounded per-file face — state and counts, with no way to carry a row — for any surface drawn over pages that are still live. Enumerating is the broken outline's own pane's job.

**Not every failure is one of these kinds, and the ones that are not still have to reach somebody.** A refused write is an answer with rows a caller renders. A git that will not commit is not: the write happened and nothing about the outlines is wrong, so it travels as two ordinary values, `why` on the reply and the `git` cell the header draws. The rule learnt here (`git-invisible`): never silently ignore an error, and most of them belong somewhere a person can see.

**The staging forbids guesses**, and the catalogue is where each code answers for itself: `set-across-files` for a code whose every instance resolves a bare id, and `set-per-finding` for one whose instances differ. `isGuessWhileUnreadable` reads that, asked of the finding, since `bad-prop` judges seven kinds and only two resolve an id.

"`kitchen` is not a known id" is a guess when the line declaring `kitchen` is the one that failed to parse. So while any outline is unreadable, an unresolved `mirror`, `after`, `blocks` or `see` target is withheld rather than reported, and a withheld finding breaks nothing: the edge dangles honestly on a page that is otherwise live. Everything else is reported alongside the parse errors, because one pass should be enough to fix a directory. A report containing a per-line error says so (`reportStage`), and a second round is expected after those are fixed.
