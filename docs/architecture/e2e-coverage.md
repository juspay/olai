# Browser coverage audit

This document records which user workflows have real browser tests, and which still do not.

## Terms

These words are used throughout with the meaning olai gives them.

- **Vault**: the directory of files admitted by the enabled kind rows.
- **Serve**: one running server over one vault.
- **Plugin row**: one plugin as drawn on the plugins panel, with its own on/off switch.
- **Plugin rebuild**: what happens when a plugin is switched on or off. The running plugins change without a page reload, so open editors, drafts and selections must survive it.
- **Door**: a named service that one plugin publishes and other plugins declare they need.
- **Outline row**: one node displayed in an outline; a format records its first source line.
- **Parked row**: a blank outline line laid out on the page but not yet written to disk, because it has no title yet. Several at once are called a skeleton.
- **Node agent**: a chat conversation bound to one outline node. Its *scope* is the live process and lifetime of that conversation; olai keeps at most eight scopes and evicts idle background ones.
- **Fresh session**: replaces a node's current conversation with a new one and moves the old transcript into that node's history.
- **Unclaimed conversation**: a stored conversation that no node claims yet; the filer gives it a node under Chats in the Inbox.
- **kolu**: a separate tool that provides terminals for coding agents. Olai reaches its local daemon over a socket called padi.

## Ground rules

These rules decide when an audit row may be closed.

- A passing suite is necessary, but does not show that an untested workflow works.
- A row stays open until its UI actions and its failure and persistence paths are reviewed, exercised, and backed by assertions that observe the outcome.
- The PR's single bug/fix/test table records confirmed defects and new coverage. This inventory keeps unresolved rows instead of treating passing scenario counts as completion.
- Full-suite validation uses `just ci` or `just e2e-fast-remote`. Targeted browser runs use the worktree's dev server.
- Exploration against a real agent uses Claude/Sonnet in a disposable vault. Scripted ACP fixtures stand in for the agent in CI, so failures repeat exactly.

## Session lifecycle fixtures

Tests about sessions need an agent fixture that stores real sessions, not the canned one that reuses a single ID.

- The step `the harness keeps distinct sessions on disk` turns on the scripted ACP agent's persistent store inside the scratch vault. New sessions get unique IDs, only sessions that were actually prompted can be listed or loaded, and replay uses their real recorded messages across agent and server restarts.
- Without it, the canned agent's constant session ID and shared replay would hide bugs in which node owns which session, in history, and in restoring a session.
- The history-restart scenario also requires that the chosen session is written down before the panel reports itself ready. `agent.memory-order.test.ts` holds that write open for both new and loaded sessions and checks the session event waits for it. The browser scenario still restarts immediately after it sees the idle selection.
- Requests from the plugin inspector re-resolve their row the same bounded way ordinary plugin switches do, so a management report redrawing the row while the user scrolls cannot abort the workflow where a plugin removes itself. Reachability checks and workflow assertions are unchanged.

## Idle lifetime against the real agent (2026-09-05)

One manual run used a disposable vault, the real Claude/Sonnet agent, and the production 15-minute idle lifetime.

- The background node `reap-background` went idle at 09:17:20 UTC. The server logged the expected `idle eviction` at 09:32:19.825 and the roster showed the node asleep.
- The foreground node was still idle and still selected at 09:33:17, more than 15 minutes after it went idle at 09:18:00, so selection does prevent eviction.
- Clicking the sleeping node restored session `ff9ac910-6f2b-4214-bd8b-25ea76f5d0a2`, replayed its original reply, and accepted a new prompt.
- Its real `outlines_read` call returned the node's own title. An attempted `outlines_title` on the sibling node `reap-foreground` was refused by the subtree rule in force at the time, and the file on disk kept the sibling's original title.
- No browser errors were recorded, and the disposable server was stopped afterwards.

`node_agent_idle_lifecycle` now covers the same protections automatically with the production timer, so this run is supporting evidence rather than the coverage itself. The private test tag `@node-idle-fast` writes `idle-ms: 2000` for the chat plugin into the scratch settings file; ordinary scenarios use the schema defaults. The assertions watch the selected node, the unanswered question or the running watcher continuously across two deadlines, then check that an eligible background agent is evicted and can be restored. No fake clock and no test-only server route are used. None of this shows the broader node or cross-domain audit is finished.
