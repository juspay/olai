# Architecture

Olai serves one directory. `.jsonl` files under it are outlines ([format.md](format.md)); `.md` files are documents. `olai web <dir>` is the only entrypoint, and it only reads — there is no write CLI, and there never will be: the two write surfaces are the web UI and agent MCP tools, both calling one ops layer.

It reads that directory and keeps reading it: edit a file or `git pull`, and the open page follows without a reload. It also writes it, through one gate, from one layer: an agent asks for a node to be marked and the tree in front of you follows, because the write went to disk and came back through the same probe every other change does.

## Shape

```
files on disk ── load + validate ──▶ snapshot ── surface stream ──▶ browser (SolidJS)
      ▲                                              │                    │
      │                                              │              chat panel
   commit(baseRev)                                   │                    │
      │                                              ▼                    ▼
      └── ops (add, mark, move, archive) ◀── MCP tools ── ACP session ── procedures
```

- **Store** (`packages/store`, generic — caller-supplied codec, no olai types; extractable to its own repo later): files load into a validated snapshot, revision-tagged, with errors on a second independent channel so a broken set does not blank what is on screen. It stays current by PROBE — re-list the tree, re-stat everything, diff against a table of mtime+size stamps — with a file watcher that only *triggers* the probe and whose event payloads are dropped unread, plus a settle delay that turns a `git pull` into one probe and a slow backstop for the events a watcher loses. So a file arriving via `git pull` appears without a restart, and only the files whose stamps moved are re-parsed. The walk prunes dot-directories and `node_modules`: a served directory is somebody's working tree, and `.git` is both the largest thing under it and the one git writes to constantly — an unpruned probe would do its most expensive work exactly when git is busy. Design and the decisions behind it: [brainstorming/architecture.live-store.md](brainstorming/architecture.live-store.md).
- **The write gate is the same loop, run deliberately.** `commit({baseRev, changes, afterPublish?})` takes the probe's own permit, so a write and a `git pull` can never interleave over the stamp table they both read. Inside it: probe (so a change that arrived out of band is part of the revision this write is judged against), then the optimistic check — a `baseRev` the store has moved past is a typed `StaleWrite{currentRev}` — then validate the set the write WOULD produce, then stage every file beside its destination and rename them all, then re-probe and publish. Validation before any rename is what makes a refusal cost nothing on disk. The two outcomes travel on different channels because they mean different things: `StaleWrite` is a failure and the caller re-derives; a set the codec refuses is an *answer*, so the caller renders the errors rather than retrying. The changed files are re-read because the gate says so rather than because a stat noticed — stamps are deliberately coarse, and a write landing in the same second at the same length is exactly what they cannot see. The git commit rides `afterPublish`, an Effect the caller supplies, so the store never learns what git is.
- **Error scope is hybrid**, and the two halves answer different questions. A file that does not PARSE costs that one outline: the sidebar still lists it, opening it shows its own errors where its tree would have been, and every other outline stays live. A failure that no single file owns — a dangling cross-file reference, a duplicate id, a cycle — holds the whole last-good snapshot and raises a banner over it, because half a set is a set that was never on disk. The codec decides which of the two applies (`validate` is handed each file's `Result`, decode failures included) and the store only publishes the answer.
- **Ops** (`packages/ops`): the only writer, and the only reader an agent gets. Between `format` and `store`, because it is where an EDIT lives — "mark this done", "put this under that", "archive this" — and neither of those two knows what one is. Every request names a NODE, never a byte range, and three things follow from that: a retry against a newer snapshot lands cleanly, so no writer silently loses an update; a plan is whole RECORDS through the format's own writer, so a malformed file is unrepresentable through this path; and a refusal carries structured detail, so "these children are unfinished" is a list rather than a sentence. It also owns the codec that joins `format` to `store` — the same joint the write gate validates through — and the internal MCP server, which is the tool surface those ops are spoken through with no transport in it.
- **Surface mapping** (kolu's surface framework, pinned via npins): the snapshot is a `stream` (the store's own `SubscriptionRef.changes` — current value then updates, which already IS snapshot-then-deltas; poll-on-event would put staleness suppression in the surface layer, duplicating the probe the store owns); error state is a `cell`; collapse/view toggles are local `cells`; chat is a `collection` with batched deltas for the transcript, a `cell` for where the conversation stands, and `procedures` for send/cancel/new/load/list. The transcript is a collection rather than an event because an event replays nothing: the `deltas` verb IS snapshot-then-deltas, so one subscription carries both the history a reloaded tab needs and the frames a live one is watching, with no dedup rule in the browser. Every subscription sends a full snapshot first, then deltas; a reconnect is just a fresh snapshot — no resume protocol, no optimistic UI. No raw wire code — Effect RPC, sockets, HTTP routes — exists outside surface's API, with one deliberate exception: the internal MCP route, which is not a surface member because its consumer is an MCP client rather than an olai browser.
- **The connection is a thing the page reports on.** A page that is live and a page whose server died look identical unless something says otherwise, so a dot in the corner reports the wire in every shape of the app, green only while a server is answering. It reads `connectSurface`'s own four-state `status` — `connecting` / `live` / `reconnecting` / `retired` — and the fourth is the one that matters: the server this page came from has been replaced, the link has stopped dialling for good, and the only recovery is a reload, which the page offers rather than pretending. The handshake behind it is the framework's, not ours: the socket probes the reserved `system/identity` member on every open and echoes the server's process id back as `?pid` on the next dial, and `gateStaleSocket` on our side closes a tab presenting an id this process did not mint. Both halves used to be an app's to remember, and forgetting them is what shipped a tab that sat on a dead server looking healthy (juspay/kolu#2133 moved them into the seam and made the terminal state a required option).
- **Web**: a SolidJS client over WebSocket, using surface's solid hooks (subscriptions reconcile into Solid stores). The client bundle is built by `Bun.build` via `@kolu/surface-app`'s helpers; the server is a Node `http` server with a `ws` upgrade. Started as `olai web <dir> [--port] [--host]` — a nix-built binary whose only job is serving; `just serve` and `nix run` wrap it — bound to loopback by default. The UI is a sidebar listing the found outlines with one page in the main pane; mirrors render their target's subtree inline, marked. There are two routes, and the difference between them is what each is a property of: `/o/<file>` names a file, so it spells the path; `/n/<id>` names a node, and an id is all it may spell — ids are unique across the loaded set and survive renames and moves across files, so the permalink outlives every edit short of a delete, while a URL that also carried the outline could disagree with the file it named. A zoomed page is the node as heading, its note, its children as the same tree, above the *canonical* parent chain as breadcrumbs — derived, so the crumbs are the same however you arrived, and a mirror's id resolves through its chain to the one page its target has. What is folded, and whether done nodes are drawn, are per-view client-local signals: they belong to a reading rather than to the file, nothing is written, and hiding what is done is a row not drawn.
- **Agents**: chat is one ACP session (`@agentclientprotocol/sdk`) over a subprocess, and the server owns exactly one — olai is a single-user app, so there is no session per tab or per outline, and every browser watching sees the same transcript. The agent's cwd is the served directory, which is what makes its stored conversations findable: boot asks `session/list` for that directory and ADOPTS the most recently updated one, replaying it, so the panel comes up in the conversation you were last in and `claude --resume` in a terminal reaches the same sessions. Olai keeps no transcript store of its own. Permission requests are auto-approved: the tools being approved are the mediated ops, already validated. The session is handed one MCP server — olai's own, over an HTTP route on the same listener, because the tools it exposes are this process's ops over this process's store and a stdio server would mean a second olai with a second store. Whole-file agent writes are rejected by design: `fs` capabilities are false in both directions, and the only channel to the disk is the ops layer.
- **The adapter is pinned.** `nix/acp-agent.nix` builds the Claude Code ACP adapter from a committed npm lockfile, and the binary's wrapper bakes it in, so a nix-built olai needs nothing ambient. `OLAI_ACP_AGENT` overrides it — that is how the e2e suite points at a scripted agent, and how you point at a different one. Unset entirely, olai serves without a chat panel rather than refusing to start: reading a directory must not depend on an agent being installed.
- **Git is the only history**: no sync protocol, no CRDT. Every write commits the files it produced, gated on the served directory actually being a work tree, with `--no-commit` as the opt-out. The message convention is the racket reference's — `capture:` / `done:` / `doing:` / `move:` / `archive:` and the node's title — because a log a person already knows how to read is worth more than a better one they do not. A git failure never fails a write: the bytes are on disk and the browser has already seen them, so a refusal is reported as `committed: false`.

## Stack

- **Runtime**: TypeScript on Bun — Bun is the package manager, test runner and script runner; types are checked separately with `tsc --noEmit`.
- **Effect**: kolu's whole stack is Effect 4 (kolu PR #2101; the "Effect, everywhere" post) — Effect Schema at process boundaries, `RpcGroup` on the wire, `HttpRouter` layers for HTTP, `Schedule` for reconnect. oRPC, partysocket and hono are gone, and nothing olai writes uses zod. The `effect` version matches the pinned kolu's exactly (one copy fleet-wide, enforced via `package.json` overrides).
- **zod is in the tree, and it is not ours.** `@agentclientprotocol/sdk` declares it a peer dependency and imports it at runtime to validate ACP payloads, so it is a declared dependency of `packages/server` and comes back in the lockfile. That is the whole of it: no olai module imports zod, no schema of ours is written in it, and the format still has exactly one validator (Effect Schema, in `format`). Written down here rather than only in the manifest because "zod is gone" is the kind of claim a reader will otherwise carry forward — the honest version is that we do not write it, not that nothing in the closure has it.
- **Effect on Bun**: the proven odu/drishti pattern — `@effect/platform-node` under Bun's Node compatibility. One known seam: Bun's unix-socket async-connect-error contract needs odu's one-line shim, relevant only if we ever serve a unix socket.
- **Markdown**: remark + rehype-sanitize, rendered only at view time.
- **Styling**: Tailwind v4 — utilities inline in the components, and a CSS entry holding only the `@theme` tokens and the rules for markup this codebase does not author (a rendered note's tags come from a file on disk and can carry no classes). No `@apply`, which would recreate the problem utilities solve by inventing a second name for a set of them. Deliberately no class-validity scanner: kolu ships unguarded Tailwind and the silent-typo trade-off is accepted (decided 2026-08-09).
- **Dates**: validated as text, not through a date library — a writer must reproduce what it read verbatim. Temporal is the intended tool if arithmetic on them is ever needed; nothing needs it yet.
- **Nix**: flake + npins (kolu, nixpkgs) + justfile; `@kolu/*` packages hydrate as source from the Nix store.
- **E2E**: Cucumber + Playwright.

Kolu's Effect-4-beta discipline ports over with the stack: any dependence on beta *behavior* carries a grep-able `BETA-ASSUMPTION(<version>)` marker that fails CI on a pin bump until re-measured, and CI scanners ban the silent agent failure modes — `await` on an Effect, an Effect built but never run — with every `Effect.run*` edge on a named allowlist.

## Packages

A Bun workspace (`packages/*`, shared `tsconfig.base.json`). Layering between packages is declared in workspace dependencies and machine-checked by `bun install`; the table below is the whole of it. The direction is downward — `server` and `web` sit on top, `format` and `store` at the bottom, and nothing points sideways or up. (`web` does not depend on `server`: they share a wire contract, `surface`, not an import.) The format validator lives in exactly one place — never re-checked in the reader, the store, the ops layer or the web layer.

| package | depends on | what it is |
|---|---|---|
| `format` | — | the format core: `parseOutline` per file, `validate` per set, the canonical writer and the `ord` index, the refusal vocabulary, and the derivations (status, sibling order, tags, one node's ancestry and what its id zooms to) both the validator and the view read from |
| `store` | — | files as a revision-tagged snapshot and the `commit` write gate; generic over content, so it carries no outline types |
| `ops` | `format`, `store` | the only writer: the semantic edits, the codec that joins the two below it, the parsed-node queries, and the internal MCP server those are spoken through |
| `surface` | `format` | the surface spec: an `outlines` stream, an `errors` cell, and chat's transcript collection, state cell and procedures |
| `server` | `format`, `ops`, `store`, `surface` | the composition root: the ACP session, the HTTP + WebSocket server with the MCP route on it, and the `olai web` binary |
| `web` | `format`, `surface` | the SolidJS client — outline and chat panel — its Tailwind stylesheet, and the `Bun.build` that produces both |
| `tests` | — | Cucumber features driven through Playwright against the nix-built binary, plus the scripted ACP agent they drive the chat loop with |

`server` does not depend on `web`: it serves a built bundle it is handed (`OLAI_DIST_DIR`, the one place either of them names it), so the browser build is a build artifact rather than an import.

**Owed upstream.** `packages/server/src/listener.ts` sequences an origin gate, an upgrade, a stale-tab check, heartbeat enrolment and a serving stack — the same sequence, in the same order, as kolu's own surface-app example. That is a `serveSurfaceApp({surface, handlers, clientDist, host, port, allowedOrigins})` primitive belonging in `@kolu/surface-app`, beside the `surfaceAppLayer` and `acceptSurfaceSocket` it already owns. Until it exists, two copies are kept in step by hand, which is exactly the volatility a receptacle is supposed to contain.

## Errors

Error kinds (`usage`, `validation`, `not-found`, `derived`, `busy`) are `Schema.TaggedErrorClass`es — schemas that travel the wire and decode as themselves — surfaced as MCP tool errors and HTTP codes. Every validation error names `file:line`. Errors that teach are the product: a refused derived-state write lists the unfinished children as structured data.

Validation is staged, and the stage is part of the taxonomy (`stageOf`): a file is decoded whole or not at all, and the set-wide rules then run over the outlines that DID parse. What that costs the reader is one outline and, usually, nothing else — the hybrid error scope above, decided in the format ([format.md](format.md)) and published by the store.

The staging still forbids guesses, and the catalogue is where each code answers for itself (`set-across-files`, read by `isGuessWhileUnreadable`). "`kitchen` is not a known id" is a guess when the line declaring `kitchen` is the one that failed to parse — so while any outline is unreadable, an unresolved `mirror`/`after`/`blocks`/`see` target is withheld rather than reported, and withholding one is itself a reason to refuse the whole set: its nodes point at ids nothing can resolve. Everything else is a finding whatever the missing file held, and is reported alongside the parse errors, because one pass should be enough to fix a directory. A report containing a per-line error says so (`reportStage`), and a second round is expected after those are fixed.
