# Architecture

Olai serves one directory. `.jsonl` files under it are outlines ([format.md](format.md)); `.md` files are documents, carried in the same snapshot with their text, because a document is content of the directory the way a note is. There are two entrypoints and they are the two write surfaces, not two products: `olai web <dir>` puts a browser in front of the ops layer, `olai mcp <dir>` puts an agent's pipes in front of the same one. There is no write CLI and there never will be — nothing on the command line adds a node, marks one or moves one, and both subcommands are transports rather than tools.

It reads that directory and keeps reading it: edit a file or `git pull`, and the open page follows without a reload. It also writes it, through one gate, from one layer: an agent asks for a node to be marked and the tree in front of you follows, because the write went to disk and came back through the same probe every other change does.

## Shape

```
files on disk ── load + validate ──▶ snapshot ── surface stream ──▶ browser (SolidJS)
      ▲                                              │                    │
      │                                              │              chat panel
   commit(baseRev)                                   │                    │
      │                                              ▼                    ▼
      └── ops (create, add, mark, move, archive, see) ◀── MCP tools ── ACP session ── procedures
                                                 ▲
                                                 └── stdio ── an agent in a terminal
```

- **Store** (`packages/store`, generic — caller-supplied codec, no olai types; extractable to its own repo later): files load into a validated snapshot, revision-tagged, with errors on a second independent channel so a broken set does not blank what is on screen. It stays current by PROBE — re-list the tree, re-stat everything, diff against a table of mtime+size stamps — with a file watcher that only *triggers* the probe and whose event payloads are dropped unread, plus a settle delay that turns a `git pull` into one probe and a slow backstop for the events a watcher loses. So a file arriving via `git pull` appears without a restart, and only the files whose stamps moved are re-parsed. The walk prunes dot-directories and `node_modules`: a served directory is somebody's working tree, and `.git` is both the largest thing under it and the one git writes to constantly — an unpruned probe would do its most expensive work exactly when git is busy. Design and the decisions behind it: [brainstorming/architecture.live-store.md](brainstorming/architecture.live-store.md).
- **The write gate is the same loop, run deliberately.** `commit({baseRev, changes, afterPublish?})` takes the probe's own permit, so a write and a `git pull` can never interleave over the stamp table they both read. Inside it: probe (so a change that arrived out of band is part of the revision this write is judged against), then the optimistic check — a `baseRev` the store has moved past is a typed `StaleWrite{currentRev}` — then validate the set the write WOULD produce, then stage every file beside its destination and rename them all, then re-probe and publish. Validation before any rename is what makes a refusal cost nothing on disk. The two outcomes travel on different channels because they mean different things: `StaleWrite` is a failure and the caller re-derives; a set the codec refuses is an *answer*, so the caller renders the errors rather than retrying. The changed files are re-read because the gate says so rather than because a stat noticed — stamps are deliberately coarse, and a write landing in the same second at the same length is exactly what they cannot see. The git commit rides `afterPublish`, an Effect the caller supplies, so the store never learns what git is.
- **Error scope is hybrid**, and the two halves answer different questions. A file that does not PARSE costs that one outline: the sidebar still lists it, opening it shows its own errors where its tree would have been, and every other outline stays live. A failure that no single file owns — a dangling cross-file reference, a duplicate id, a cycle — holds the whole last-good snapshot and raises a banner over it, because half a set is a set that was never on disk. The codec decides which of the two applies (`validate` is handed each file's `Result`, decode failures included) and the store only publishes the answer.
- **Ops** (`packages/ops`): the only writer, and the only reader an agent gets. Between `format` and `store`, because it is where an EDIT lives — "mark this done", "put this under that", "start a new outline", "archive this", "point this at that" (`see`) — and neither of those two knows what one is. Every request names a NODE (or, for `create`, a relative `.jsonl` path judged segment by segment the way `/media/*` is), never a free-form byte range, and three things follow from that: a retry against a newer snapshot lands cleanly, so no writer silently loses an update; a plan is whole RECORDS through the format's own writer, so a malformed file is unrepresentable through this path; and a refusal carries structured detail, so "these children are unfinished" is a list rather than a sentence. `create` is the one op that mints a file the set does not yet hold — `add` refuses any path that is not already loaded — and it rides the same stage → validate → rename → commit gate, optionally seeding a first node shaped exactly like a capture. It also owns the codec that joins `format` to `store` — the same joint the write gate validates through — and the MCP server, which is the tool surface those ops are spoken through with no transport in it. That last word is what made the external tool surface nearly free: `handle` takes a JSON-RPC message and answers one, so an HTTP route and a pair of pipes are two callers of one dispatch rather than two servers.
- **Documents ride the snapshot, and that is the whole read path.** A `.md` decodes to its text through the same codec, is cached against the same stamp, and travels in the same revision — so an edited document reaches an open page by the mechanism that was already there, a `doc`-carrying node can show a line of its document wherever it is drawn without asking for it, and there is exactly one answer on screen to "what does this directory say right now". What it costs is the text of every served document in every frame; what a second read path would have cost is a second thing to invalidate and a page whose outline and document could be two different reads of the disk. The one thing that cannot ride it is a PICTURE — the browser fetches an `<img src>` itself — so there is one HTTP route besides the bundle, `/media/*`, restricted to picture extensions, and its URL is declared in `surface` so the renderer that writes it and the route that reads it are one bijection rather than two spellings kept in step by hand.
- **Surface mapping** (kolu's surface framework, pinned via npins): the snapshot is a `stream` (the store's own `SubscriptionRef.changes` — current value then updates, which already IS snapshot-then-deltas; poll-on-event would put staleness suppression in the surface layer, duplicating the probe the store owns); error state is a `cell`; collapse/view toggles are local `cells`; chat is a `collection` with batched deltas for the transcript, a `cell` for where the conversation stands, and `procedures` for send/cancel/new/load/list. The transcript is a collection rather than an event because an event replays nothing: the `deltas` verb IS snapshot-then-deltas, so one subscription carries both the history a reloaded tab needs and the frames a live one is watching, with no dedup rule in the browser. Every subscription sends a full snapshot first, then deltas; a reconnect is just a fresh snapshot — no resume protocol, no optimistic UI. No raw wire code — Effect RPC, sockets, HTTP routes — exists outside surface's API, with two deliberate exceptions, and neither carries surface data: everything an MCP CLIENT speaks (the internal route, and the stdin/stdout `olai mcp` answers on), whose consumer is an agent rather than an olai browser, and `/media/*`, which the browser fetches itself — the URL of that one is still declared in `surface`, so the renderer that writes it and the route that reads it are one bijection rather than two spellings kept in step by hand.
- **The connection is a thing the page reports on.** A page that is live and a page whose server died look identical unless something says otherwise, so a dot in the corner reports the wire in every shape of the app, green only while a server is answering. It reads `connectSurface`'s own four-state `status` — `connecting` / `live` / `reconnecting` / `retired` — and the fourth is the one that matters: the server this page came from has been replaced, the link has stopped dialling for good, and the only recovery is a reload, which the page offers rather than pretending. The handshake behind it is the framework's, not ours: the socket probes the reserved `system/identity` member on every open and echoes the server's process id back as `?pid` on the next dial, and `gateStaleSocket` on our side closes a tab presenting an id this process did not mint. Both halves used to be an app's to remember, and forgetting them is what shipped a tab that sat on a dead server looking healthy (juspay/kolu#2133 moved them into the seam and made the terminal state a required option).
- **Web**: a SolidJS client over WebSocket, using surface's solid hooks (subscriptions reconcile into Solid stores). **The client reads that store and never writes to it.** What arrives on the wire is BORROWED: a row wrapper is minted fresh per frame but the records inside it are the served set's own objects, and Solid's `reconcile` mutates what it is given, transitively — so a page model reconciled into a store of its own rewrites the set in place, poisoning every other page and feeding the write back into the derivation that produced it (that was the day view, until it stack-overflowed on the second day opened). So there is no store in the client above the framework's: what a page draws is a memo, and identity across frames — the thing a store was reached for — is a keying question, answered by `<Key>` on `Row.key` and on a day entry's `file/id`. The client bundle is built by `Bun.build` via `@kolu/surface-app`'s helpers; the server is a Node `http` server with a `ws` upgrade. Started as `olai web <dir> [--port] [--host]` — a nix-built binary whose only job is serving; `just serve` and `nix run` wrap it — bound to loopback by default. The UI is a sidebar listing the found outlines with one page in the main pane; mirrors render their target's subtree inline, marked. There are five routes, and the difference between them is what each is a property of: `/o/<file>` names a file, so it spells the path; `/doc/<file>` names a document, which is also a file and also spells its path — a second prefix rather than more work for the first, because an outline and a document are two different things a file can be, and the address says which before the set is in hand; `/n/<id>` names a node, and an id is all it may spell — ids are unique across the loaded set and survive renames and moves across files, so the permalink outlives every edit short of a delete, while a URL that also carried the outline could disagree with the file it named; `/d/<ISO-date>` names a day, which is not a thing on disk at all; and `/today` names no day but the day it *is*, which is what an agent, a bookmark and a home screen can each keep. A zoomed page is the node as heading, its note, its children as the same tree, above the *canonical* parent chain as breadcrumbs — derived, so the crumbs are the same however you arrived, and a mirror's id resolves through its chain to the one page its target has. What is folded, whether done nodes are drawn, and which month the calendar shows are per-view client-local signals: they belong to a reading rather than to the file, nothing is written, and hiding what is done is a row not drawn. Notes have one shape under a row — one dim plain-text line under the title, clamped with an ellipsis (Workflowy-style), and a click (or tap) expands it in place to the full note and see links; click again or click away collapses; the date badge stays on the title line; there is no density switch, no hover, and no per-place unfold cell. A zoomed page's own note is always full — it is the body of the page. Three decisions belong to the client rather than to the set and are named here because nothing else would name them: the shell is wrapped in an `<ErrorBoundary>`, because the three error surfaces above are errors as DATA and none of them can catch a bug in this app's own render — a thrown render used to be a white tab with the truth in a console nobody opened; navigating decides where the PAGE is, since a route change redraws the main pane and moves nothing else, so a page you go to starts at the top and a page you go back to is where you left it (remembered per history entry, in the document's own memory, recorded as the reader scrolls because `popstate` fires after the position it was made from is gone); and a preference of this browser's belongs to the BROWSER rather than to the tab, so the `storage` event carries a pick into every other tab this app is open in.
- **Installable, never offline.** The page is a PWA: a web app manifest assembled by the server through kolu's manifest layer (which owns `start_url` and `display: standalone`), naming the original olai mark — an SVG, 192/512 PNGs and a maskable 512, plus an `apple-touch-icon` for what reads no manifest — as files the bundle ships verbatim at the dist root, outside the content-hashed `/assets/` so their URLs are stable. There is deliberately **no service worker**: this app is live or nothing, so a cached shell would show outlines that had stopped being true, and the framework's lifecycle retires any worker an older olai left behind. Below 48rem the sidebar stops being a column and goes behind a burger — one row shut, the whole sidebar open, capped and scrolling so the outline is still under it — because everything in it has to fit on a screen 390 points wide and the one control that must be reachable (the way into the agent) is in its footer. What a finger aims at is 44px — except the tree's gutter, which takes that in height only, because a 44px-wide toggle and bullet at every level of indent leave a phone no room for the title. An on-screen keyboard covers the viewport without shrinking it, so the page publishes its own `visualViewport` reading as `--visible-h`/`--visible-bottom` for anything anchored to the bottom.
- **The journal is a query.** There is no stored year→month hierarchy, no journal file and no filename anything is special about (format.md's `date` field; rewrite decision 11): a month in the sidebar aggregates the *whole set's* dated nodes, and a day page is every node carrying that date, in any outline, grouped by the file it lives in and shown with the same ancestry, tags, derived status and note a zoomed page gives it. All of it is derived at view time by `format`'s date derivations — the one place both surfaces read from, so a dot and the day it opens cannot disagree — and none of it writes: a day with something on it is a link with a dot, an empty day is inert, today wears a ring and the day being read is filled. An empty day says so and offers nothing to press, because pressing it could only mean a write, and writes arrive with the ops layer.
- **Agents** (`packages/chat`): chat is one ACP session (`@agentclientprotocol/sdk`) over a subprocess, and the server owns exactly one — olai is a single-user app, so there is no session per tab or per outline, and every browser watching sees the same transcript. The agent's cwd is the served directory, which is what makes its stored conversations findable: boot asks `session/list` for that directory and ADOPTS the most recently updated one, replaying it, so the panel comes up in the conversation you were last in and `claude --resume` in a terminal reaches the same sessions. Olai keeps no transcript store of its own. Permission requests are auto-approved: the tools being approved are the mediated ops, already validated. The session is handed one MCP server — olai's own, over an HTTP route on the same listener, because the tools it exposes are this process's ops over this process's store and a stdio server would mean a second olai with a second store. Whole-file agent writes are rejected by design: `fs` capabilities are false in both directions, and the only channel to the disk is the ops layer. WHICH MODEL is two facts, not one: the session's config option is what was picked, and the CLI's own `init` message — forwarded because `session/new` asked for it — is what is running. A `/model` is handled inside the wrapped CLI, so the picker never hears about it; whichever source moved last is what the header names, each debounced against its own previous value, and the first live id is a baseline rather than a change. A new conversation EMPTIES the panel: the agent's context is gone, so nothing above could be followed up, and a transcript you cannot refer to is history kept for its own sake. A message sent while a turn is running QUEUES rather than being refused — a person watching an agent work has the next thing ready long before it finishes — and the queue is dropped, out loud, when what it was waiting behind stops meaning what it meant: a cancel, an agent that died, a conversation being left.
- **The same tools are also a command anybody can launch** (`olai mcp <dir>`, `packages/server/src/mcp/`). A coding agent in a terminal is not olai's subprocess and has no listener to dial, so it gets what nearly every MCP client expects: a command, and JSON-RPC newline-framed over its own pipes. That is the OPPOSITE conclusion from the bullet above out of the same argument — who owns the store. The panel's agent is a child of the server, so a stdio server there would have been a second olai for nothing; this one has to work with no server running at all, which is the ordinary case, and a bridge into a running instance would need that instance's port and its per-process token discovered from outside and would still have to do all of this on finding nothing listening. So two stores may watch one directory, and that is safe for the reason the write gate exists: it probes before it judges, and a base that has moved comes back as `StaleWrite` for the ops layer to re-plan against the newer snapshot — the same machinery a `git pull` under an open tab already goes through. What it is not is a lock: two writers landing on one file inside the same instant is last-write-wins, exactly as an editor and a `git checkout` are, and git is the recovery net for that as for everything else. One rule belongs to the transport rather than to any caller — **stdout is the protocol** — so the whole program's logging is routed to stderr (`@olai/log`'s `toStderr`, one line at that composition root): a store's failed-probe warning on stdout is a frame that is not a frame, and no future writer should have to remember that.
- **The adapter is pinned, and it is the default on every launch path.** `nix/acp-agent.nix` builds the Claude Code ACP adapter from a committed npm lockfile; the packaged binary's wrapper bakes it in with `--set-default`, and the justfile recipes that run the tree directly (`just serve`, `just run`) resolve the same derivation on demand through `scripts/acp-agent.sh`. So no documented way of starting olai lands without an agent, and a person never has to learn that the variable exists. The `nix` CI lane asserts it: the wrapper must carry the assignment and the path it names must be executable, so dropping the `--set-default` fails a check rather than a browser.
- **`OLAI_ACP_AGENT` is the override, and empty is the off switch.** Point it at another ACP agent and that is what gets spawned — it is how the e2e suite points at a scripted one. Set it to the EMPTY string and there is deliberately no agent; that works through the packaged binary too, because `makeWrapper --set-default` emits `${VAR-default}`, which substitutes only when the variable is unset. (The one-dash form is asserted in the same CI lane: `:-` would swallow the off switch.)
- **With no agent, the panel says so.** Serving a directory has never depended on an agent being installed, and it still does not — but that principle is "the server is fine without one", not "hide the feature". The drawer draws, and its body names the variable and how to fix it. A capability that is silently absent cannot be told apart from one that is broken, or from one the reader has not found yet.
- **Logging is Effect's, and it is quiet by default** (`packages/log`). Every package says what it is doing with `Effect.logDebug` / `logInfo` / `logWarning` / `logError` — there is no `log` callback threaded through a constructor, which is what there used to be for the two packages a person actually hears from. One format for all of it, [logfmt](https://brandur.org/logfmt): one line per event, `key=value`, so the message is a short stable sentence and every value that varies is an ANNOTATION (`url=`, `root=`, `claimed=`, `agent=`) that can be grepped by field rather than matched out of a sentence. The e2e suite reads the bound address that way, which is also why there is no colour in it. Annotations set with `Effect.annotateLogsScoped` are inherited by every fiber forked under that scope, so the store's own probe warning says which directory it was probing without the store ever learning what a served directory is; `Effect.withLogSpan` puts `serve=…ms` on every line, so a boot is timed and a later line says how long the server has been up. **The verbosity switch is Effect's CLI `--log-level`**, already parsed and already in `--help`: `Info` is the default, so the loudest thing in the program (a relayed agent stderr chunk, at `debug`) is off until asked for. A second spelling of that — a `--verbose` of ours, an env var — would be a second answer to one question, so there is not one. The one thing Effect cannot do by itself is log from a Node callback, where there is no fiber and the operator's chosen level would silently not apply: `@olai/log`'s `emitter` captures the fiber's services once and runs every later line under them.
- **`OLAI_ALLOWED_ORIGINS` is the CSWSH escape hatch**, comma-separated, empty by default (`packages/server/src/allowedOrigins.ts`, its own file for the same reason `OLAI_DIST_DIR` has one). Loopback and same-origin is the common case; the extra entries are for a front end whose browser origin is not the `Host` it forwards — a reverse proxy, or `tailscale serve`. The gate runs on the raw socket BEFORE the upgrade, because after it the browser has a connection to argue about, and the surface is unauthenticated: the origin is the only thing between a page somebody else served and every outline in the directory.
- **Git is the only history**: no sync protocol, no CRDT. Every write commits the files it produced, gated on the served directory actually being a work tree, with `--no-commit` as the opt-out. The message convention is the racket reference's — `capture:` / `done:` / `doing:` / `move:` / `archive:` / `create:` / `see:` and the node's title (or a path, when an outline is born empty) — because a log a person already knows how to read is worth more than a better one they do not. A git failure never fails a write: the bytes are on disk and the browser has already seen them, so a refusal is reported as `committed: false`.

## Stack

- **Runtime**: TypeScript on Bun — Bun is the package manager, test runner and script runner; types are checked separately with `tsc --noEmit`.
- **Effect**: kolu's whole stack is Effect 4 (kolu PR #2101; the "Effect, everywhere" post) — Effect Schema at process boundaries, `RpcGroup` on the wire, `HttpRouter` layers for HTTP, `Schedule` for reconnect. oRPC, partysocket and hono are gone, and nothing olai writes uses zod. The `effect` version matches the pinned kolu's exactly (one copy fleet-wide, enforced via `package.json` overrides).
- **zod is in the tree, and it is not ours.** `@agentclientprotocol/sdk` declares it a peer dependency and imports it at runtime to validate ACP payloads, so it is a declared dependency of `packages/chat` — the one package that speaks the protocol — and comes back in the lockfile. That is the whole of it: no olai module imports zod, no schema of ours is written in it, and the format still has exactly one validator (Effect Schema, in `format`). Written down here rather than only in the manifest because "zod is gone" is the kind of claim a reader will otherwise carry forward — the honest version is that we do not write it, not that nothing in the closure has it.
- **Effect on Bun**: the proven odu/drishti pattern — `@effect/platform-node` under Bun's Node compatibility. One known seam: Bun's unix-socket async-connect-error contract needs odu's one-line shim, relevant only if we ever serve a unix socket.
- **Markdown**: remark + rehype-sanitize, rendered only at view time, and one pipeline for every piece of it — a node's note and a whole document are the same language read out of the same directory. GFM brings footnotes (whose ids are re-minted per rendered block, so two notes on a page cannot answer for each other); `rehype-highlight` paints fenced code, bundled with the client rather than fetched from a CDN, and coloured with this theme's own tokens; relative images are rewritten to the `/media` route and everything else is dropped. Highlighting runs AFTER the sanitiser deliberately: the `hljs-` spans are ours and need no allowlist entry, while the `language-…` class that produced them is the reader's and is on the sanitiser's default one.
- **Styling**: Tailwind v4 — utilities inline in the components, and a CSS entry holding only the `@theme` tokens and the rules for markup this codebase does not author (a rendered note's tags come from a file on disk and can carry no classes). No `@apply`, which would recreate the problem utilities solve by inventing a second name for a set of them. Deliberately no class-validity scanner: kolu ships unguarded Tailwind and the silent-typo trade-off is accepted (decided 2026-08-09).
- **Theming**: the eight tokens above are a *palette*, and there are fifteen of them (`web/src/client/theme/palettes.ts`, ported from the racket implementation). The table is the source: the build generates one unlayered `:root[data-theme="…"]` block per row and appends it to the stylesheet, and the picker draws one chip per row, so adding a theme is adding a row. A pick is CLIENT state — written on `<html>` by four inline lines in the shell before the first paint, stored in that browser, never sent anywhere, and carried into every other tab of that browser by its own `storage` event rather than waiting for a reload — and the OS's preference is not consulted at all: it used to choose the palette, which meant two ways to be dark that could disagree with each other and with the reader. One palette promises WCAG AA and a unit test holds it to that, pair by painted pair.
- **Dates**: validated as text, not through a date library — a writer must reproduce what it read verbatim. Reading them is text too: a day is a ten-character prefix and a month a seven-character one, so grouping, month boundaries and datetime→day are string comparisons. The one exception is where the days of a month land on a grid, which is integer arithmetic in the client (`web/src/client/calendar/month.ts`) rather than a `Date` — `new Date("2026-08-01")` is midnight UTC, which is the previous day for half the world, and a calendar that shifted a column by time zone is the bug that avoids. Temporal is still the intended tool if real date arithmetic is ever needed; nothing needs it yet. WHAT DAY IT IS is the client's one reading of a clock (`web/src/client/clock.ts`), in the reader's own time zone because the dates in the files are what a person wrote down, and it moves twice over: at the next local midnight, computed each time rather than assumed to be 24 hours later, and whenever the page becomes visible again — a laptop shut at eleven and opened at nine ran no timer while it slept, and a page whose promise is that it follows the files without a reload cannot have the day be the stale thing on it.
- **Nix**: flake + npins (kolu, nixpkgs) + justfile; `@kolu/*` packages hydrate as source from the Nix store.
- **E2E**: Cucumber + Playwright.


## Packages

A Bun workspace (`packages/*`, shared `tsconfig.base.json`). Layering between packages is declared in workspace dependencies and machine-checked by `bun install`; the table below is the whole of it. The direction is downward — `server` and `web` sit on top, `format`, `store` and `log` at the bottom, and nothing points sideways or up. (`web` does not depend on `server`: they share a wire contract, `surface`, not an import.) The format validator lives in exactly one place — never re-checked in the reader, the store, the ops layer or the web layer.

| package | depends on | what it is |
|---|---|---|
| `format` | — | the format core: `parseOutline` per file, `validate` per set, the canonical writer and the `ord` index, the refusal vocabulary, and the derivations (status, sibling order, tags, one node's ancestry, what its id zooms to, and what is dated a given day or month) both the validator and the view read from |
| `store` | — | files as a revision-tagged snapshot and the `commit` write gate; generic over content, so it carries no outline types |
| `log` | — | how olai says what it is doing: one format (logfmt) and two streams, the two lengths a failure is rendered at (`prettyCause` for a log, `reasonOf` for a sentence somebody reads — an Effect `Cause` renders through neither `.message` nor a template literal), the emitter a Node callback logs through without losing the fiber's level, annotations and spans, and the two ways a test hears a line — a collecting logger inside the process, a logfmt decoder for a suite reading a spawned binary's stdout. No logger and no level knob of its own — the verbs are `Effect.log*` and the switch is Effect's CLI `--log-level` |
| `ops` | `format`, `store` (`log` for tests only) | the only writer: the semantic edits, the codec that joins the two below it, the parsed-node queries, and the MCP server those are spoken through — transport-free, so the listener's route and the stdio command are two callers of one dispatch |
| `surface` | `format` | the surface spec: an `outlines` stream, an `errors` cell, and chat's transcript collection, state cell and procedures — plus the `/media` URL, the one address both ends spell and neither can import from the other |
| `chat` | `format`, `log`, `surface` | one conversation with one ACP agent: the subprocess, the session, the transcript, and the five verbs. NOT `ops` — the agent reaches the ops layer as an MCP client, over a URL and a token, which is why a whole-file write is not expressible |
| `server` | `chat`, `format`, `log`, `ops`, `store`, `surface` | the composition root: the HTTP + WebSocket server with the MCP route on it, the stdio transport `olai mcp` answers on, the order the layers go in, and the binary both are subcommands of |
| `web` | `format`, `surface` | the SolidJS client — outline, journal and chat panel — its Tailwind stylesheet, and the `Bun.build` that produces both |
| `tests` | `web` (`log` for its stdout decoder) | Cucumber features driven through Playwright against the nix-built binary, plus the scripted ACP agent they drive the chat loop with |

`server` does not depend on `web`: it serves a built bundle it is handed (`OLAI_DIST_DIR`, the one place either of them names it), so the browser build is a build artifact rather than an import. `chat` and `ops` do not depend on each other: they are the two things a person does to a directory, and the one place they meet is the internal MCP route, where one is a server and the other is a client.

**Paid upstream.** `packages/server/src/listener.ts` used to sequence an origin gate, an upgrade, a stale-tab check, heartbeat enrolment and a serving stack — the same sequence, in the same order, as kolu's own surface-app example, and two copies kept in step by hand. That sequence is `serveSurfaceApp` now (`@kolu/surface-app`, kolu#2137), and the file is one call to it plus the two decisions the primitive deliberately leaves to a consumer: whose port this is, and what a listener event sounds like in this program's log (`report.ts`). ## Errors

Error kinds (`usage`, `validation`, `not-found`, `derived`, `busy`) are `Schema.TaggedErrorClass`es — schemas that travel the wire and decode as themselves — surfaced as MCP tool errors and HTTP codes. Every validation error names `file:line`. Errors that teach are the product: a refused derived-state write lists the unfinished children as structured data.

Validation is staged, and the stage is part of the taxonomy (`stageOf`): a file is decoded whole or not at all, and the set-wide rules then run over the outlines that DID parse. What that costs the reader is one outline and, usually, nothing else — the hybrid error scope above, decided in the format ([format.md](format.md)) and published by the store.

The staging still forbids guesses, and the catalogue is where each code answers for itself (`set-across-files`, read by `isGuessWhileUnreadable`). "`kitchen` is not a known id" is a guess when the line declaring `kitchen` is the one that failed to parse — so while any outline is unreadable, an unresolved `mirror`/`after`/`blocks`/`see` target is withheld rather than reported, and withholding one is itself a reason to refuse the whole set: its nodes point at ids nothing can resolve. Everything else is a finding whatever the missing file held, and is reported alongside the parse errors, because one pass should be enough to fix a directory. A report containing a per-line error says so (`reportStage`), and a second round is expected after those are fixed.
