# What the research says: LLM agents and custom DSLs

Measured record, 2022–2026, on coding agents meeting domain-specific languages. Split out of [live-dsl.md](live-dsl.md) because it applies to any DSL a swarm-maintained codebase might grow, not just that one. Conclusions here; numbers, citations, caveats in the footnotes.

1. **The model's prior works against you.** A custom DSL has zero training data by construction. Racket itself is near the bottom of what models know. A macro DSL on Racket: "a minority language within a minority language."[^prior]
2. **The cost shows up in the compile loop, not in reasoning.** Models pick the right algorithm, then fail to spell it in the unfamiliar syntax — and when the syntax keeps fighting back, they abandon it for a language they know. Two consequences: the edit-check loop must be fast, and hand-writing what the DSL abstracts must never be easier than using the DSL, or agents will route around it.[^tax]
3. **Those numbers describe a model meeting the DSL cold.** Teaching it works, and the channel you teach through matters more than how much you write. The next three conclusions are the channels.
4. **Teach with the grammar plus worked examples, kept in the repo.** The best-evidenced intervention: show a model the grammar and a few real uses and it can write constructs it has never seen. On Racket specifically, in-context examples beat fine-tuning. A DSL that is thin sugar over a substrate the model already knows pays the least tax.[^teach]
5. **Error messages must explain, not just point.** Richer error text measurably raises agent success; a bare file:line adds nothing on its own; the right verbosity for an agent is higher than for a human. So: rule name, offending form quoted, candidates in scope, a did-you-mean — at a length you would never inflict on a human.[^errors]
6. **Don't teach through standing instructions.** Blanket guidance in context files (CLAUDE.md and kin) doesn't improve task success in general; the measured exception is documenting non-standard practice, which a DSL is. Anything a repo tool can enforce deterministically, enforce with the tool instead of restating in prose: checkers fail loudly, prose rots silently.[^prose]
7. **An abstraction without a name and a docstring is worse than no abstraction.** The docstring is load-bearing, not courtesy.[^naming]
8. **Keep the vocabulary tiny and human-curated.** Abstraction libraries rot as they grow, and abstractions authored by LLMs for themselves measure at zero benefit. So: the swarm proposes new constructs, a human ratifies them, unused ones get deleted.[^curation]
9. **Ship a command that prints what a macro expands to.** Treat it as part of the interface, not a debug tool. The one verified case of an agent successfully debugging through macros depended on being able to see the expansion.[^dump]
10. **Never reject code a model would reasonably write.** A grammar with arbitrary gaps is worse than no grammar — the model thrashes against rules it can't infer. Keep a plain-function API under the macros, directly usable; that escape valve is what lets the macros stay strict.[^complete]
11. **This is past the edge of the literature.** There is no research program on designing languages for LLM agents, and no published account of a coding agent working on a Racket codebase at all. Agent performance on a DSL is measurable (iteration counts, error rates), so build-it-or-not verdicts can eventually be data, not taste.[^gap]

[^prior]: [MultiPL-E](https://arxiv.org/abs/2208.08227) lists Racket as the only benchmarked language unranked on both GitHub share and TIOBE; The Stack holds 64GB of Python against ~0.5GB of Scheme/Racket (~128×, [MultiPL-T](https://arxiv.org/abs/2308.09895)); StarCoderBase-15B scores 30.6 on Python, 11.8 on Racket; frontier models still carry a ~15–20pp Lisp-family penalty (McEval). The "minority language within a minority language" line is from [Racket Discourse](https://racket.discourse.group/t/racket-and-llms/3527), whose opening complaint — an LLM unable to infer the bindings `define-tokens` generates — is exactly what a declaration macro does.

[^tax]: In an unfamiliar language, [92% of failed attempts are compile errors](https://arxiv.org/abs/2607.22807), not wrong algorithms; models [pick the same algorithm as their Python solution 80% of the time yet cannot express it](https://arxiv.org/abs/2605.15607) in an unseen language ("the implementation fidelity gap"). Escape behavior: frontier models embedded `python3 -c` in 18–27% of non-Python tasks; one practitioner watched Claude quietly migrate a Clojure app into bash until no Clojure was left.

[^teach]: [Grammar prompting](https://arxiv.org/abs/2305.19234) (NeurIPS 2023): GPT-4 GeoQuery 85→98; 63.3→90.8 on *held-out functions the model had never seen*. Put the grammar in the prompt and the model can wield a construct it has never met. [No Silver Bullet](https://arxiv.org/abs/2501.19085) (ICPC 2025; targets are literally R and Racket): worked in-context examples beat fine-tuning at scale — fine-tuning *degraded* a 33B model's Racket, 32.5→28.0. In the field: [DSL accuracy below 20% → ~85%](https://devblogs.microsoft.com/all-things-azure/ai-coding-agents-domain-specific-languages/) from in-repo examples plus compiler-validation loops. So: grammar sketch in the module docs, 3–5 worked examples in the repo.

[^errors]: [Krishnamurthi & Flatt](https://arxiv.org/abs/2606.01522) — Racket's own implementer, testing a Racket-hosted `#lang`: agent success rises monotonically with error verbosity, 24.6%→63.4% for one model, p<0.001; 97.9% of type-error fixes were also semantically correct. Location alone doesn't cut it: compilation feedback alone measured [+0.0pp](https://arxiv.org/abs/2502.19852), raw compiler messages [scored below a bare "your code is wrong"](https://arxiv.org/abs/2504.06939), and a precise-looking but under-specified diagnostic sends agents off satisfying the wrong constraint. Agents "do not tire, lose attention, or find length cognitively overwhelming" — hence more verbose than you'd write for a human. Budget 2–4 repair rounds; nobody reports gains past ~5.

[^prose]: [ETH Zurich on AGENTS.md](https://arxiv.org/abs/2602.11988): context files don't improve task success and cost +20% inference. Instructions get followed; repository *overviews* get ignored; the one place they pay is non-standard practice. [SlopCodeBench](https://arxiv.org/abs/2603.24755): quality prompts lower the intercept of code decay, not the slope — only mechanical checking bends the slope. [Operational rule](https://asdlc.io/practices/agents-md-spec/): if a tool in the repo can enforce it deterministically, don't restate it in prose.

[^naming]: [LILO](https://arxiv.org/abs/2310.19791)'s ablation: identical machine-compressed abstractions, minus their names and docstrings, cost −30.6pp — raw undocumented abstractions made the LLM *worse* than no abstractions. Independently, stripping meaningful identifiers costs up to 30pp.

[^curation]: LLM-authored skill libraries: ≈0 benefit. Human-curated: +16.6pp ([SkillsBench](https://arxiv.org/abs/2602.12670), replicated). A 202-entry library cost up to −21% via wrong-sibling selection; unbounded accumulation sinks below the no-library baseline; ≤3-unit bundles beat exhaustive ones. [Fowler & Joshi](https://martinfowler.com/articles/convo-llm-abstractions.html): LLMs apply stable abstractions well and undermine discovering them. The opposite endgame — [agents in a persistent Lisp loop growing their own macros](https://arxiv.org/abs/2506.10021) — is a conceptual framework, zero experiments.

[^dump]: [Teaching Claude to Be Lazy](https://www.parsonsmatt.org/2026/03/10/teaching_claude_to_be_lazy.html): Claude debugged Template Haskell codegen successfully because it could run `-ddump-splices` and read the expansion. The Racket analog (`raco expand`, dressed for the purpose) is therefore interface, not debug convenience.

[^complete]: [The alignment result](https://arxiv.org/abs/2606.21619): an incomplete grammar constraining generation cost up to −97% functional correctness — one missing optional-space rule took a model from 62.5% to 1.9%. A compile-time checker constrains nothing at generation time, but the lesson transfers: a rule that rejects what an agent reasonably writes produces thrash. The thin-DSL escape — write the functional core directly — is what keeps strictness affordable.

[^gap]: Checked: no papers at Onward!/SPLASH/PLDI (one keynote, unpublished); no controlled S-expression-vs-C-syntax study for LLMs; no published writeup of a coding agent working a Racket codebase (Racket Discourse and HN swept). Grain of salt: several load-bearing results here — Krishnamurthi & Flatt and the skill-library cluster included — are unrefereed 2026 preprints, and the one end-to-end test of the thin-checked-DSL hypothesis ([a purpose-built DSL learned wholly in-context, +40pp over Python](https://arxiv.org/abs/2512.23214)) is single-author and self-benchmarked.
