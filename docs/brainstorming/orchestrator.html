One PR, overnight

The orchestrator, played as a single night — the clearest demonstration, because whatever merges at 3am merged with zero trust in anyone being awake. Night is not a mode: the driver, the gates and the executor classes run the same by day, when a #human gate resolves in minutes instead of at breakfast. Olai is the orchestrator — the dashboard you dispatch from and wake up to — and kolu terminals effectuate everything behind the scenes. Olai works on top of kolu and never launches an agent itself: every process with a model in it is a kolu terminal, pi runs the bounded steps, and the fully bounded ones are code. One example PR, every moment, both sides of the glass — drawn in olai's own vocabulary (reef by day, aurora after dark).

00Executor classes — who acts, per kind of step

Coined for this design (nearest prior art: BPMN's service/script/user tasks; Löwy's volatility axis). Merge and retire — a for-loop, not a promise

The gate is a conjunction, and it holds. The merge is a host command, so it too goes through kolu: a one-shot terminal running gh pr merge, the night's only merge-capable token injected into that terminal's env at create — no agent ever saw it. The driver believes the merge when pr.state=merged arrives on the mirror, then kills every lane terminal, verified against the live list (the twelve-zombie rule), and removes the worktree only after.

03The architecture under the night

Three layers, each a function of the one below, none holding state of its own — and one rule about hands: the driver's only effectors are padi verbs and olai ops. The composition (which steps, what order, who runs each, which gate) is data on dag.olai, edited as an outline; the primitive verbs are code in a registry.
