## The findings, in plain words

Findings 1–3 are changes to the **kolu repository** (where `@kolu/surface`
lives), not to olai: each ships as a kolu PR, olai then updates its kolu pin
and *deletes* the workaround it was carrying — the same route the previous
sitting's three upstream fixes took (kolu #2158/#2159/#2160, installed by
olai #129). Findings 4–5 are olai's own.

**1. `@kolu/surface`'s client side should pass along "what changed" instead of throwing it away.** *(the headline — two debaters found it independently)*
olai's web app receives all its data by subscribing to server collections through `@kolu/surface` — kolu's surface framework, whose client half runs in the browser. When you edit a file, the server already sends an exact message: "these entries changed, these were removed." But the framework's client half (its Solid integration, `useCollection.ts`) digests that message into a big keyed dictionary and hands olai only the dictionary — the message itself is discarded. So olai wrote ~150 lines of workaround code that reverse-engineers what changed by comparing revision numbers, and the library copies the entire dictionary on every update. Measured on a 980-file vault, that copy is the single biggest cost when you type — bigger than the actual work. **Fix (in kolu):** hand the "what changed" message through, and update only the entries it names. **Then olai deletes its workaround, and typing in big vaults gets faster.**

**2. `@kolu/surface`'s server side should tell the app when the last reader of a file leaves.**
olai's server keeps file bodies in memory for pages people have open. The framework's server half (the same `@kolu/surface`, where collection handlers live) knows when a reader disconnects but never tells the app — so olai guesses with a "keep the 16 most recently opened" cache. That guess already caused a real bug two days before this debate (#229): a page went silent while someone was still reading it, and closed tabs kept being re-read. Olai now has a workaround (`holding.ts`). **Fix (in kolu):** an optional hook where the app is told "the last reader of this key is gone." **Then olai deletes the workaround.**

**3. Tiny kolu fix:** `@kolu/surface`'s unix-socket module has a function that checks "is this directory private and owned by us?" but doesn't export it, so olai maintains a copy of the same three checks in its lock code (the copy even says "if upstream ever exports it, delete me"). Export it; delete the copy.

**4. Three guard tests in olai** — small automated checks that keep a promise from silently breaking, a pattern the earlier debates established:
   - Only one place in the app may decide "is this string one of our addresses?" (to be added to the address-rework PR that's in flight right now, where it's cheapest).
   - Code-splitting `import()` calls must keep literal file names (the bundler needs them; today this rule is just a comment).
   - Until fix #2 ships, nothing outside the one workaround file may reach into the connection machinery it wraps.

**5. One cleanliness fix in olai:** the test suite imports web's *internal* files in sixteen places, while web's own package manifest claims "exports: nothing." Both statements can't be true. Fix: give web an official testing entry point (`./testlib`) — four packages already follow exactly this convention — and correct the manifest sentence. (The debate first proposed exporting just one file; that was refuted — it would fix one door of sixteen — and withdrawn.)

**6. No new packages.** For the third sitting in a row, arguing *for* extraction still produced zero new olai packages. Ideas killed on the way, with reasons on record: a "utilities" package (it's a grab-bag, not one concept), a chat-UI package (busy ≠ volatile — that's just the product being worked on), and unifying the two text-completion engines (their differences turned out to be deliberate, reviewed decisions, not accidental drift).

## Corrections the debate produced (this is why it's worth running)

- **The store package's "stillness" record is stale.** Earlier debates celebrated that `@olai/store` hadn't been edited at all; that's now false — eight commits touched it since Aug 13, including its public interface twice. This matters for the one decision still parked with you: when (if ever) to graduate store to its own repo. No debater proposed moving it; the clock just restarts.
- Each debater's sharpest correction hit their *own* earlier claim: grok retracted his misreading of the revision numbers, fable withdrew her only candidate's sizing after grok disproved its factual basis, and opencode's headline finding turned out to be already-fixed in the address-rework PR dispatched that same morning — exactly the escape clause he'd written into his own opening.
- Two written records (a survey claim and a roadmap stamp) were caught being wrong mid-debate — the same reason the guard tests above exist: comments and stamps rot; tests don't.

## The surface design for findings 1 and 2 (post-debate addendum)

After the debate closed, a separate design pass (Claude Fable, working in a
kolu worktree against framework HEAD, with the debate's guards as hard
constraints) produced the concrete API for the two kolu findings. The full
document with semantics and edge cases is
[surface-design-2026-08-19.md](surface-design-2026-08-19.md); the shape in
brief:

**Finding 1 — two faces that ship together as one socket:**
- *Internal fix, no API change:* `useCollectionDeltas` stops routing frames
  through the generic copy-the-whole-dictionary path and instead writes only
  the keys each frame names — O(size of the change) instead of two passes
  over the whole collection per keystroke. Snapshot/reconnect behavior,
  key rules, and the existing `{keys, byKey}` contract all preserved
  verbatim.
- *New face:* a `fold` member on the collection handle, only for
  collections that declare `deltas` (type-level — unspellable elsewhere):

  ```ts
  entries.fold({
    init: (all)          => …,  // full-set frame: first connect, reconnect, late arrival
    step: (acc, {upserts, removes}) => …,  // the wire's own delta frame, unchanged
  })
  ```

  **olai after:** `deriving.ts` is deleted whole — its `fold` call becomes
  two lines handing the frames straight to `@olai/format`'s existing
  `patch` (whose docstring already says it takes "Surface's
  collection-delta frame"). `rev` stays on the wire; `documents.tsx`'s
  heads tax disappears with zero olai code changes.

**Finding 2 — one optional member on the server's collection handler:**

  ```ts
  holders?: (key: K) => Effect.Effect<unknown, never, Scope.Scope>
  ```

  Runs in the per-reader stream's own scope, **before** the snapshot read
  (the load-bearing pull order, whose test moves upstream as the
  framework's own pin); disconnection releases it automatically; two
  readers are two holds; a failure inside a hold is unspellable
  (`never`) — a defect crashes that one subscription loudly rather than
  serving it unheld. Absent, byte-identical behavior to today.
  **olai after:** `holding.ts` and its test are deleted whole;
  `runtime.ts` says `holders: bodies.held` — the one line the workaround's
  own header always said it should be.

**Does kolu's own code benefit?** (asked after the design; full survey at
the end of [surface-design-2026-08-19.md](surface-design-2026-08-19.md).) Kolu-the-app: no — none of its surfaces declare the
`deltas` verb and none serve expensive per-key values. But two of kolu's
other production consumers do: **drishti** pays finding 1 twice — its
process table hand-rolled the exact same frame-reconstruction olai did
(copying the whole process map per poll tick, because the framework's
deltas hook isn't even exported from the barrel), and four more of its
collections silently pay the whole-dict copy — and **odu** is a real
finding-2 payer: its logs store keeps every log ever read resident and
followed for the run's lifetime because it can't hear "last reader gone."
The survey also forced one design amendment: export `useCollectionDeltas`
from the solid barrel, which is why drishti rebuilt it by hand. Kaval and
padi genuinely don't benefit (their expensive lifetimes are already
stream-scoped) — stated, not inflated.

Deliberately *not* designed, per the debate's guards: the client-side
`askers` refcount (separate axis), a `lastDelta` accessor (a second
spelling of `fold`), holds on collection-wide streams, and any touch of
`rev` or olai's `patch`. Shipping note: both changes are additive and
API-facing on `@kolu/surface`, so they carry kolu's drishti pair-PR gate
and odu-impact check — expected verdict "adoption opportunity," to be
confirmed by the mandated grep at implementation time.
