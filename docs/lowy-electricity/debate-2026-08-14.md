# Should the search-by-meaning code get walls around it? — the third three-AI debate

| | |
|---|---|
| **What was debated** | PR #165 teaches olai to find notes by meaning. To do that it starts a helper program (the "embedder"), keeps an index of vectors, merges two kinds of search results, and ships an AI model inside olai's build. The question: which parts of that should get a stable interface that hides messy internals — as a package, as an internal seam, or as a contribution to kolu — and which parts should be left exactly as written? |
| **The lens** | Juval Löwy's *Righting Software*, chapter 2: put a wall around things that change often, the way a power outlet hides the power plant from your toaster. Four concrete tests decide whether a wall is deserved. Conclusions from the two earlier debates were off-limits to reargue. |

| **Result** | One small new package agreed by all three; two must-fix items attached to the PR before it merges; one build-script cleanup; two automated guard tests; a long list of rejected ideas — each rejected by its own proposer; one experiment left for the human |

## What happened, in plain words

Usually a debate like this hunts for code that *should* have a wall and
doesn't. This time the surprise was the opposite: **the PR's author had
already built the most important wall.** The search code asks for
"nearest neighbours" through one small interface, and the messy details —
which AI model, how vectors are stored, how the helper program is managed —
all hide behind it. All three debaters, working separately, concluded the
same thing: don't add a big new structure here; protect the good design that
already exists.

The debate also had a culture worth noting: **every debater shot down at
least one of their own ideas, in public, with the reason written down.**
fable proposed and killed the very package her role invited her to argue
for. opencode killed both of his named candidates. grok proposed the
strongest possible versions of "move it into kolu," then showed why each one
fails, and separately took back two claims from his first round after
re-reading the code. And the one real disagreement of the debate dissolved
in the final round, when opencode conceded the point after fable's argument
landed.

## What was agreed (waiting on your go-ahead)

1. **Build one small new package: `@olai/child`.** olai now starts helper
   programs in three different places — the chat agent, the search embedder,
   and the startup check that briefly runs `kolu` to see whether Kolu
   terminals are available on this machine (that check lives upstream in
   `@kolu/detect`) — and each place hand-writes the same fragile plumbing: what happens if the program can't start? who reads its error
   output? how do you ask it to shut down politely before force-killing it?
   The third copy of this plumbing is actually *wrong* today: if the
   embedder's path is bad, you get a misleading "didn't answer within 30
   seconds" instead of "this file couldn't run." The new package holds
   exactly that shared plumbing — and, just as important, the debaters
   agreed on a list of things it must **never** absorb (health checks,
   communication protocols, restart rules), because bolting those on would
   recreate the bloated do-everything package a previous debate already
   rejected. Three small fixes come along for free, including giving the
   chat agent a polite shutdown (today it's killed abruptly even on a
   normal exit).

2. **Fix #1 that the PR's merge must carry: teach search's two halves to
   share one vocabulary.** The word `meaning` (the label on a
   found-by-meaning result) should be declared in the one shared place where
   all search words now live — a place that was only built last week, after
   this PR was written. The PR's own duplicate declaration gets deleted.

3. **Fix #2 that the PR's merge must carry: don't feed raw query text to
   the AI model.** The PR was written before last week's search-operator
   feature landed, so merged as-is, three things would go wrong: a mistyped
   query like `is:blocked` would come back with *plausible-looking results
   and no error* — exactly the kind of silent lie the operator feature just
   eliminated; operator words like `is:done` would be sent to the AI model
   as if they were ordinary prose; and meaning-based results would ignore
   filters like `file:` or `is:done` that exact results respect. The fix:
   parse the query once, and hand the AI model only the actual words.

4. **Merge two near-identical build scripts into one.** The script that
   wires up the embedder is a copy-paste of the script that wires up the
   chat agent — the file even admits it in a comment. One shared script
   (plus one shared nix helper) replaces both. The debaters disagreed only
   about what *category* of improvement this is, not about doing it.

5. **Two automated guard tests** (tests that fail if a rule is broken, so
   the rule can't silently rot): only the search-recall code may read the
   embedder's environment variables, and only it may know where its cache
   file lives.

6. **A "leave it alone" list.** Just as valuable as the changes: the parts
   of the PR that future cleanup work must *not* touch, because they're
   right as written — the small search interface, the cache living in the
   user's cache directory (never in their notes), the rule that a missing
   index is not an error, exact matches always ranking first, and the
   simple linear scan that's fast enough at this scale.

## Ideas proposed and rejected — each by its own advocate

- A whole `@olai/recall` search package — rejected because the useful wall
  already exists and is one interface wide; a package would add ceremony
  around nothing.
- Moving the subprocess plumbing or the embedding machinery **into kolu** —
  rejected in every variant: too specific to olai, too thin to be worth a
  package, or it would pollute an existing well-designed kolu package.
- Two internal-seam candidates (a query/document type marker; a size
  constant) — rejected as ordinary code, not "frequently changing things
  needing a wall."
- Folding the vector index into `@olai/store` — rejected because that
  package has deliberately been left untouched for weeks to prove it's
  stable, and this would reset the clock.

## Three things left for you

1. **A one-command experiment nobody could run** (the PR's checkout was
   read-only for the debaters): if you force-kill olai (`kill -9`), does
   the chat agent process die with it, or live on as a ~589 MB orphan?
   Start olai, open the chat panel, `kill -9` olai's process, then check
   `ps` for the agent. If it dies, the cleanup code stays where it is (as
   agreed). If it survives, the cleanup code should move into the new
   package — and the orphan becomes the best argument for it.
2. **A small housekeeping call**: `@kolu/detect` — the package behind that
   is-kolu-available startup check — contains fifteen lines duplicating the
   "program couldn't start" handling. Options: export it from kolu now,
   wait until `@olai/child` has proven itself and let kolu use that, or
   just leave the duplication. (Nothing gets filed on kolu without your
   say-so.)
3. **PR #165's merge** now carries items 2 and 3 above as required fixes.

## Why this format keeps earning its keep

Pointing the debate at a single PR made it sharper, not smaller: it
protected the PR's own best decisions from well-meaning future cleanup,
caught two bugs that would only appear at merge time (because other work
landed after the PR was written), and turned the one genuine disagreement
into a cheap experiment instead of a stalemate. Three debates in a row,
the discipline has held: argue hard for your assigned angle, but let the
tests — not the role — decide, and put your own retractions on the record.
