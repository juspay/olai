## The sitting in one sentence

Four bugs in one afternoon, and not one needed a new wall: each was a question with one true answer being derived twice, and the fix each time is tightening the face of a package the repo already has.

## The findings, in plain words

**1. MEANING — one place answers "what does this property value name?"** *(home: `@olai/format`; kills the whole chip-doors bug family — roadmap: `meaning-socket`)*
Today the validator resolves a declared value through the vocabulary (`typing.ts`), while the display re-guesses the same question from the value's shape (`door.ts` — written before #395, never reads the declarations). They disagree three ways: every `brief` chip on the board is dead (the two sides assume different path bases), ref chips show raw ids instead of titles, and a declared `doc` teaches the display nothing. Fix: one resolution module beside the validator, and the browser receives its *answers* — a "doors table" shipped with each page exactly the way resolved names already are — never the vocabulary itself. That keeps #395's deliberate decision (declarations stay off the wire) intact. One amendment ruled along the way: **whether a path key resolves from the vault root or beside the writing file becomes a declared fact on the key's own row**, so the two premises can never fight in code again. Notes (the `doc` field in markdown) keep beside-the-writer forever — that's the markdown premise's only home.

**2. VERDICT — the validator's judgement becomes shaped data, not a log.** *(home: `@olai/format`; kills the healthy-write freeze and the banner flood; makes the cold-boot policy writable — roadmap: `verdict-shape`)*
Today a validation result is a flat list of rows. Every consumer re-derives what it needs from that log and gets it wrong differently: the write gate reduces it to one boolean (so one broken file froze writes to every healthy file, and the refusal couldn't name the culprit), the banner has nothing but the rows (so 135 of them flooded every page), and cold boot applies a blanket "any error refuses the set" (so two long-dangling `see` edges served *nothing*, chat included). Fix: the verdict carries its own structure — which files each finding implicates, whether a given write is admissible (`admits(files)` names the blocker), a bounded per-file summary for any surface to draw, and a severity tier for set-level rules (the per-line tier already exists — a parse-broken file already degrades gracefully; set rules never got their half). The freeze and the flood become *unspellable through the socket*. Cold boot is **reduced, not abolished**: which error classes brick a boot becomes one ruled line of data — a policy call that stays the human's, deliberately not smuggled into architecture.

**3. VINTAGE — no read without an age.** *(home: `@olai/store`; kills the silent-staleness class — roadmap: `vintage-reads`)*
The day's worst incident: a git rebase replaced files on disk, the watcher missed it, and the server served week-old truth for 30+ minutes with *empty* errors — nothing was "wrong," the set was just old, and no cell anywhere carries "how current is this answer." The debate found the exact mechanism: a probe that sees identical stamps settles quietly and publishes nothing, so a missed rebase is *unrepresentable as an error* by design. Fix, with the debate's hardest-won shape constraint (grok's red line, adopted by all three seats): store's read answer carries a **Vintage**, a consumer cannot obtain the set without it, and the vintage's verification path is independent of the publish loop — so a wedged loop yields a *visibly stale* vintage, never a fresh-looking lie. Callers state a freshness *class* (cheap for UI redraws, verified for a tool result an agent will act on), never the means — otherwise today's `resync` folklore just gets rehired one floor up. The stale-but-healthy-looking read becomes unrepresentable; what survives is a *named* staleness, which is an honest failure and a different bug.

**4. Zero new packages, zero kolu changes.** fable's opening package (`@olai/custody`) was withdrawn once the debate split it along a design sentence already in the tree ("there is not one olai type in store") — its judgement half folded into the Verdict, its transport half into the Vintage. grok ran two kolu candidates and killed both himself: last-good/health as a framework verb fails "functional but not domain-functional" (kolu's other consumers have no last-good axis; policy stays app-side), and the directory-pulse unification failed the same wall. Four sittings of arguing *for* extraction; still zero new packages — the bar working as designed.

**5. Guards, correctly demoted to guards:** the banner clamps (on top of the Verdict's summary — a knob is not a receptacle); the MCP read joins the vintage; the errors-cell join stays pinned for the family it actually covers (last-good-with-rows, unreadable-directory); no-successful-read-without-vintage pinned as a type-level test.

## Corrections the debate produced (why it's worth running)

- **grok retracted his own headline** — "the errors cell is already the receptacle; the bugs are unplugged lamps" — after fable showed the cell was *empty during* the staleness: validity and currency are different facts, and there was no outlet on the wall for the second. His concession found the `store.ts:405` mechanism that proves it.
- **fable withdrew the sitting's only package candidate** (the honest fallback her opening had pre-reserved), retracted two exhibits (a stale watcher-bug citation — the bun 1.4.0 pin had already closed it; a wrong claim about chat's transport dying), and accepted that her original "freshness field" was, in grok's words, "a clock on the lamp" until the verify became a door a dead loop cannot hold shut.
- **opencode downgraded his own probe-math certainty** ("no probe published at all — the loop, not the join") to what the evidence proves: silence, cause undiagnosed — while showing every finding independent of the diagnosis.
