The file format

Each outline is a .olai file: one JSON object per line, one node per line. Nodes have stable ids and parent pointers, so line-based git merges are safe and moving a subtree changes one field. See the format spec.

{"id":"kitchen","ord":"a","title":"Kitchen renovation"}
{"id":"demo","parent":"kitchen","ord":"a0",
 "title":"Demolition","done":"2026-08-09T14:02:11-04:00"}
{"id":"order","parent":"kitchen","ord":"a1",
 "title":"Order the new cabinets #blocking",
 "doing":true,"date":"2026-08-07","after":["demo"],
 "doc":"cabinets.md",
 "desc":"Measure twice — the corner unit is the risky one."}

The outline above, as stored on disk.

$ git diff
-{"id":"order","parent":"kitchen","ord":"a1", … }
+{"id":"order","parent":"now","ord":"a1", … }

Moving a subtree changes the parent field. Children reference order by id and are unaffected.

Markdown documents

Notes are Markdown. Longer content goes in .md files, referenced from the outline by the doc field. Each document gets its own page and appears in the sidebar's file tree — and the page edits: Edit turns the rendered body into its source, Save is one operation through the same layer the agent's write_document uses, and a file that changed on disk while you were typing refuses the save in plain words instead of being silently overwritten, in either direction. New documents come from the sidebar's path box, or from a bare calendar day — pressing one creates that day's note where your vault already keeps them.

A .html file in the directory — a saved article, a report a build wrote, a dashboard something exported — is listed and previewed the same way, and is read rather than edited. The page works: its own JavaScript runs, its own stylesheet paints, and a link to another file of your vault opens that file's own page in olai — the address, the heading and the sidebar entry a click in the directory would have given you. It runs in a sandboxed frame whose origin is nobody's, so nothing in there can reach the app around it — no cookies, no storage, no reading the page it sits in — and every fetch it makes is answered by one place: your own directory, on this server. A remote image, an inlined one, a form posting somewhere, or an address climbing out of the vault is refused before the request is made, so a saved page that merely carries somebody else's addresses reaches nobody. (A page that goes out of its way to leave — a script navigating its own frame — can, once; no browser gives a page's embedder a way to stop that. olai brings the frame back when a document does not identify itself as one of your own files, which bounds how far a page can drag it — but a page that runs code can claim to be one of yours, so that is a limit on looping and not a proof of where the frame is.) One extra script rides along, olai's own, doing two jobs: reporting how tall the page is, so the frame is the height of what it holds instead of a fixed slice of the screen, and noticing when you click a link at another file of your vault, so that opens as a page here rather than inside the frame. It hands the address out and never navigates; olai looks it up in the files it is serving before it goes anywhere.

Task status

A node can carry one of three marks: done, doing, or todo. A node with no mark is not a task and gets no checkbox.

completed taskdone
task in progressdoing
task not startedtodo
●a noteno mark
●read this book 1/3
chapter one
the streams chapter
exercises

1/3 is a display annotation. A parent's status is never computed from its children.

⌘⇧Enter, on the row

● no mark → todo → doing → ● no mark

done is not a stop on the ring.

Two keys write all three. ⌘+Enter finishes something, and takes that back: done is the mark with an instant on it, which is what puts the work on that day’s page. ⌘+⇧+Enter walks the mark on, one step round the answers a person gives about work they have not finished. The last stop is an answer rather than a gap — a node carrying no mark is not an unfinished one, and walking to it is how you say a row was never a task.

Finishing something is a thing you mean, not a thing to do on the way past, so nothing stamps a completion while you are walking round — and the walk will not take finished work backwards. Press it on a finished row and the write is refused, in the same words an agent gets: nothing should decide on your behalf that finished work is not finished. ⌘Enter takes the done off, and the walk carries on from there.

A done on a parent is a claim about the whole branch, because hiding what is finished takes the subtree with the row. So the claim has to be true: ticking off a branch that still holds an unfinished task is refused, naming them — and filing new work under a branch somebody called finished last week takes that mark back off instead of turning you away. Nobody’s note goes quietly missing under a sentence that has gone stale.

overdue(n) ⇔ n carries todo or doing
             ∧ day(n.date) < today

Derived when the page is drawn, stored nowhere, and spelled once — the days above now on the spine and the tone of every date badge are the same predicate. day() is the first ten characters and the comparison is plain string order: dates are text.

Overdue is a definition, not a flag. Nobody sets it and nothing stores it. done extinguishes it by construction — finished work is late at nothing — and a date with no mark is an occurrence: a delivery, a birthday, a ferry. It draws no checkbox, its pill never takes the attention tone, and when its day passes it simply leaves. A day going by is not a failure of a bullet.

One spine of time, and now is a place on it. Every day the directory owes something on is a dot on one continuous line, oldest first. Above the today mark is what SLIPPED — the one answer no day page can give, because a slipped task is on a day nobody visits. The mark itself is today, drawn whether or not anything is due on it. Below it the future recedes: the line's ink fades, whole entries fade with it, and the next seven days that have anything are the days you see — each one a link to its own page, and days with nothing do not appear.

Days say how far away they FEEL. Mon, Aug 24 and in 6 days; Yesterday, in the attention tone, over a row whose pill reads 1 day late. Dates in the file are ten characters and always will be — but a page that made you subtract them to work out whether something was urgent was making you do the one job it exists for. The silences between listed days are content too: a wait long enough to notice says how long it was, and the room every wait takes grows with it, so a fifty-day gap reads as longer than a two-day one without costing a screen.

A task nobody dated is absent entirely: it has no when to be late against, and inventing one is what this format refuses to do. So is one you moved to the Trash — putting something away takes it off your days and off this page, which is the whole of what putting it away means. An empty agenda says Nothing is due., draws no line at all and offers nothing to press — every row on it lives somewhere else, and that is where it is changed.

A date is set on the row. Press the date beside a title and the picker opens in place under it; a row with no date has no pill to press, so its way in is the ••• menu — Set date…, or Change date… on a row that has one. What is written is the ten characters you picked, never a timestamp this app invented on the way, because the control is the browser’s own <input type="date"> and a date is text.

Empty the box and the button becomes Clear date — the ••• menu's own verb, and the same write.

A dated node can come back. Give it a repeat rule and completing it does two things: it stamps the node done, as always, and it captures the next occurrence — a fresh node on the day the rule names, same title, same note, same rule, marked todo, placed right below the one you finished. The old row keeps its own date and the instant it was finished, so eleven weeks of bins are eleven rows on eleven days rather than one row whose date kept moving and could prove none of them.

The grammar is four shapes and it is spelled in the file. every day, every week on monday, every month, every year — no intervals, no end dates, no counts, no cron. A .olai is read by people, and 0 0 * * 1 says the same thing in a dialect that has to be learned. The picker is a list of exactly those rules, because there is nothing to type that is not on it.

The rule moves to the occurrence it makes, which is what a recurrence with one live head means — so undoing a completion leaves the new occurrence standing (it is still owed) and ticking the old row again makes no second one. And the next date counts from the row's own day, never from today: finish a weekly chore three weeks late and the next one is the week after the one you just did. Nothing here quietly skips a backlog forward.

Everywhere else it is simply a dated node — on this page, on its day, in the calendar's dots, overdue when it goes past. An agent writes the same rule with set_repeat and gets the same occurrence out of set_done, because the deciding happens in one place under both faces.

Put the bins out2026-08-17
Put the bins out2026-08-24↻ every week on monday

One completion, two rows: what happened on Monday the 17th, and what is owed on Monday the 24th.

And the directory says so before you open it. Overdue is the one answer no day page can give — and a page nobody opens cannot give it either. So the Agenda entry in the directory carries the news: work that has slipped puts it in the app's alarm, with the count of what is late on it; work that is merely on today wears the same chip in the quiet face a date badge takes when it is not late. Neither, and it is the entry it always was — a door, not news.

When both are true the alarm wins the row whole and prints the late number alone: one claim per readout, and the number that decides whether to press is that one. The other is still spoken — the entry's own label reads Agenda — 3 overdue, 1 on today — and shown in full one click away. Collapse the column and the same alarm rides the rail as a dot; on a phone it is inside the same sheet, behind the same burger.

It is the page's own count, not a second opinion. The client makes exactly one reading of what is owed and both things that show it read that: the page lists the rows, the entry counts them. A number beside the word can never disagree with the rows behind it, and it moves with the files — tick a late task off in the tree and the alarm goes down without a reload.

Finding, and filtering in place

One query language, four doors: the box in the header, the ⌘K palette, an agent’s search_nodes, and the filter that narrows the page in front of you. The first three list what they found; the fourth takes rows away and leaves the rest standing where they live. The two that list also find documents: a .md or a saved page is a hit of its own, looked for in four places that line up with a node’s one for one — what it is called, its path, the tags in its prose, and the prose itself. Both kinds come back in one ranked list, so a document whose title holds the word outranks a node that only mentions it in a note. What a document does not have, it does not pretend to: an operator over a field it lacks — is:done, has:date — selects none of them.

/house.olai?q=%23home+OR+alcove
●kitchen remodel #home
●order the new cabinets
…measure the alcove before ordering.
●install the cabinets
pick the hinges #home

A match is drawn with the ancestors that lead to it, so a bare title still says what it is about — and every row says WHICH it is. The query's words are lit where they sit; a row drawn only as the ancestry leading somewhere is dim; and a row found behind its ¶ draws one clamped line of the note around the hit, since its title holds nothing you typed. The collapse you left on install is suspended while the filter is on, and comes back when it clears.

Words are substrings; operators say what a node is. is:done / is:doing / is:todo read the mark a node stores — a parent whose children are all ticked is not is:done unless somebody ticked it. has:desc, has:date, has:see ask what the record carries. Two are derived rather than read off the record: is:blocked is a node waiting, because something it must come after is a task nobody has finished — the same reading that dims the row and writes its blocked by line — and is:mirrored is a node drawn somewhere else as well, because you put it on a list. date:2026-08 takes a day, a month, a year or a range (date:2026-08-01..2026-08-14), reading the same two dates the journal reads — or it takes the words: date:yesterday, date:last-week, date:this-month, counted from the day you ask on and composing with a range like any other value (date:last-week..). prop:pr and prop:agent=claude-opus ask after a property you put on a node yourself — by key, or by key and value. - in front of any of them takes it back out.

And two ask what olai did, rather than what you said. When olai captures a node it stamps the instant; when it writes to one afterwards it re-stamps another. Both are put on by the tool and by no verb you can type — so a node has a created from the moment olai made it, a changed only once something has been written to it since, and a node older than the stamps has neither. created: and changed: read those, and they take every value date: takes — so changed:today is what you touched today, created:last-week is what arrived, and -changed:last-month is what has gone quiet. They are not the same question as date:: one node can be scheduled for the 10th, captured on the 1st and last written this morning. And nothing invents a past for the ones that have none — no span reaches an unstamped node, however wide, because a ledger does not make up a past it did not see. What finds them is the negation, -has:created; what says when they were really written is git log.

Quote a phrase, or say OR. "kitchen remodel" is one substring where two words are two, so quoting is how the order of the words gets into a query — and a quoted token is text rather than an operator, which is the only way to search for the note that explains what is:done means. walnut OR birch is either one; it joins the tokens on each side of it and binds tighter than the space between two tokens, so #home kitchen OR bathroom is #home and one of the other two rather than every bathroom in the directory. In capitals, because or is a word people write.

An operator it does not know is refused, not guessed at. is:open answers with the values is: takes rather than quietly searching for that text and finding nothing, and a date no calendar could hold — date:2026-13 — is refused on the same terms rather than answered with an empty page. The refusal quotes what you typed, case and all. A colon anywhere else — TODO:, a URL — is just a word.

Clicking a #tag filters by it, and the filter lives in the address (?q=), so a narrowed page is a link you can send and the back button works. Trashed nodes stay out of every reading until a query says is:trashed.

The box is above every page that draws nodes — an outline, a zoomed node, a day, the agenda, the Trash — and it means the same thing on each: what did not match goes, what did stays where it lives. A day and the agenda keep no ancestors because their rows already carry them; the Trash searches within what was put away, since that page is the trash and the box is asking about the rows in front of you. The one page with no filter is a document: it is prose, and this grammar selects nodes.

The same words reach an agent unchanged, with a scope a person gets from the page they are on: search_nodes takes under (a node and everything beneath it) and file. One matcher, four callers — so is:done cannot come to mean two things.

Keyboard editing

Click a title to edit it in place. Each edit is one operation through the same layer the agent uses, and each lands as a git commit.

Enter mid-linesplit the row in two, there
Backspace at the startjoin this row onto the one above
Tab / Shift+Tabindent, or out again
Alt+Shift+↑/↓move a row among its siblings
⌘+Ztake back your last edit here
⌘+Entertick it off, or take that back
⌘+⇧+Enterwalk the mark on: to do, then doing, then none
⌘+⇧+Dduplicate the row, and everything under it
⌘+⇧+Mmove it under a node you search for, anywhere
Shift+Enterwrite the note under it
Escdrop what you were typing
⌘+⇧+Zput that edit back
⌘+⇧+Ppin this page to the sidebar, or unpin it

Splitting and merging are one operation each rather than a sequence the browser performs, which is what makes them safe: a merge joins two titles, joins their notes, hands the row above everything that hung under the row you were in, and puts that record in the Trash with its id — all of it, or none of it. Whatever the merged row carried that a single node cannot carry twice — its mark, its date, what it waited on — goes to the Trash with the record, and a line under the row says so rather than letting you find out later. Splitting is the same trade the other way: the half that comes off is a new row, so it starts as a bullet, and everything that described the row you were in stays with it.

Undo is an inverse rather than a restore: it replays the edit that reverses yours, judged against the outline as it is now — so it never takes back what an agent or another tab did in the meantime, and one that no longer fits says why.

Drag a bullet and the row goes with everything under it. A line shows where it would land before you let go — and it moves sideways as well as up and down, because a gap between two rows reads the same whether you are joining that level or becoming the last child of the row above it. Where the line starts is the answer. Hold a row near the top or bottom of the window and the page comes to you; with a finger, hold the bullet until the row lifts and then it follows your thumb — until that moment nothing is claimed, so a flick still scrolls the page.

Everything works on more than one row too: ⌘-click a title to add it to the pick, Shift-click to take everything between, Shift+↑/↓ to start picking from a caret, ⌘+A to widen, or drag across the rows. That last one has a rule worth knowing, because press-and-pull already means something: where the pull begins decides. Start on the words and it is the browser’s own text selection, unchanged. Start on the outline’s empty space — the rail beside an indented branch, the page below the last row — and it picks every row it passes over. Then the keys are the keys you already know, several times over — Tab, Shift+Tab, Alt+Shift+↑/↓, ⌘+Enter, or a drag by any of their bullets. A pick and a caret are never both live, which is what lets them share those keys. Each is the single-row operation repeated, in the order that produces the shape you asked for, so an agent asked to do the same thing makes the same calls — and ⌘+Z walks it back a row at a time.

Three characters open a short list under the line you are typing. ! takes a day in words — tomorrow, next fri, aug 20 — and every row says the date it means, so nobody has to press Enter to find out which Friday. # and @ complete over the tags this set already uses, two namespaces rather than two spellings of one. (( searches the whole directory — the same search ⌘K runs — and the node you pick is placed here as a mirror. Walk any of them with the arrows, take one with Enter, dismiss with Esc. The first and the last are the same two operations an agent has, set_date and add_mirror; the middle one is just text, because a tag lives in the title.

Not everything has a key. Hover a row and the ••• in the gutter carries the rest — on a phone there is no room for one, so hold a finger on the row (anywhere but the bullet, which is the handle) and the same menu opens: the three marks and clearing one, setting, changing or clearing a date — the same picker the row’s own pill opens — setting, changing or stopping a repeat rule on a dated row, from the picker its own ↻ pill opens — retiring one placement of a mirrored node, duplicating a row and everything under it — the copy lands as the sibling below with ids of its own, so it is a second thing rather than a second view of the first, and ⌘+⇧+D is the same verb from the keyboard — moving the row under a node you search for, anywhere in the directory — the panel lists what it finds and says, before you press Enter, which of them cannot take it: another outline (every outline is an independent tree), the row’s own subtree, the Trash, or the parent it already has; ⌘+⇧+M is that one from the keyboard — moving a subtree to the Trash — it asks first, and says how many rows go with it — and copying the subtree as tab-indented plain text. Those go on the same undo stack, so ⌘Z takes a menu edit back too — all but the retire, which has no ⌘Z at all, and (( is how that line comes back instead. Nothing you put away is deleted by putting it away: the Trash keeps the subtree whole, ids and all — on disk it is _olai/Trash.olai, the one trash for the served directory, which is why nothing that pointed at it breaks — and the sidebar’s Trash is where you read it, with Put back on the rows that were put away, restoring each where it came from. A row you put away leaves every other page with it — off its day, out of the calendar’s dots, off the agenda even if it was late — because putting something away is saying you are done looking at it; the Trash is the one page that shows it, and is:trashed is how you go looking on purpose. (The titles above them are the signposts the trash wrote to remember which outline they left and where they hung; they are not rows anybody put away, so they have nothing to put back.) It is a place to look and to restore from rather than one to edit. Every one of those is the same operation an agent would perform, which is a rule olai holds itself to: both faces can do the same things to a directory.

And the Trash can be emptied — the one thing in olai that permanently deletes. Empty trash sits beside the heading on that page and takes every record in the trash, subtrees and signposts alike. It asks first, and the question says how many rows go — counted over what the trash holds rather than over what the page happens to be drawing, so narrowing the Trash with the filter box does not narrow what you are agreeing to — and it says outright that nothing in olai puts them back and that what survives is whatever git has already recorded. It is refused while anything outside the Trash still points into it, since ids come along when a subtree is put away and deleting those records would leave live rows naming nothing; the refusal names each of them. An empty Trash does not offer the verb at all. There is still no delete key: this one names no node, reaches no live outline, and can only take rows you already put away and can still see. And if something is put away between the moment you read that sentence and the moment you press it, the write is refused naming both counts rather than taking the newcomer with it. empty_trash is the same operation for an agent.

A node can point at other nodes, and that is writable from either end now. The menu’s Link to a node… and Wait for a node… each open a panel under the row: what this node says now, with an × on each, and a box that searches the whole directory — the same search ⌘K runs. A zoomed node has the two as controls under its own lines, because a heading has no ••• to hang them off. They are set_see and set_after, the same two an agent has, and a dependency that would close a loop is refused in the ops layer’s own words, naming the loop: nothing is greyed out first, because the reason is worth more than the absence. A node’s page draws what it declares beside what is in its way — the second is derived, and only the first is yours to change.

And a zoomed node says what points back at it. A Referenced by … line under the heading, shut until you open it, holding what sees this node and what mentions it by its @id — the same handle the chat’s @ writes into a sentence. Every reference in an outline points one way on disk, so this is the reverse read out of the same live view the page is drawn from: write @herbs in a note in another file and the herb bed’s page gains a row while you are looking at it. A second placement of a node is not a reference — a mirror is a view of the thing rather than a remark about it — and neither is an ordering edge, which the page already draws both ways.

So does a document. A Referred to by … line under its body, on the same terms: the node that attaches it with doc, the note that links it, and the other document whose prose does. It names the record rather than the file the record sits in — “install the cabinets”, not “house.olai” — because a link is always some record’s. A link written at one of the document’s own headings counts: whoever wrote brief.md#scope is talking about brief.md.

And the sidebar starts files as well as listing them. + New outline and + New document ask for a path, relative and with its own extension, judged by exactly the rules an agent’s create_outline and create_document are judged by — a path that exists, or climbs out of the directory, comes back as that operation’s own sentence rather than a browser’s guess at one.

The ⌘+K palette is the same verbs without the mouse. Zoomed into a node, it lists what that node can take — mark it, clear its mark or its date, move it to the Trash, asking the same question first — which is the one place the ••• could not reach, since it hangs off a row and a zoom is a page. A refusal is shown in the palette rather than swallowed by it, and ⌘Z takes any of it back.

And what you keep coming back to gets a shelf. A row’s ••• offers Pin to sidebar; ⌘+⇧+P pins the page you are on — including the query you narrowed it with, so a saved search is a pin rather than a fourth kind of thing — and the pins sit in the directory column between the month and the files, one click from wherever you are. Drag to reorder, × to take one off.

A saved search gets a name where the thought arrives. Narrow a page and press ⌘+⇧+P and olai asks what to call it, in the palette's own box: type a name and Enter, or Enter alone to keep it unnamed. A query is the one part of an address nothing in your directory can name — three narrowings of the agenda are three rows called Agenda — which is why that press asks and no other one does. The name is not a new kind of thing either: the row's title becomes [What is late](/agenda?q=is%3Atodo), the markdown link you would have typed yourself, and the ✎ on a shelf row changes it later — or takes it off, leaving a door drawn by whatever it points at.

The shelf is a file, and that is the point: a Pins.olai in the directory — minted at _olai/Pins.olai, or wherever you already keep one — with one ordinary node per pin, whose title is the address it opens. Nothing is stored in the browser, nothing new was added to the format, and an agent keeps the shelf with the tools it already has — add_node pins, move_node reorders, set_title renames, trash_node unpins. Nothing stores a copy of a node’s name either, so renaming one anywhere renames it on the shelf — and opening Pins.olai shows the same faces the shelf does, because a title that is nothing but an address is drawn as the page it names wherever it is written. What the editor opens is the address itself.

And a thought that arrives while you are reading something else does not cost you your place. ⌘+K, +, the line, Enter: it becomes a node in the directory’s inbox — an Inbox.olai, created the first time you capture — while your page, your scroll and the address stay exactly where they were, and the box empties for the next line.

Preferences, and the palettes

The same rows, in two of the palettes. A palette is eleven colours with a name; picking one writes data-theme on <html>, and the stored pick lands there before the first paint, so a reload never flashes the wrong one.

Eight of the seventeen are dark grounds. There is no system chip and no auto: the operating system’s preference is not consulted at all, because two ways to be dark are two answers that can disagree — with each other, and with the reader who already said what they wanted. Agents, over ACP

The chat panel connects to any agent that speaks ACP. Claude Code is bundled as the default; set OLAI_ACP_AGENT to use a different agent CLI. Olai hands an agent no filesystem — a fixed set of tools that name nodes and whole documents, never bytes — so every write it asks olai for is validated before it lands. What a coding assistant brings with it is its own: it edits files on the authority it already has in a terminal, and olai neither grants that nor pretends it away. It shows it.

Files go in by paste, by drag, or by the picker: drag a screenshot, a PDF or a text file onto the conversation — several at once if you like — and the panel lights up the area that will take it while you are still holding it. The agent is handed the path to read, not the bytes. They live in a temporary directory of that conversation's own, never under the directory being served, and go away with it. A picture shows itself; a document shows its name and size. Anything olai will not take is refused where you dropped it, by name.

A tool call is one folded line, and what the call changed is not folded away. There are two kinds of change and the panel draws them differently, because they are different things. A write through olai’s node tools shows what changed about the node, in the same words the commit panel uses for the same edit — marked done, note rewritten, moved — and the outline it landed in. A file the agent rewrote with its own tools shows a diff: the path, how many lines came and went, and the change itself, with the unchanged stretches collapsed so the first thing you read is what moved. It is trimmed to a few rows and expands where it stands. An outline never gets a text diff — one line per node means a text diff of one is a single enormous line with everything on it changing at once.

An agent can send agents of its own, and their work is drawn as theirs. A call a subagent made sits indented behind a rail, under the call that spawned it; the ordinary column stays the main agent’s. Where a stretch of one agent’s work begins, the lane says whose it is — the description that agent was sent with — and then stops repeating itself, so a subagent that reads ten files gets one name and ten rows. The name comes back whenever the thread is picked up again, which is what makes two agents running at once readable: their calls interleave, and each stretch says which of them it was. A question a subagent stops to ask — permission for a tool, or options to pick from — is a row like its calls, so the form is drawn in that agent’s lane and the lane names who is asking wherever it sits: you are sent to a blocked form from the composer and the header rather than scrolling down to it, so there is no row above you have read. A turn that spawned nobody looks exactly as it always did.

A row can hand the agent the node it stands for. Ask agent in the row menu arms the box with that node — a chip above what you type, removable until you send — and the turn is then about that node rather than about whatever your sentence re-describes. What the agent is handed is the node’s id, the same handle its tools take, with the title and where it lives; not a copy of its contents, which would stop being true the moment anything wrote. It points back, too: an id in the conversation is pressable, and pressing one brings that row onto the page. Nothing had to be invented for that — an agent already writes ids in backticks, and one becomes pressable exactly when your outlines declare it.

A tool server that does not arrive is named too. If this machine has an MCP server the conversation was meant to be handed — kolu’s terminals, when kolu is running here — and it would not answer, the panel says so under its header, with the reason the server itself gave and the file that was probed. A session quietly short of its tools looks exactly like a healthy one, and the difference is not something to go and read a log for.
