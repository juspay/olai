# olai-plugin-kolu — everything that says kolu, on this side of the wall

kolu was extracted into packages long before there was a plugin system, and ONE of them still stands: [`@olai/kolu-client`](../../kolu-client/README.md) is THE DIAL and the wire — the only package that opens padi's socket, where a change to padi's contract stops, and the only package here that names no olai package at all. That last clause is the wall, and it is the resolver's rather than a sweep's: the isolated linker gives a member exactly the `@olai/*` siblings its manifest declares, so an import upward out of the dial does not resolve. It does not move.

`@olai/kolu-ui` was the other, and it moved IN — the appliance fold (2026-08-31), which is why this package is now everything kolu-shaped except the dial. What was that package is [`src/appliance/`](src/appliance/): the Dock row a `terminal` property wears, the live pane it opens, the re-attach policy that pane runs, the fleet a tab holds once however many rows draw, the events the padi press fans, and the words the header readout says. The wall it had was not protecting the appliance — nothing in there is kolu's implementation, it is olai's DRAWING of kolu, on olai's own graph, using olai's own wire — and a second manifest to say so was a second identity for one appliance. THE RULE, MECHANICALLY: `src/appliance/` is every face that stands on KOLU'S OWN PRODUCT TIER — its components (`@kolu/solid-dockrow`, `@kolu/solid-statepip`), its vocabulary (`@kolu/terminal-vocab`, `terminal-themes`), the emulator (`@xterm/*`), and the wire shapes in `@olai/kolu-client/wire`. `src/browser/` is every face that reaches NONE of it: the pill, the drawer box, the mark, the tab's mount, and the app-furniture contract, all of them over values olai hands across. That is a reading of the two directories rather than a taste — but state it precisely, because a first draft of this sentence claimed `src/browser/` "imports no package outside this one" and that is false: every module in it imports `solid-js`, and one test reaches `node:fs`. What is true, and is the line, is that `src/browser/` names no `@kolu/*`, no `@xterm/*` and no `terminal-themes` — nothing of the APPLIANCE's tier — while `src/appliance/` names eight such specifiers plus `@olai/kolu-client/wire`. [`src/faces.test.ts`](src/faces.test.ts) HOLDS that, both ways, in this package rather than in the registry's fence — a per-directory rule up there would be the fence inventing a layout convention and enforcing its own invention, and a line stated as a reading and held nowhere is one the first mis-filed face passes green on. The same file keeps the wall the fold dropped: `@olai/kolu-ui`'s manifest did not declare `@olai/format` and this one does, so `src/appliance/` is held to naming none of it — weaker in kind than a resolution failure, and said so, but not absent. It is also why odu has no such directory and needs none: nothing odu draws reaches an odu component tier, so there is no second half for the wall to hold.
 The rest of `src/` is the JUDGEMENT.

That judgement is the thing that had no package of its own and was therefore living in packages that have no business knowing the word: `packages/chat/src/kolu.ts` (now [`src/probe.ts`](src/probe.ts)), `packages/server/src/koluConfig.ts`, `packages/server/src/claimants.ts`, `packages/web/src/client/padi/`.

It is not kolu implementation. It is **olai's own JUDGEMENT about kolu** — what an absent padi means in whole English sentences, which vault file is kolu's by convention, who owns a terminal, which property kind wears the terminal door, which chrome slot the padi pill hangs in. [`@olai/plugin-api`](../../plugin-api/README.md) argues why that judgement is neither the appliance's nor core's; this package is where kolu's share of it lands, and the reason nothing here re-implements anything is that the dial already did.

## What is in `src/appliance/`

The browser's kolu half, unchanged by the move but for its address:

- **[`src/appliance/props/KoluUi.tsx`](src/appliance/props/KoluUi.tsx)** — the socket: `KoluClient`, the structural pin, and the members of the composition (three cells — the link, the pill's liveness and the drawer's foot — the two collections — fleet and the watcher's events — the screen read, the live pane). The app hands over its composed client and a clock; which surface members exist, what they are called and how a pane's subscription is bound stay inside.
- **`src/appliance/props/fleet.tsx` / `src/appliance/props/held.ts`** — the fleet the tab holds once: one subscription per tab however many chips are down the page, one map, one counter; and the accumulator the events ring reuses (a frame the events ring sees is the same move as one the fleet sees, since the server's ring is one Store).
- **`src/appliance/props/EventsFeed.tsx` / `src/appliance/padi/events.ts`** — the drawer the Padi pill opens: what recently wanted attention, the folds over kolu's own, the words spelled **once, in `padi/events.ts`, and nowhere else** — past tense means the past, even for a still-held state. ATTENTION only: heartbeats never reach this drawer, since liveness lives on the pill.
- **`src/appliance/props/TerminalDoor.tsx` / `src/appliance/props/LivePane.tsx`** — the block and the window, wearing the app's own chrome.
- **`src/appliance/padi/said.ts`** — every word a status reads has one home; the header and the chat's probe speak this three-state sentence. THE ONE VOCAB — what an event IS — is `@olai/kolu-client`'s `KoluEvent`.
- **`src/appliance/testids.ts`** — this half's `data-testid`s, spread into [`src/testids.ts`](src/testids.ts) so the package has one door for them.

## The seven, as a surface of their own

[`src/wire.ts`](src/wire.ts) declares a **whole surface** — `defineSurface`, exactly as `@olai/surface` calls it — out of the declarations, schemas, `equals` and doc blocks that stay in `@olai/kolu-client/wire`. Core composes it as a **sibling** under this plugin's `name`, so the framework mints every address and olai computes none of them:

| declared here | on the wire, composed |
| --- | --- |
| cell `link` | `surface/kolu/link/get` |
| cells `pulse`, `knobs` | `surface/kolu/pulse/get`, `surface/kolu/knobs/get` |
| collections `fleet`, `events` | `surface/kolu/fleet/…` |
| stream `terminal` | `surface/kolu/terminal/…` |
| procedure `screen.text` | `surface/kolu/screen/text` |

The one rename in the set is the cell that was called `kolu`, which became **`link`** — and it went into `@olai/kolu-client`, where the member is declared, rather than being papered over here: a cell named for its own appliance composes to `surface/kolu/kolu/get`, which says the word twice and the thing once. What it holds is a `KoluLink`.

The doc blocks did not travel. They argue what a member IS — what a `fleet` row carries, what the pulse is off — and they stayed beside each schema in `@olai/kolu-client/wire`, where a reader asking that question is already standing. What lives here is which members this plugin puts on the wire and which face may see each.

[`src/wire.ts`](src/wire.ts) also carries this plugin's own **`ExposeMap`**, which used to be a row per member in `@olai/server`'s expose map — a general package holding a per-appliance decision, edited every time an appliance grew a member and silently forgettable: a member absent from that map is a member no face serves, and it reaches a person as a chip that never fills with nothing red anywhere. All seven are the **browser's alone**, and the reason is one sentence said seven times: every member here is a reading of somebody else's daemon, and an agent that wants padi has padi's own MCP face.

## Three doors, and the graph behind each

`package.json` exports six entries; three of them are disjoint by **graph** rather than by taste. The split is [`@olai/kolu-client`](../../kolu-client/README.md)'s own, one floor down, grown a door.

- **`./wire`** is this plugin's wire IDENTITY — the sibling key, the surface, and which of its members each face may see — and it is what everything that composes or reads that surface reaches. It used to be reached *through* `@olai/bundle/wire`, a browser-safe door that statically imported every plugin's wire half so the tab could compose a client out of them. **There is no such door.** The bundle's root is one ROW per plugin with a dynamic `import()` behind it, so nothing outside this package imports this file at all: what reaches it is this package's own two runtime doors — `./server`, which hands `surface` and `faces` to `ctx.surfaces.register`, and `./browser`, which re-exports `name` and `surface` because the tab has to DIAL the sibling in the same chunk it mounts. The graph is what it always was and for the reasons it always was: `effect` and `@olai/kolu-client/wire`, and it stops there. No `solid-js`, which would put a UI runtime on the server's graph — a server still reads this file, and the fence's walk over each row's server module refuses a `.tsx` on it. No `@kolu/padi-client`, which would put the daemon's whole contract on the browser's — the fence's walk over each tenant's `./browser` chunk refuses exactly that. Only the third of the old list is no longer a claim anybody holds about this door: `@olai/format` was forbidden here because the SERVER reached the wire door and a floor package has no business teaching a daemon a vocabulary, and the browser is the end that spends it.
- **`./server`** is everything that runs in a SERVER process, which is two things on one door. The RUNTIME HALF: [`src/server.ts`](src/server.ts) is a CORDIS PLUGIN — `name`, `inject`, `apply(ctx)` — which calls `koluHalf` itself, holds the three vault walks, and registers its sibling, its kind and its wake, each registration carrying its own undo. And the PROBE beside it: [`src/probe.ts`](src/probe.ts), pushed onto the `chat/session-start` waterfall and asked per chat session rather than per process. The door is disjoint from the root in **both** directions — a server must not pull a plugin's browser faces onto the graph of a process that renders nothing, and a browser must not pull `node:child_process` and kolu's whole detect surface into a tab.
- **`./browser`** is what REPLACED the manifest. [`src/browser.tsx`](src/browser.tsx) is a CORDIS PLUGIN too — `name`, `inject`, `apply(ctx)`, exactly its server half — registering the terminal block, the padi pill, kolu's mark and the tab's one mount into the app's declared slots, each registration carrying its own undo. It reaches `src/appliance/` and `src/browser/` and is therefore SolidJS and an emulator: the heaviest graph in the tree, and a split CHUNK now, named by a literal `import()` in a generated row and fetched only when a serve says kolu is running. **The root** is the wire identity re-exported and nothing more, now that there is no manifest for it to be.

One door for all three would carry a component onto the server's static graph and padi's contract into the browser bundle. [`@olai/bundle`](../../bundle/README.md)'s [`fence.test.ts`](../../bundle/src/fence.test.ts) walks each closure rather than trusting this list.

## The three vault walks, and where the wall actually runs

[`src/claimants.ts`](src/claimants.ts) reads which nodes carry a key DECLARED this plugin's kind — the word in [`src/kinds.ts`](src/kinds.ts), never a key's spelling. A declaration is two layers folded once (`@olai/format`'s `withClaims`): the vault's own row, which always wins, and the key the kind CLAIMS by convention, which is its own composed word. So `kolu-terminal` wears the door with nothing declared anywhere, a column called `pty` wears it the day one row says so, and a column somebody else calls `terminal` is never captured by switching kolu on; [`src/config.ts`](src/config.ts) reads what `_olai/Kolu.olai` says about the watcher's knobs, and [`src/doorbell.ts`](src/doorbell.ts) is the third of the kind: which terminals one scoped FILTER FILE claims — the same declared kind, over the nodes of that file that have not SETTLED — an unmarked row judged by what is under it — with mirrors followed to their targets — and what a fleet event about one of them MEANS to a conversation filtered by it. The first two were `packages/server/src/`'s, under kolu-shaped filenames; the third is new with the doorbell. All three walk **outline records** — which is exactly why they may not live in `@olai/kolu-client`: that package's interfaces are parametric in the node type so a compiler can hold it to never reading one, and what crosses into it is four strings per claim, one reading per revision, and — for the doorbell — one frozen `KoluEvent` in the other direction.

So the wall runs between three things and not two. The appliance knows how to reach the tool; core holds the vault; and the judgement about what the vault SAYS about the tool is this package's. `config.ts` is not called `koluConfig.ts` any more for the reason the `link` cell is not called `kolu`: inside `olai-plugin-kolu` the prefix says the word twice and the thing once.

## The doorbell, and the one generic capability behind it

Core grew ONE thing for this: `ctx.deliveries` — `scopes()`, which conversations opted into this plugin's wakes and which file each picked, and `deliver(to, body, options?)`, write-only, both keyed by the CALLING FIBER rather than by anything this package passes in. It speaks conversations and files and will never speak a terminal. Everything kolu-shaped about the second doorbell is on this side: [`src/doorbell.ts`](src/doorbell.ts) joins a watcher event to the unsettled nodes of a scoped file and answers `"wake" | "digest" | null`; [`src/wake.ts`](src/wake.ts) declares the three strings the strip's control is drawn out of, the KIND of file it may be pointed at (one: the outline, because a claim lives on a node and nothing else here has one — annotated `NodeKind` and not `FileKind`, so `"document"` is as unspellable there as `"hologram"`, and `src/wake.test.ts` fails the build if it stops being) and the two sentences a conversation is told when its doorbell stops watching — one for a file that went, one for a file that is there and holds nothing kolu can read — re-exported from [`src/server.ts`](src/server.ts) beside `kinds` and `probe`; and the WORDS of every delivered message are composed here, whole, because core may not author a clause of a sentence a plugin sends.

The tap into the watcher is one optional callback on `KoluDeps` — `rang`, in the shape `claimants` and `config` already take — and what crosses is the wire's own frozen `KoluEvent`. So `@olai/kolu-client` still cannot spell an outline record, in either direction.

Silence is the absence of a call. There is no third arm and no unclaimed-terminal warning anywhere: a doorbell that also reported what it decided not to ring about is one nobody would leave on. And **the mute list went with this PR** — the filter file a conversation is scoped to is the silence control now, so `_olai/Kolu.olai` keeps its duration knobs and nothing else, and the `mutes` cell was renamed `knobs` rather than removed because the drawer's wrench has no other source for the config's path.

...BUT IT IS NO LONGER SILENT TO THE OWNER, which is what `doorbell-missing-claim` (P1, 2026-09-01) bought. [`src/trace.ts`](src/trace.ts) is one formatter and one line per moment (`kolu doorbell <moment> key=value …`), written on `ctx.log.say` — which is `Effect.logDebug`, so it is off until `OLAI_LOG_LEVEL=debug`. It is part of the feature rather than instrumentation over it, on the same argument every seam here makes about second spellings: a doorbell whose failure mode is *a call that does not happen* is byte-for-byte identical to a healthy quiet one, so nothing but an account of what it decided can tell them apart. That P1 was diagnosed by counting messages **by hand** out of a chat transcript, because the transcript was the only record there was; the `derived` line — which NAMES the ringing set rather than counting it, since the readable fact is usually an absence and an absence needs a list to be read against — would have ended it in a glance. [`docs.md`](docs.md#what-the-doorbell-says-it-did) is the owner's page for it, including the `why=` vocabulary a silent classification carries — `settled`, `not-live`, `unmarked-leaf`, `unmatched`, `unclaimed` — which is the half that turns "absent from the set" into "absent, and here is the gate".

## Both halves are Cordis plugins, and that is the direction

[`src/server.ts`](src/server.ts) and [`src/browser.tsx`](src/browser.tsx) are the same shape one process apart — `name`, `inject`, `apply(ctx)` — and both import `@olai/plugin-api`, the INTERFACE, which names no plugin: the server half for the services its `inject` declares, the browser half for the type-only augmentation that puts `ctx.slots` and the three services beside it on the context. What must never be imported is `@olai/bundle`, the REGISTRY, which imports this package: an import back would be a cycle the manifests could not express.

It was `src/plugin.ts`, a plain `as const` object with **no `: OlaiPlugin` annotation on it**, and the fit was proved at the registry's `satisfies` — the same structural agreement `@olai/ops` keeps with the surface's `Status`, and the one [`src/appliance/props/block.ts`](src/appliance/props/block.ts) still keeps with the drawer's entry. The object went with the compiled-in registry that walked it, and the reason is the tab following the ROSTER: a manifest is present whether or not a serve composed the plugin, so every walk over it had to carry a licence beside it, while a fiber the roster never names registers nothing at all. What the `satisfies` used to catch is caught inside this package now — a face hung in a slot the app does not declare is a type error on its own `ctx.slots.register` line, and the reading of the app this half composes out of `ctx.bar`, `ctx.clocks` and `ctx.links` ([`src/browser/app.ts`](src/browser/app.ts)) fails on the line that composes it, with this plugin's name on the file.

The same physics runs the other way too. `src/appliance/` used to read its wire types from `@olai/surface` back when it was a package; it reads them from `@olai/kolu-client/wire`, which is where they live — because the surface sits ABOVE this package and a dependency back would be a cycle `bun install` cannot describe.

`name` is spelled once, in [`src/wire.ts`](src/wire.ts), and it is the **sibling key** — so the wire prefix, the preferences row, the docs slug and the word `--plugins` takes cannot drift apart.

## kolu off is a state kolu has always had

Nothing about what these members answer when there is no padi changed: an `absent` link, an empty fleet, a quiet pulse, no events, no terminal, a screen read that refuses in words. That is what a machine without kolu shows, and [`@olai/kolu-client`](../../kolu-client/README.md) settled it under its own heading.

What DID change is what "this process runs no kolu" means. `@olai/server` used to pass `wiring.kolu: null` and serve every member present-and-hollow; a plugin that is not composed now contributes **no sibling at all** — no tag, no handler, no expose row, no `surface/kolu/` on the wire. Absence is the sharper of the two answers, because a member that is not there cannot be read as a member that is there and empty, and the framework's own composition expresses it for free.

## The browser half

`src/browser/` is this package's third face, and it is the one that stopped `@olai/web` spelling `kolu`:

- **The padi pill** (`Padi.tsx`) and the feed its press opens (`Feed.tsx`) — the header readout that says whether this olai can see kolu's terminals, the third standing promise beside the connection and the Commit pill. It hangs in the `app.header` slot, and the app draws every plugin's header face where the padi pill used to be spelled out — WHERE in the cluster it sits is the app's decision and always was; what a plugin gets is a seat.
- **The tab's mount** — `../appliance/`'s `KoluUi` bound to THIS plugin's sibling client, hung in `app.mount` by [`src/browser.tsx`](src/browser.tsx) and wrapped ONCE around the page however many rows draw. That line lived in the app's composition root as `<KoluUi client={olai}>`, and the day kolu's members composed as a sibling it would have had to read `olai.clients.kolu`, which is a general package writing a plugin's name in its own `App`. It reads the client off `ctx.wired`, keyed by the fiber, so it cannot be asked for under another plugin's name.
- **Kolu's MARK** (`Mark.tsx`) — the face over a sentence the doorbell delivered into somebody's conversation. The chat panel names the speaker of every run of messages (you, the agent, or a plugin) and looks a plugin's face up by the name core stamped on the row, so this shape is contributed here and core keeps no table of them. It is **kolu's own logo** — `packages/client/favicon.svg` in juspay/kolu, the three rainbow steps — and it gets here **through the pin**, via [`@olai/plugin-kit`](../../plugin-kit/README.md): `default.nix` beside this README names that file on the npins kolu source (the same revision every `@kolu/*` module hydrates from), the kit turns it into a TypeScript module, and `just install` copies the result into `src/browser/mark.generated.ts`, which is gitignored. Bumping the pin is the whole of updating the logo; there is no copy of the asset in this repository and no fetch from a running page. The nested viewport, the id rewrite and the backtick spelling a claiming node is named with (`nodeRef`) are the kit's, shared with every other tenant that fills `mark`. It used to be a hand-drawn glyph — two panes and a prompt chevron, invented here — and that was the defect rather than the drawing: it was not kolu's mark, so a reader who learned it learned something true of nothing outside this tab. The cost of the real one is stated where it is paid: the gradients are the logo, so the mark carries kolu's palette rather than `currentColor`.
- **The terminal DRESSING**, hung in `outline.row.block` against `TERMINAL_KIND` — the declared KIND, never the property key — and passed BARE, so `ctx.slots` composes it with the fiber's name exactly as `ctx.kinds` composes it on the server and the word a face is looked up by cannot become a second spelling of the word a vault declares. A BLOCK rather than a chip, because a terminal owns its row whether or not anything is happening in it. The component is `src/appliance/`'s `TerminalBlock`, because it renders kolu's row and mounts kolu's emulator; what is decided here is the one thing that is olai's, which is that this KIND wears that face — the browser follows the same declared word the server walks, through the page's licence table, so a vault that put the kind on a column called `pty` draws the door too.

**None of it imports `@olai/web`**, and that is a wall rather than an omission — the app mounts every plugin, so an import back would be a cycle, and `@olai/bundle`'s `fence.test.ts` refuses it before a reviewer has to notice. What the pill needs of the app — the bar's pill geometry, the desktop breakpoint, the popover that shares the bar's one focus cycle, a door onto a served file — arrives as SERVICES this half NAMES in its `inject` (`bar`, `clocks`, `links`, beside the `slots` its faces hang in and the `wired` that is its own client), composed once in [`src/browser.tsx`](src/browser.tsx) into the value the faces take as a prop and declared structurally in [`src/browser/app.ts`](src/browser/app.ts). It was one blob the app handed every face, and what retired it is that a fiber has an `inject`: a half now says what it wants and Cordis holds it PENDING until every one of them exists. That is [`src/appliance/props/block.ts`](src/appliance/props/block.ts)'s own pin, one directory over, and its argument scales exactly: a face that spelled the app's contract itself would be a second spelling, free to drift the day the app changed it, with the app's own suite green because the face it broke is in another package.

Two doors come with it and neither is a graph. `./testids` is names only, so a scenario asserts on the pill without pulling SolidJS and an emulator into a cucumber process with no browser in it; `./all.css` chains `src/appliance/props/all.css` and adds a `@source` at these faces, because Tailwind emits only what it can SEE and a component that moved out of the app's scan path renders with **no layout at all while nothing errors**.

## Is kolu running here — and the five sentences saying why not

[`src/probe.ts`](src/probe.ts) was `packages/chat/src/kolu.ts`: 341 lines of this appliance's name inside a package whose whole subject is one conversation with one ACP agent. What `@olai/chat` keeps is the SHAPE of the question — a list of things that answer *is your tool here, and what am I owed if it is not* — and everything below is the answer, which is olai's judgement about kolu and belongs on this side of the wall.

**The probe IS the detection.** A `kolu` on PATH is not necessarily the host's kolu: a padi-spawned terminal prepends its own bundled copy, and one of those was an older build reporting the same version string while missing most of the verbs ([juspay/kolu#2146](https://github.com/juspay/kolu/issues/2146), fixed by #2147 — but the wrong build still SPAWNS, so the lesson outlives the fix). So nothing here trusts a path, a version or an exit code: the executable is started, handshaken with, and asked to read a resource only a live daemon can answer. One answer is evidence of both halves — this binary speaks the protocol, AND a padi is behind it — and the absolute path that answered is what the session is given, so the agent cannot resolve the bare word against a different PATH and spawn something else.

**The plumbing is kolu's and the sentences are ours** (`@olai/kolu-client/detect`, over `@kolu/detect`, juspay/kolu#2168). Resolving `kolu` on PATH, starting it, handshaking and reading a cell only a live daemon can answer is knowledge *about kolu*, including the two incidents it encodes, which are facts about kolu's own builds and discoverable there rather than here. So this file writes no message and reads no pipe: it asks, and gets back which of the five ways it failed with the failing party's own words where there were any. A kolu that pre-worded those five would make five English strings a contract between two repositories, and one that only said "it did not work" would put the debug log line on screen — which is what the incident this feature comes from was debugged around.

**And that is why there is no failure TABLE anywhere in the plugin interface.** Three of the five sentences carry something that only exists at the moment of failing — a deadline, a cause, the daemon's own refusal — so a `Record<tag, string>` core could look a tag up in would hold at most two of them and leave core composing the rest. The sentence rides on the probe's own answer instead, whole.

**`PADI_SOCKET` set with nothing on PATH is the one miss with no file to name.** Absence is quiet because olai auto-detects and nothing declares that a host should have kolu — but that variable is a declaration, set by a kolu terminal for what it starts and by a person who meant it. And the PATH it is measured against is OLAI's: run as a systemd user service (`nix/home/module.nix` passes neither), this process need not see a `kolu` its user runs every day, which is the original incident approached from the environment instead of from the binary. Narrow on purpose — without the variable this stays quiet, so a machine that never heard of kolu never hears about it. It is also the one arm kolu declines to decide: `@kolu/detect` reports that nothing was found and says nothing about whether that is a fault, because our PATH is not its business.

**What is detected is the DAEMON, not kolu's web server**, which may be running on another machine reaching this host as a remote. `PADI_SOCKET` is forwarded when olai was launched inside a kolu terminal, and kolu resolves its own default when it was not — socket discovery is not reimplemented here, and a host running two padis says so and is left alone rather than guessed about.

**The environment is a PARAMETER**, handed in by the composition root, and that is not only the usual seam rule: the probe has to read what a session's own spawn will resolve against, so a probe that reached for `process.env` itself would be answering a different question. [`src/probe.test.ts`](src/probe.test.ts) is the visible dividend — it used to replace this process's `PATH` and delete its `PADI_SOCKET` in a `beforeEach`, because the machine it was written on IS running kolu and the ambient variable silently turned the quiet case into the loud one.

## The browser's half of the kind, and how it landed

This section used to say the browser's half was **not here yet** — that the KIND
had landed on the server and the dressing was still looked up by the property
KEY, so a vault whose `terminal` kind sat on a column called something else was
walked, probed, and drew nothing. That was true for one PR window and it is not
true now: the page carries the licence as an ANSWER per drawn value
(`@olai/format`'s `Licence`), the browser looks the contributed WORD up in the
table each plugin registered, and `@olai/plugin-api`'s README states the close —
*"keying the tab's table on the property key was the last surviving half of the
name-matching defect, and it is gone."* A vault's declarations still never
travel to a tab; what travels is one answer about one drawn value.

The other tenant is `olai-plugin-odu`, which composes [`@olai/odu-client`](../../odu-client/README.md)'s one `ci` cell at `surface/odu/ci/get`. A plugin is not a size.
