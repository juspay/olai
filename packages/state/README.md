# @olai/state — where this machine keeps olai's own files

Not in the vault. A vault is somebody's git repository or notes app: the store probes every file in it, the sidebar lists it, and a commit sweeps it — so a lockfile or a panel's last conversation would each be a file olai left behind, offered up for committing, and carried to every clone by `git pull`. A personal clone of a team's outlines must not inherit the team's last chat. A vault on a read-only mount still serves. After git left this package there are **three** kinds plus a per-plugin hold, and the split between them is what each SURVIVES rather than what each is about: `chat` is the panel's last conversation, one record rewritten whenever the panel opens one; `wake` is which conversations a person pointed a plugin's doorbell at, and on which file; `heard` is what olai OVERHEARD a conversation do — that this session was told its node agent's contract, and the last line its agent said while olai was watching; a plugin's hold is a small record that plugin keeps about this serve — one file per plugin per vault (`fileForHold`), reached through core as `ctx.held` so this leaf stays out of every tenant. `heard` is here because it is BOOKKEEPING rather than configuration, which is the line the human's 2026-09-02 ruling drew: all configuration lives in `.olai` files or their properties, and which node agent a session belongs to is accordingly a property on the node — but nothing configures these two, nothing else can reconstruct them, and a board written to on every turn would be a board committed on every turn. The `wake` record holds the PICKS and never the messages — a held message is a derivation of state that is still true, and whatever derived it rings again.

**Two homes, because they answer two different questions.** `runtimeHome()` is `$XDG_RUNTIME_DIR/olai` (or the fixed per-user `/tmp/olai-$UID`) and is for a claim that must not outlive the process that made it — the one-brain lock. The machine clears it at logout; a graceful stop unlinks its own file, and the next boot sweeps leftovers, because a server that stays logged in never gets that logout. `stateHome()` is `$XDG_STATE_HOME/olai` and is for something that should survive a restart and means nothing to anybody else. Both are read at call time, never at import, so a test — or the e2e harness, per worker — can point a process somewhere of its own. The state home's leftover is not a process that died but a directory that did — a chat memory or a doorbell pick outlives a scratch vault in `/tmp` forever, and nothing is ever going to read those records back — so every boot that holds a vault sweeps it once with `pruneGone()`: a record whose `cwd` answers ENOENT, and only that, is unlinked, logged as `pruned state records for directories that are gone`; a stalled mount, a moved permission, a record this build never wrote, all stay.

**One file per served directory**, `fileFor(kind, root)`, named by `digestOf(root)`: sixteen hex characters of a SHA-256 over the path's **realpath**. A plugin's hold is the same digest plus the plugin's name (`fileForHold(plugin, root)`), and a name that is not a filename is refused. Not the path itself — an encoded path is a filename that can outgrow the 255 bytes a component gets — and not a single shared index, which is a read-modify-write two olai servers can lose an update through. The realpath is the load-bearing half: a person types `olai web ~/notes` in one terminal and `olai web .` from inside a symlink to it in another, and two brains over one vault is what the difference would buy.

`readHeld(at, cwd)` / `writeHeld(at, held)` are the pair over one small JSON record. The write is staged beside its destination and renamed onto it (a half-written record read by the next boot is a parse failure reported to somebody who did nothing wrong), the home is minted `0700` and the file `0600`. The record carries its own `cwd`, which is what makes a state directory readable by the person whose state it is and is read back as a **guard**: a file about some other directory is answered `null` rather than refused — it is a digest collision, not damage. A missing file is `null` too; that is the answer on a directory's first serve. Everything else — permissions that moved, a disk that will not answer, bytes that are not JSON — is a `StateFailure` on the error channel, and no caller treats one as fatal.

**The staged name is unique per CALL**, `<file>.<pid>.<n>.tmp`, and that is a defect closed rather than a detail. One process can have two writes in the air at once — two tabs, a double-click on a picker, a boot fiber and a protocol callback — and two calls sharing one staged name do not lose a byte, they *lie*: A stages, B overwrites the stage, A renames it onto the destination, and B's rename then fails `ENOENT`, so B reports a failure to the person who just made the gesture for bytes that are on the disk. It used to be one name per destination per process, and the hazard was patched **twice above** — a semaphore in `@olai/chat`'s `agent.ts`, then a second one in its `scopes.ts` — before it was closed here. A leaf that is only correct while every tenant remembers to queue is a leaf that is wrong on the next tenant. The permits above stay, for the jobs that are their own: `scopes.ts` read-modify-writes an in-memory mirror and would lose a pick without one, and `agent.ts` orders two writes that have to land in the order they were made.

What a record's own FIELDS mean is the caller's. `readHeld` hands the object back once it has checked the one thing it owns, because what a missing or strange field costs differs per record: `@olai/chat`'s memory can do without a model and not without a session.

## Why it is a package

It was written more than once before it was one, which is the bar: `@olai/server`'s `lock.ts` (the runtime home and the digest) and `@olai/chat`'s `memory.ts` (the state home, the digest, the atomic write and the `cwd` guard). A git policy used to live here too and no longer does; chat brought two more records with it (`scopes.ts`, the `wake` kind; `sessions.ts`, the `heard` kind) rather than two more packages. `memory.ts` named this module before it existed — *"not a receptacle for where this machine keeps olai's state, though that is what it would be at population two"*.

A **leaf**, beside `format`, `git`, `log` and `identity`: `effect` and node built-ins, no `@olai/*` import. That is what lets `@olai/chat` and `@olai/server` share it — they sit beside each other, so a home they could both reach had to be below both. It knows about a filesystem and nothing about outlines, git, a wire or a writer; even its "what went wrong, in words" is four characters of its own rather than `@olai/log`'s, because a workspace sibling here would be exactly the knowledge coming back.
