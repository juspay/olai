# @olai/state — where this machine keeps olai's own files

Not in the vault. A vault is somebody's git repository or notes app: the store probes every file in it, the sidebar lists it, and a commit sweeps it — so a lockfile, a remembered git policy or a panel's last conversation would each be a file olai left behind, offered up for committing, and carried to every clone by `git pull`. That last one is the ruling this repository keeps being handed (#335, and again for `git-policy-server-side`): a personal clone of a team's outlines must not inherit the team's auto-push. A vault on a read-only mount still serves.

**Two homes, because they answer two different questions.** `runtimeHome()` is `$XDG_RUNTIME_DIR/olai` (or the fixed per-user `/tmp/olai-$UID`) and is for a claim that must not outlive the process that made it — the one-brain lock. The machine clears it at logout; a graceful stop unlinks its own file, and the next boot sweeps leftovers, because a server that stays logged in never gets that logout. `stateHome()` is `$XDG_STATE_HOME/olai` and is for something that should survive a restart and means nothing to anybody else. Both are read at call time, never at import, so a test — or the e2e harness, per worker — can point a process somewhere of its own.

**One file per served directory**, `fileFor(kind, root)`, named by `digestOf(root)`: sixteen hex characters of a SHA-256 over the path's **realpath**. Not the path itself — an encoded path is a filename that can outgrow the 255 bytes a component gets — and not a single shared index, which is a read-modify-write two olai servers can lose an update through. The realpath is the load-bearing half: a person types `olai web ~/notes` in one terminal and `olai web .` from inside a symlink to it in another, and two brains over one vault is what the difference would buy.

`readHeld(at, cwd)` / `writeHeld(at, held)` are the pair over one small JSON record. The write is staged beside its destination and renamed onto it (a half-written record read by the next boot is a parse failure reported to somebody who did nothing wrong), the home is minted `0700` and the file `0600`. The record carries its own `cwd`, which is what makes a state directory readable by the person whose state it is and is read back as a **guard**: a file about some other directory is answered `null` rather than refused — it is a digest collision, not damage. A missing file is `null` too; that is the answer on a directory's first serve. Everything else — permissions that moved, a disk that will not answer, bytes that are not JSON — is a `StateFailure` on the error channel, and no caller treats one as fatal.

What a record's own FIELDS mean is the caller's. `readHeld` hands the object back once it has checked the one thing it owns, because what a missing or strange field costs differs per record: `@olai/chat`'s memory can do without a model and not without a session, `@olai/server`'s git policy can do without either half.

## Why it is a package

It was written three times before it was one, which is the bar: `@olai/server`'s `lock.ts` (the runtime home and the digest), `@olai/chat`'s `memory.ts` (the state home, the digest, the atomic write and the `cwd` guard), and `@olai/server`'s `gitPolicy.ts` (all of it again). `memory.ts` named this module before it existed — *"not a receptacle for where this machine keeps olai's state, though that is what it would be at population two"* — and the third caller is what moved it.

A **leaf**, beside `format`, `git`, `log` and `identity`: `effect` and node built-ins, no `@olai/*` import. That is what lets `@olai/chat` and `@olai/server` share it — they sit beside each other, so a home they could both reach had to be below both. It knows about a filesystem and nothing about outlines, git, a wire or a writer; even its "what went wrong, in words" is four characters of its own rather than `@olai/log`'s, because a workspace sibling here would be exactly the knowledge coming back.
